# 概算要求 明細表（備考を除く）raw text → CSV（v0）

令和6年度歳出概算要求額明細表の、**備考を除く左側**（要求番号・事項・前年度予算額・６年度概算要求額・対前年度比較増△減）を、PDF から生成済みの plain text（pdftotext 出力、Form Feed でページ区切り）から deterministic に CSV 化する。LLM・OCR・他資料による補完は行わない。備考（予算額の推移、要求要旨、積算の内訳）は対象外。

- 実装: `scripts/pipeline-v2/lib/budget-request-detail-table.ts`（pure）、`scripts/pipeline-v2/build-budget-request-detail-table-csv.ts`（runner）
- テスト: `scripts/pipeline-v2/lib/budget-request-detail-table.test.ts`、fixture は `tests/fixtures/budget-request-detail-table/2024/`（実ページの全文。出典は `excerpts.json`）
- 総表は別の仕様: [budget-request-total-table-csv.md](budget-request-total-table-csv.md)

```bash
npx tsx scripts/pipeline-v2/build-budget-request-detail-table-csv.ts [inputDir] [outputDir] [--year=2024]
# 既定: data/work/budget-request-plain-text/{year}/（build-budget-request-plain-text.ts --year={year} の出力）→ data/work/budget-request-csv/{year}/detail-table/
```

`--year` が選ぶのは、入力ディレクトリの選択（既定 `data/work/budget-request-plain-text/{year}/`。出力の `source_file` は `budget-request-plain-text/{year}/{file}.txt` の形）、整合性の診断に使う manifest（FY2024 は `tests/fixtures/budget-request-raw-text/2024/raw-text-manifest.json`、ほかの年度は `tests/fixtures/budget-request-plain-text/{year}/plain-text-manifest.json`）、既定の出力先、`summary.json` の scope だけ。parser は年度によらず同じで、表頭の語彙は「６年度」のまま（他の年度では、年度を含む表頭の行は `UNKNOWN_HEADER_ZONE_LINE` として unresolved に入る）。plain text は `build-budget-request-plain-text.ts --year={year}` で作る。

## 原則

- raw text に存在する値だけを抽出する。空欄を `0` にしない、`△` を補完しない、他の行・他のページから値を補わない。
- **名称と金額の文字は、空白を除いて出力する**（名称の文字間の空白は均等割付で、`△` と数字の間の空白と合わせて、情報を持たない。総表の CSV と同じ扱い）。カンマと `△` はそのまま。**コードは、raw text のままにする**（コードの中の空白も含む。下記）。数値化・字下げの正規化はしない。空欄は空欄のまま出力する。
- 判断できない行は main CSV に入れず、`unresolved.csv` に生の行と理由を残す。
- コードの形（`row_type`）は物理文法であり、組織・項・事項・目などの意味付けはしない。同じ3桁コードが異なる階層に現れる。
- 親子関係の復元はしない（行の順序と、`row_type`、出所の行番号から後段で行う）。

## 文法

### ページ

- **明細表のページ**: 空白を除去したページ本文に `事項` `前年度` `比較増` `備考` `予算額` `概算要求額` がすべて含まれ、かつ総表のページ（`一般行政経費` `その他の経費` `明細書` がすべて含まれる）でないもの。明細表の表頭は、備考側を含め、各ページに繰り返し出る（FY2024 は8,585ページのうち8,574ページで境が決まる）。
- **text layer の無い source**: 全ページが空の source（FY2024 は法務省 737ページ、金融庁 77ページ）は、明細表のページが検出されず、出力しない（`summary.json` の `sourcesWithNoTextLayer` に記録する）。

### 左側と備考側の境

- 表頭の1行目（`事項` `前年度` `備考` を含む行）にある、見出し `前年度` の開始桁（`前` の位置）を、そのページの境（`q`）とする。2行目（`番号 … 予算額 … 比較…` の行）までをヘッダ領域とする。
- 本文の行は、行頭の位置（先頭の空白の数）が `q` 以上なら備考側とし、読まない（`RIGHT_REGION`）。`q` より左で始まる行だけを左側として読む。
- **同じ物理行の右側にある備考も、金額として読まない。** 見出し `備考` の開始桁（`b`）では分けられない（FY2024 は、行の備考の文字の99.9%が、`b` より左で始まる。中央値で25桁左、比較増△減の列の右端の1文字後）。そこで、数字は、**金額の列の窓に右端が入るときだけ**金額とし、列の順に割り当てる。
  - **窓（表頭だけから決める）:** 表頭の2行目の見出しの語（`予算額`、`概算要求額`、`比較増△減`）の右端から、各列の金額の右端がどこにあるかは、FY2024 の4,376ページの実測で、前年度は−2〜+3、要求額は0〜+14、比較は+2〜+14 だった。余裕を2文字足して、窓とする（前年度 −4〜+5、要求額 −2〜+16、比較 0〜+16）。本文の行は読まないので、備考の数字は窓に影響しない。窓は「備考」の見出しの桁を超えない。
  - **割り当て:** 行の数字を左から順に、まだ使っていない列のうち、窓に入る最初の列に割り当てる。窓に入らない数字と、それ以降は、備考とみなす。備考の数字の並び（例: `100 150 50`）は、最初の数字が前年度の窓に入らないので、金額の列に割り当てられず、金額3つの行にならない（途中の列から始まる並びも、列の数が足りない）。
  - **実測の右端（ページごと）:** 窓に入り、検算が通る、金額3つの行が3行以上あり、その右端が列ごとに5文字以内で揃うページは、右端の中央値を使い、窓を中央値±6文字に狭める（空欄セルの位置合わせは±3文字）。校正に使う行は、上の窓のテストを通ったものだけなので、備考の数字は校正に入らない。揃わない、または3行に満たないページは、表頭の窓のまま。
- 境が見つからないページ（FY2024 は11ページ）は、推測せず、全行を `unresolved.csv`（`PAGE_WITHOUT_HEADER_BOUNDARY`）に残す。

### ヘッダ領域の行

| クラス | 判定 | 出力 |
|---|---|---|
| `TABLE_HEADER` | 空白除去後が表頭の語（`要求` `番号` `事項` `前年度` `６年度` `予算額` `概算要求額` `対前年度` `比較増△減` `備考`、途切れた `比較増△` `比較` を含む）だけ | 出さない |
| `TABLE_TITLE` | `概算要求額明細表` を含む | 出さない |
| `UNIT` | `単位` を含む | 出さない |
| `CONTEXT` | 1〜4桁の数字で始まり、`所管` または `会計` を含む（例: `19 内閣府所管(官房総務課（総務課）)`、`9101 東日本大震災復興特別会計（警察庁）`） | **行として出す**（`row_type = CONTEXT`、`事項` に行の全文、金額は空欄） |
| `PAGE_LABEL` | ページの最初の非空行で、上のどれでもないもの（例: `内（本）`、`厚（本） 313`） | 出さない |
| 上以外 | | `unresolved.csv`（`UNKNOWN_HEADER_ZONE_LINE`） |

本文の末尾にある日時の行（`2023/09/12 20:27:48`）は `FOOTER_TIMESTAMP` として出さない。

### 行頭（左側の本文）

`[字下げ] [要求番号] コード 名称 [金額 金額 金額] [備考側の文字]`

| `row_type` | コードの形 |
|---|---|
| `DETAIL` | 要求番号（1〜3桁）に続く `NN‑NN`（例: `1  01‑95`） |
| `CODE_5_4_2_4` | `95016‑2111‑05‑0710`。**中央の4桁が欠けて空白が入る行がある**（例: `95016‑ 815‑16‑7878`、`95016‑   2‑08‑2010`。FY2024 は24,604行のうち3,839行、15.6%）。raw text の抽出で先頭の桁が落ちたと見られる。空白を詰めると、正しそうに見える別のコードになるので、**raw text のまま保持する**（補完しない） |
| `CODE_NN_NNNN` | 略記 `02‑0100` |
| `CODE_NN_NN` | 要求番号なしの `NN‑NN` |
| `CODE3` / `CODE2` / `CODE1` | 3桁 / 2桁 / 1桁 |

- 先頭の数字を要求番号とみなすのは、その後ろに `NN‑NN` の形のコードが続くときだけ。
- 金額は ASCII の数字だけ（全角数字は名称や備考の一部）。金額の列は、2つ以上の空白（または `△` の直前）の後ろから始まるものとする。`△` は金額から離れて付くことがある（例: `△    32,160`）。前の金額の直後に付くこともある（例: `0△    32,160`）。
- 金額が0個の行は見出し行（金額は空欄）。このとき、`事項` は境の左にある文字だけ（境より右は備考）。

### 金額のセルと空欄

- 金額が3つ: 前年度予算額・６年度概算要求額・対前年度比較増△減の順に入れる（空白を除く）。
- **金額が2つ（1つが空欄）**: 空欄のセルは空欄のまま、2つの金額を、**原文の位置だけで**列に置く（`AMOUNTS_PLACED_BY_PAGE_EDGES`）。そのページの、金額3つで `要求額−前年度＝増減` が成り立つ行（3行以上）の、3列の右端の位置（中央値）に、各金額の右端が±3文字で一意に合い、2つが別の列になる場合。それで決まらない行は、**表頭2行目の見出しの語から決めた窓だけ**で、各金額の右端が一意に1つの列の窓に入り、2つが別の列になる場合に置く（`AMOUNTS_PLACED_BY_HEADER_WINDOWS`。凍結した独立GT 139件で、3列とも一致 139/139）。窓が重なる行・位置が合わない行は、`unresolved.csv` に残す（`BLANK_CELL_COLUMN_UNDETERMINED`）。**検算は、どの列に値があるかを決めるために使わない**（推定になるため）。
- 金額が1つ、または4つ以上の行は `unresolved.csv`（`UNEXPECTED_AMOUNT_COUNT`）。
- 検算（`要求額−前年度＝増減`、`△` を負として計算）は、抽出したあとの確認としてだけ、金額が3つの行で行い、不一致を `arithmetic-diagnostics.csv` に残す。**値は書き換えない。列の所属を決める材料にもしない。**

### 名称の継続行

左側にあり、コードで始まらない行は、次をすべて満たすとき、直前の行の `事項` の名称に、区切りなしで連結する（空白は除く）。

- 境の左だけで読める（境をまたぐ行は連結しない）。
- 物理行が、行（または、その行の直前の継続行）の**すぐ下**にある。空行や備考側だけの行を挟まない。
- 行頭の位置が、直前の行の名称の開始位置と±1文字で揃う。

備考の表は、左側の領域から始まることがある（例: 事務事業別内訳表）。連結の条件を厳しくして、備考の内容を名称に取り込まない。条件に合わない行は `unresolved.csv` に残す（`LEFT_FRAGMENT_NOT_ADJACENT` / `LEFT_FRAGMENT_NOT_ALIGNED` / `LEFT_FRAGMENT_WITHOUT_PRECEDING_ROW_ON_PAGE`、境をまたぐ行は `LEFT_TEXT_CROSSES_BOUNDARY`）。

## 出力（`data/work/budget-request-csv/2024/detail-table/`）

| ファイル | 内容 |
|---|---|
| `sources/<slug>.csv` | 明細表を持つ source ごとの CSV（行順。全 source を1つにまとめた CSV は出力しない） |
| `unresolved.csv` | `source_file, source_page, source_line_start, source_line_end, raw_text, reason` |
| `arithmetic-diagnostics.csv` | 金額が3つの行の検算の不一致。抽出値は書き換えない |
| `summary.json` | 件数集計、source 別の内訳、行のクラス別の件数、凍結 manifest とのページハッシュ照合結果 |
| `output-manifest.json` | 上記ファイルの SHA-256（決定性の確認用） |

行のクラス（`ROW` `CONTINUATION` `RIGHT_REGION` `TABLE_HEADER` `PAGE_LABEL` `TABLE_TITLE` `UNIT` `FOOTER_TIMESTAMP` `UNRESOLVED`）の件数の合計が、明細表のページの非空の物理行の数と一致することを、runner が検査する（取りこぼしがない証跡）。

### main CSV の列

総表の方針と同じく、明細表の見出しを日本語のまま列名にし、行の出所をたどる列を末尾に置く。

| 列 | 内容 |
|---|---|
| `要求番号` | 原文。無い行は空 |
| `事項` | コードと名称を半角空白でつないだもの。コードは raw text のまま、名称は空白を除いたもの（継続行は連結済み。行は `source_line_start`〜`source_line_end`）。`CONTEXT` は、先頭の番号と、残りを空白を除いたもの |
| `前年度予算額` `６年度概算要求額` `対前年度比較増△減` | 金額のセル（空白を除く。カンマと `△` は残す）。空欄は空 |
| `頁` | 行があるページの、**印刷された頁**（ページの最初の非空行にあるラベル。ページ番号に、府省・会計の略号が付く）を、空白を除いたもの。例: `厚（本）13`、`14厚（本）`、`1058国（保）`、`97`。ラベルが無いページは空（FY2024 は、8,585ページのうち78ページ。表題や表頭の行から始まるページ）。総表の `明細書頁数` は、この頁の番号を指す |
| `source_page` `source_line_start` `source_line_end` `row_index` `row_type` `parse_status` | 行の出所（ページと、ファイルの物理行番号。1始まり）、source 内の連番、コードの形、金額の置き方（`PARSED` / `AMOUNTS_PLACED_BY_PAGE_EDGES` / `AMOUNTS_PLACED_BY_HEADER_WINDOWS`） |

- **`source_file` 列は持たない。** source は、ソース別 CSV のファイル名（`sources/<slug>.csv`。`<slug>` は plain text のファイル名から `.txt` を除いたもの）で判別する。複数の source をまとめる `unresolved.csv` と `arithmetic-diagnostics.csv` には `source_file` 列を残す。
- 字下げ（行頭の空白）は出力しない。元の plain text は、ソース別 CSV のファイル名と `source_line_start` から引ける。
- **単位は千円**（表題の `(単位:千円)` は、FY2024 のヘッダ領域の62件すべてが千円。備考の中には、百万円や円の表がある）。列にはしない。
- 備考は出力しない。

## FY2024 の実測（記述的な件数。精度の評価ではない）

- 82 source のうち、明細表のページを持つのは73 source・8,585ページ。残りの9 source は、明細表の表頭が無い7 source（表紙・目次・総表など）と、text layer の無い2 source（法務省、金融庁）。
- 行は47,693行（`CONTEXT` 62、見出し行 7,602、金額3つ 39,277、金額2つ 752＝実測の右端 612＋表頭の窓 140）。`row_type` は `CODE_5_4_2_4` 24,718、`CODE3` 10,899、`CODE_NN_NNNN` 8,424、`CODE2` 1,923、`DETAIL` 1,641、`CODE1` 26。
- **金額が3つの行は全行で検算が通る（不一致0）。**
- 金額が2つの行は、実測の右端で置けた612行と、表頭の窓だけで置けた140行（凍結GT 139件で3列とも一致、T013は post-hoc 確認で一致）を出した。置けなかった345行（窓が重なる。算術では置けるものもあるが、推定になるので使わない）は unresolved。
- 備考の数字を金額と読まないための窓と割り当てを入れたとき、既存の行のセルは1つも変わらず（差0）、行の後ろに備考の番号（`1 既定分` の `1` など）がある2行が、金額3つの行として読めた。
- 名称の継続行は21,881行を連結した（窓で置いた140行の継続行99を含む）。
- 未解決は2,217行: 境が無いページ 397、空欄の列が位置で決まらない 345、継続行の条件に合わない左側の行 1,474（隣接しない 708、境をまたぐ 314、揃わない 16、そのページに直前の行が無い 436）、金額の数が合わない 1。抜き取りで見た範囲では、左側の行は備考の表の一部が多い。
- main CSV の全行について、コードが出所の物理行にそのままの文字で含まれ、名称の文字が出所の行に（空白を除いて）順序どおり含まれ、各金額が最初の行に順序どおり含まれることを、実装とは別の確認（Python。スクリプトはコミットしていない）で確かめた。あわせて、全行のセルの右端が、そのページの `備考` 見出しの桁より左にあることも確かめた（違反0）。ただし、これは窓が「備考」の見出しの桁を超えない構造の確認であり、窓の校正が備考に影響されないことの証拠は、テスト（備考の数字を校正に使わせようとする synthetic のページ）で見る。

### 総表との結合（`頁`）

総表の `明細書頁数`（FY2024 は、同じ source に明細表がある行が3,003行）は、明細表の `頁` の番号に対応する。**番号の部分（数字）で結び、`事項` の文字（コードと名称）で絞る。**

- 3,003行のうち2,814行（93.7%）で、その番号の頁が、同じ source の明細表にある。ない189行は、原因を確かめていない（ラベルが無いページ〈78ページ〉がある、など）。
- 総表の `DETAIL` 行（要求番号がある行）で、番号の頁があるのは1,409行。うち1,407行（99.9%）で、同じ頁に、同じ `事項` の文字の行がある。残る2行は、文字が違う。
- その1,407行は、**金額が違う行が0**。696行は、明細表の行にも同じ3つの金額がある。711行は、明細表の行の金額が空欄で、金額はその下の行（目）にある。
- 金額の突合は、明細表の行の下にある目の行の合計を、構造（事項と目の対応）から求める必要がある。親子関係の復元（H1）の範囲。

## 既知の後段課題（v0 の対象外）

- **左側の未解決の行（記録のみ。別途確認する）。** `unresolved.csv` の、継続行の条件に合わない左側の行（FY2024 は1,573行）は、備考の表の一部が多いと見られるが、全件は確かめていない。
- 備考。
- 階層（組織・項・事項・目）の復元と意味付け。`CONTEXT` 行、`row_type`、行の順序が素材になる。
- 金額の数値化。
- text layer の無い2 source（OCR が別途必要）。
- 備考の表が左側の領域から始まるページで、境をまたぐ行や、連結の条件に合わない行（unresolved に残している）。
