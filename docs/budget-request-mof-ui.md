# 概算要求と当初予算の差（`/budget-request-mof`、URL 直打ち）

概算要求額と、MOF の予算書の当初予算額（国会への提出時の政府案）を、項ごとに並べる。差の理由の型をバッジで示す。対象は FY2023〜2026（FY2027 は予算書が未公表）。年度推移（`/budget-request-trend`）とは別のページにする。年度推移には MOF との突合を混ぜない。

```bash
npx tsx scripts/pipeline-v2/build-budget-request-mof-ui.ts   # → public/data/v2/ui/budget-request-mof/{kou,detail}.json.gz、tests/fixtures/budget-request-mof/summary.json
```

実行の順番:

1. MOF 突合（`build-mof-budget-request-match.ts`）
2. 年度推移 CSV（`build-budget-request-trend-csv.ts`）
3. 事項要求の検知（`build-budget-request-jikou-youkyu.ts`）
4. 事項・目の年度推移（`build-budget-request-trend-detail-csv.ts`。詳細の事項・目の要求側）
5. このスクリプト

## MOF の版

すべて提出時（政府案）にそろえる。

| 年度 | 版 |
|---|---|
| FY2023 | `2023` |
| FY2024 | `2024` |
| FY2025 | `2025_teishutsu`（成立後の `2025` は使わない。国会で修正された年度） |
| FY2026 | `2026` |

要求側の所属と前年度予算額は、要求の年度の `request-kou.csv` から取る（`2025_teishutsu` には無いので `2025` のもの）。

## 行

1 行 = 年度 × MOF の項。型は `types/budget-request-mof.ts`。

| 種類（`kind`） | 内容 |
|---|---|
| `matched` 対応あり | MATCHED / NEAR_NAME の MOF の項。同じ MOF の項に複数の要求行が対応するとき（複数の府省の書に載る項、復興特会の持ち分）は 1 行にまとめる。要求額は最も大きい額（合計書）、要求書は書ごとに `books` に持つ |
| `mofOnly` MOF のみ | `unmatched-mof-kou.csv` |
| `reqOnly` 概算要求のみ | NO_CANDIDATE の要求行。要求側の所属＋項名でまとめる |
| `zero` 額0の項 | ZERO_AMOUNT の要求行（前年度・要求とも 0）。既定では隠す |

FY2026 は、対応あり 1,035、MOF のみ 49、概算要求のみ 9、額0の項 42。年度ごとの数は `tests/fixtures/budget-request-mof/summary.json`。

**差** は、当初予算額 − 要求額（正なら要求より予算が大きい）。差率は、差 ÷ 要求額。

**前年度予算額:** 概算要求書は前年度の当初予算額を、予算書は前年度の**補正後**の額（補正予算の改予算額）を載せる。例: 消費者庁共通費 FY2026 の予算書の前年度予算額 5,232,537 千円は、FY2025 の改予算額（当初 5,212,333）。補正で額の変わった項では、両者は違う。FY2026 の予算書の項の前年度予算額は、一般会計 824 項のうち 556 が補正後の額に一致し（補正で変わらない項は 154 が当初と同じ）、特別会計 260 項のうち 68 が補正後、177 が当初と同じ。残り（一般会計 114、特別会計 15）は項の新設・組替えなどで、内訳は未確認。

## 事項・目

詳細のタブ（事項・目）で、要求側と予算書の事項・目を名前でつないで並べる。`detail.json.gz`（行のキー `mofRowKey` → 内訳。型は `types/budget-request-mof.ts` の `BudgetRequestMofDetail`）。つなぐ処理は `scripts/pipeline-v2/lib/budget-request-mof-detail.ts`。

- **要求側:** 年度推移の事項・目（`tests/fixtures/budget-request-trend/{jikou.csv,moku/{year}.csv}`）。目は分冊の明細表から取っており、総表の書とは書が違うので、要求書ではなく項の識別（会計区分＋所管（特別会計は特別会計名）＋勘定＋組織＋項名）で引く。同じ MOF の項に複数の要求行が対応するときは、要求額の最も大きい行（合計書）の内訳だけ。年度推移の内訳は、同じ項が複数の府省の書に載ると書ごとに行を持つので、要求書の公開元（ドメイン）がその行と同じものだけを取る（取らないと、FY2026 の電源開発促進勘定のように 4 府省の書の分を 4 倍に足す）。統合は、要求の項ごとの内訳を足す。
- **計と項の額:** 要求側の事項の計は、FY2024〜2026 のすべての対応ありの項で項の要求額と一致する（FY2023 は 1 項違う）。目の計が違う項（FY2026 で 10）は、要求書の明細表の読み取りの欠け（額の空いた行・画像の頁・目次の無い書・解決できない行）で、年度推移の「項 ≠ Σ目」（`tests/fixtures/budget-request-trend/detail-summary.json` の `kou_ne_moku`）と同じ項。詳細では差額を注記する。
- **予算書側:** `tests/fixtures/mof-archive-csv/{ver}/{jikou,moku}-{general,special}.csv`。項の識別は、一般会計が所管＋組織＋項コード＋項名、特別会計が特別会計＋勘定＋項コード＋項名（どちらも項の CSV で一意）。
- **目:** 予算書の目は項ごと（事項をまたいだ額）なので、要求側も事項をまたいで目名で足す。予算書に事項 × 目の額は無い。
- **つなぐ鍵は名前**（幅と空白をそろえたもの）。目のコードは分類で、1 つのコードに複数の目が入る（FY2026 で予算書の項の中の重複 1,421）ので鍵にしない。コードが同じで片側に 1 つずつ残る目には、改称（国際防災機関等拠出金 → 国際防災戦略事務局拠出金）も別の目への差し替え（経済新生政策調査費 → 成果連動型民間委託契約方式推進調査費）もあり、組にはしない。
- **目のコード:** 主要経費＋目的別-目別（例: `95016-16`）。中段（財政法・経済性質・使途）は、特別会計の要求書の原文（例: `65061-9-18`）と予算書とで桁の取り方が違うので使わない。表示と並びにだけ使う。
- **並び:** 予算書の順。要求にだけある行は、同じコードの予算書の行の後ろ（無ければ末尾）。
- 対応ありの項の事項・目の一致の数は、`summary.json` の年度ごとの `jikou` / `moku`（`kou` 項の数、`sameSet` 集合が同じ項、`bothEq` / `bothNe` 両側にあり額が同じ / 違う、`reqOnly(Zero)` 要求のみ（うち要求額0）、`mofOnly(Zero)` 予算のみ（うち当初0））。FY2026 の目は、両側 7,768・要求のみ 454（うち要求額0 が 376）・予算のみ 151。要求書は額のない目も載せる。

## 差の理由の型

読み方の手がかりで、理由を確定するものではない。

| 型 | 付け方 |
|---|---|
| 事項要求 | 事項要求の検知（`docs/budget-request-jikou-youkyu.md`）の形が `印` か `文`（項の中に事項要求の記載がある） |
| 組織に事項要求 | `jikou.json.gz` の `orgs` に、その組織がある |
| 要求額0 | 検知の形が `要求0` / `要求0・場所ごと` |
| 一括計上 | 検知の形が `一括計上`（概算要求のみの行。例: 国際観光旅客税財源観光振興推進費） |
| 一括計上の配分先 | `要求0` のうち、同じ所管・組織に一括計上の項がある年度のもの（例: 国際観光旅客税財源観光振興費） |
| 編成で決まる | 項名が `予備費` / `国債費` / `地方交付税交付金` / `地方特例交付金` を含むか、`繰入` で終わる |
| 複数書 / 持ち分 | 同じ MOF の項に、複数の書の要求行が対応する。額が違えば持ち分（東日本大震災復興の各省の書と合計の書）。額が同じで、同じ府省（公開元のドメイン）の書どうしなら複数書（例: FY2023 金融庁の分冊）。複数所管で額が同じ項には付けない（所管の列の N所管 で分かる）。額の取れない書（総表の無い分冊）は比べない |
| 名前が近い | NEAR_NAME（予算書の項名が少し違う。詳細に予算書の項名を出す） |
| 改称 | 突合の項名の対応表（`reason` = `kou_renamed`。`docs/mof-budget-request-match.md`）でつないだ |
| 統合 | 複数の要求の項が、1 つの MOF の項に対応する。名前の違う項（対応表の統合。項名は「A ＋ B」）と、同じ書の項コード違いの同名の項（例: FY2023 国土交通本省の情報化推進費 642 と 800（情報管理共通経費（自動車分））。予算書では 1 つの項・1 つの事項）。要求額・前年度予算額は、要求の項ごとの値を足す |

**要求行と型の結びつけ:** 年度推移 CSV の行を、要求書＋項コード＋項名で引く。同じ書に同名同コードの項が複数あるときは、組織か勘定で絞る。事項要求・要求0・組織の事項要求は、その行の識別（会計区分＋所管＋勘定＋組織＋項名）で引く。

**編成で決まる項の重み:** 編成で決まる項に当たる対応ありの項は、各年度で約 1 割。差の絶対値の合計に占める割合は、FY2023〜2026 で 79% / 59% / 38% / 60%（FY2025 は提出時の版）。フィルタの「編成で決まる項を除く」で外して見る。

## 画面

年度推移と同じ 3 ペイン。

**フィルタ（左）**

- 所管・会計
- 組織／勘定・項名
- 行の種類（既定は額0の項以外）
- 差の大きさ（|差| が 1 億・10 億・100 億円以上、差率 ±10%）
- 編成で決まる項を除く
- 差の理由の型（どれかを持つ項）

**一覧（中）**

- 所管・会計・組織／勘定・項名（型のバッジ）・要求額・当初予算額・差・差率。
- 既定は、差の降順。
- 組織の事項要求は、組織の列のバッジにする（年度推移と同じ）。
- **所管:**
  - 府省は、年度推移と同じく要求書の公開元（PDF のドメイン由来）。内閣府の外局（こども家庭庁・消費者庁・金融庁など）は、予算書の所管が内閣府でも、それぞれの府省になる。要求書の無い MOF のみの行は、予算書の所管（特別会計は予算書の共管所管名があればそれ。複数の府省の会計は「、」「及び」の列挙を府省に分ける）。
  - **複数所管の行**（府省が 2 つ以上）は 2 種類ある。
    - 同額: 同じ特別会計（勘定）の要求書全体を、所管の各府省がそれぞれ掲載している。ファイルは別で、体裁（表紙・目次の有無、印刷日時）は違うが、明細と金額は同じ（FY2026 の子ども・子育て支援、エネルギー需給、電源開発促進で確かめた）。データから主の府省は決められない。
    - 合計: 東日本大震災復興だけ。各省が持ち分を載せ、復興庁の書が合計（予算書の共管所管名もほとんど復興庁）。
  - 一覧の列は、単独ならその府省、複数所管は「N所管」（例: 2所管）。府省名はツールチップと詳細に出す。
  - フィルタは府省ごとの選択肢と「複数所管」。府省を選ぶと、その府省が載せている複数所管の行も出る。「複数所管」を選ぶと複数所管の行だけ。件数は合計だけ出す（内訳は出さない）。

**分布図（中のタブ）**

- 横軸は概算要求額、縦軸は当初予算額で、どちらも対数（千円）。対角線は「要求 = 当初」で、それより上は予算が要求を上回った項。
- 0 の値は、軸の外側の帯に置く（対数で描けないため）。要求か予算の無い行（MOF のみ・概算要求のみ）は描かない。
- 色は 3 つ: 編成で決まる項 / 金額を示さない要求を含む（事項要求・要求額0・一括計上の配分先）/ 通常の要求（中身を積み上げて要求し、査定された項。差を査定の結果として読めるのは主にこれ）。3 つともデータとしては正常で、額の決まり方の区別。散布図ですべての組が判別できるのは 3 色まで。
  - 配色: 青 `#2a78d6`、橙 `#eb6834`、緑 `#1baf7a`（ダークは `#3987e5`、`#d95926`、`#199e70`）。
  - 配色の検査を通した（全組、ライト・ダーク）。緑はライトで背景とのコントラストが 3:1 未満なので、一覧（表）を代わりの表示とする。
- 点にマウスを載せると項名・要求額・当初予算額・差、クリックで詳細。フィルタは一覧と共通。

**詳細（右）**

タブで「項 / 事項 / 目」を切り替える（ラベルに事項・目の数。両側の和集合）。

- 項: 要求額・当初予算額・それぞれの前年度予算額（上記の注記つき）・差、要求書へのリンク（`#page=`）、型の説明（事項要求には備考の行を添える）
- 事項・目: 名前・要求額・当初予算額・差の表と計。片側にしか無い行は、無い側を「—」にし「要求のみ」「予算のみ」の印。目は名前の下にコード。計が項の額と合わないときは差を注記する

**絞り込み・並べ替え:** `app/lib/budget-request-mof.ts`（純粋関数）。

**保存:** 年度・表示（一覧 / 分布図）・詳細のタブ・フィルタ・並べ替え・選んだ項・ペインと列の幅は、ブラウザ（localStorage、キーは `budget-request-mof:*`）に保存し、再読み込みしても戻らない。フィルタは保存値を既定値の上に重ねて読む（項目が増えても欠けない）。
