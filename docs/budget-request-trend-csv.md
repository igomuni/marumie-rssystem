# 概算要求の年度推移 CSV（項の粒度, FY2023〜FY2027）

概算要求の項を、年度をまたいで並べるための 1 本の CSV。MOF の予算書との突合は参考情報で、キーにも出力の有無にも使わない。

```bash
npx tsx scripts/pipeline-v2/build-budget-request-trend-csv.ts   # → tests/fixtures/budget-request-trend/{kou.csv,summary.json}
```

- 入力: `tests/fixtures/mof-budget-request-match/{2023,2024,2025,2026}/request-kou.csv`（概算要求の TOC・総表の木だけから決めた項の所属と金額。`build-mof-budget-request-match.ts` が出す）と同 `m1-kou.csv`（突合の状態）、`tests/fixtures/budget-request-csv/{年度}/cover/sources/*.csv`（表紙の所管コード）。
- FY2027 は MOF の令和9年度版が無いため、`mof-budget-request-match/2027/` には `request-kou.csv` だけを置く（`build-mof-budget-request-match.ts 2027 2026 <dir>` を実行し、`request-kou.csv` だけを残す。他の出力は MOF 令和8年度を辞書にした参考にならない値なので置かない）。`MOF突合(参考)` は空。

## 列

| 列 | 内容 |
|---|---|
| `年度` | 概算要求の年度（西暦） |
| `会計区分` | 一般 / 特別 |
| `所管コード` | 表紙の見出しのコード（例: `19` 内閣府、`9905` エネルギー対策特別会計） |
| `所管` | 一般会計の所管名（目次の見出しから）。特別会計は空 |
| `特別会計` `勘定` | 特別会計の名称と勘定（一般会計は空） |
| `組織` `組織の出所` | 組織名と、その出所（`目次` / `総表` / `表紙括弧` / `他の書` / `なし`） |
| `項名` `項コード` | 項の名称（空白を除く）とコード（組織内の連番で、キーにしない） |
| `前年度予算額_千円` `要求額_千円` `増減_千円` | 総表の値。増減は要求額 − 前年度予算額（総表の値ではなく差を計算） |
| `要求書` `頁` `PDF頁` `PDFの要求書` `PDF頁の根拠` `画像頁` `階層` | 出所（source の slug、TOC 上の頁＝紙面の印字、PDF の通し頁、`toc` / `position`）。`PDF頁` は、同じ書（分冊を含む。slug から日付と末尾の連番を除いたもの）の明細表の項（CODE3）の行を、項コード + 項名（複数に当たるときは組織。項が複数の PDF にまたがる内閣府・内閣官房の分冊は、各 PDF の項の要求額の合計が項の要求額に一致すれば、最初の PDF の最初の頁。`e1` / `e2` のような英字つきの連番は別の書として扱う）で探し、その行の `source_page`（PDF の通し頁）をそのまま使う。決まらない行は、目次の印字頁（`4復興特` `エ1` のような接頭辞・接尾辞つきもある）を明細表の各行の `頁` ラベルに引き当てる。分冊の書（文科省など。表紙・目次・総表だけの PDF と、明細表を持つ複数の PDF に分かれる）は、`PDFの要求書` がその明細表を持つ PDF で、UI のリンクもそこを開く（`#page=<PDF頁>`）。`PDF頁の根拠` は `項`（明細表の項の行）/ `頁ラベル`（印字頁の引き当て）/ `推定`。引けなかった行は、同じ PDF の印字頁と PDF の頁の差が前後で同じとき（目次の頁の前後 8 頁以内）に推定する。後ろに頁ラベルが無い（以降が画像の頁の）ときは、直前の 2 つの頁ラベルで差が同じとき（例: 法務省 FY2026 の破壊的団体等調査費は、763 → 767、765 → 769 の差 4 から 764 → 768。FY2025 は 724 → 728、726 → 730 の差 4 から 728 → 732）。推定した頁に文字層が無い（plain text で空）ときは `画像頁` = 1（その頁は画像のスキャンで、明細表の目以下が取り込めていない。金額は総表の値）。推定もできない行は空で、リンクは PDF の先頭を開く（各年度で全体の約 2〜3%、主に内閣府の一部の分冊） |
| `複数書` | 同じキーが同じ年度に複数の要求書にある行は 1。CSV では要求書ごとに別の行で、どの行にも 1 が付く（複数所管の項も含む）。UI の「複数書」（バッジ・データの状態）は、同じ府省の複数の要求書に載る項だけ（例: FY2023 金融庁の分冊）。複数所管の項は所管の列（N所管）で分かるので含めない |
| `金額不一致` | `複数書` のうち、要求額か前年度の額が行によって異なるものは 1 |
| `繰入先` | 項の下の目の名前に「繰入」を含むときの繰入先（目名、「、」区切り。例: `交付税及び譲与税配付金特別会計へ繰入`）。明細表の項（CODE3）に続く目（CODE_）から引く。受け側は歳入なので、会計をまたぐ合計では二重になりうる（一覧の「繰入」バッジ・フィルタ） |
| `MOF突合(参考)` | `m1-kou.csv` の status（FY2027 は空） |

キー（年度ごとに）: `会計区分 + 所管名（一般会計のみ。特別会計は特別会計名）+ 勘定 + 組織 + 項名`。表紙の所管コードはキーにしない（年金特会 9207 → 2507 のようにコードだけ変わる。コードは `所管コード` 列と UI の詳細に年度ごとに残す）。項コードは組織内の連番でキーにならない。ただし同じ要求書の中で同名の別の項（例: 厚生労働調査研究等推進費の 087 / 405、国交省の情報化推進費の 642 / 800）が同じキーになるときは、そのキーを全年度で `項コード` つきの別の行にする（UI の `kou`）。名称の変更・統廃合の紐づけは、このCSVの範囲外（別のロジック）。

## 方針

- **組織**: 目次があれば目次の見出し。目次を持たない要求書は、総表で「組織計」（TOTAL）の後ろ（表の始め）にある CODE3 の行のうち、次の行も CODE3 のものを組織の見出しとする（項には明細が続く）。それでも決まらない行は、表紙の括弧内の組織で補う。
- **会計・所管・特別会計名が明細表の CONTEXT 行から決まらない行**（FY2023 の金融庁・個人情報保護委員会、FY2027 の総務省冊子の復興特会 3 行など）は、表紙の見出しで補う（コード 2 桁は一般会計の所管、4 桁は特別会計）。
- **複数の府省の要求書に載る特別会計の項は按分しない。** 同じ特別会計の項が複数の府省の要求書に載り、額が同じ（総額が各書に載る）。CSV では要求書ごとに行を残し、`複数書` を付ける。所管をまたいで合計すると二重になる。UI では同じキーを 1 行にまとめる。
- **例外: 東日本大震災復興特別会計は各書が自分の取り分だけを載せ、復興庁の書が合計を載せる**（例: FY2026 東日本大震災復興事業費の要求額は 国交省 22,381,339 ＋ 復興庁 4,054,000 ＝ 復興庁全体書 26,435,339）。これが `金額不一致` の主な原因。UI では同じキーで額が違うときは最も大きい額の書（合計書）の額を表示し、各書の額は詳細の PDF の横に出す。
- 検算（要求額 − 前年度 = 増減）は総表の値では行わない。増減は差を計算した値。
- 単位は千円。事項要求（金額を持たない要求）は、項に金額がある限りこの CSV の対象外ではない。金額が無い行は空。

## UI（`/budget-request-trend`、URL 直打ち）

- データ: 同じスクリプトが `public/data/v2/ui/budget-request-trend/kou.json.gz`（キー単位に束ね、元の PDF の URL を持つ。型は `types/budget-request-trend.ts`）を出し、ページがブラウザから静的ファイルとして直接取得する（Vercel の関数には `public/data` を同梱しないため、API を経由しない。他の v2 データと同じ方式）。
- 画面: 左がフィルタ、中が選択年度の一覧（所管・組織・項名・前年度予算額・要求額・増減・増減率）、右が選んだ項の全年度分の表・棒グラフ・元の PDF へのリンク。
- 金額は `client/lib/formatBudget.ts` の `formatBudgetShort` と同じ桁数（/sankey-svg に合わせる）で、円・万円・億円・兆円に自動で切り替える。
- 増減・増減率は、その年度の要求額 − 前年度予算額（その年度の要求書が載せる値どうし）。新規・消滅は前年度のキーとの比較。名称変更の紐づけはしない。
- 絞り込み・並べ替えは `app/lib/budget-request-trend.ts`（純粋関数）。
- 要求書の公開元（PDF のドメイン → 府省庁名、`publisherOf`）は、キーに使わず表示だけに使う。詳細の PDF リンクに府省名を付け、一覧の所管の列（N所管）のツールチップに載っている府省を出す。特別会計の共管（どの府省の書にも載る）や、復興特会の各省の取り分の内訳を追うため。
- UI の「所管」（一覧の列・フィルタ・詳細）は、その年度に載っている要求書の公開元の府省（PDF ドメイン由来）。複数の府省の書に載る項（複数所管）は、一覧の列では「N所管」とし、府省名はツールチップと詳細に出す。フィルタは府省ごとの選択肢と「複数所管」で、府省を選ぶとその府省が載せている複数所管の項も出る。一般会計の内閣府の外局（消費者庁、金融庁など）も、それぞれの書の府省として別に数える。要求書が引けないときだけ表紙の所管名。CSV の `所管` 列（表紙）は変えない。
- 一覧の 1 行は、項（2026-10-22 から。それまでは項 × 所管で、複数所管の項を府省ごとに出していた）。複数所管の項は 2 種類で、同額（同じ要求書を各府省が載せている）と、東日本大震災復興の持ち分（各省の書と復興庁の合計の書）。金額はその年度の値（書ごとに額が違うときは最も大きい額＝合計書）なので、一覧の合計は二重に数えない。各書の額は詳細の PDF の横に出す。画像頁・PDF頁なしのバッジは、どの府省の書かをツールチップに出す。 列は 所管 → 会計（一般会計 / ○○特別会計）→ 組織（特別会計は勘定）→ 項名。会計のバッジ列は廃止。詳細は項（キー）単位のまま。
- 表紙の頁が無い書（総表・明細表から始まる抜粋版。FY2026 の環境省エネルギー対策・復興、FY2023 の金融庁の 1 冊）は、所管コード・組織を明細表の先頭の CONTEXT 行の見出しから補う（表紙の CSV は変えない）。補わないとコードが空のまま別キーになり、他府省の書と 1 行にまとまらない。
- 組織が引けなかった特別会計の行（目次の無い抜粋版。例: 環境省 FY2026 の復興特会）は、同じ年度・所管コード・特別会計・勘定・項名で他の書が示す組織が 1 つに決まるときに、それで補う（`組織の出所` = `他の書`）。補わないと別キーになり、同じ項が 1 行にまとまらない。
- 項のつなぎ（UI。`kou.json.gz`、`summary.json` の `links`）: 前年度に無い項（新規）と、その年度に無い項（消滅）で、会計区分が同じ、項名が同じかほぼ同じ（編集距離 2 以内、6 文字以上）、新規側の前年度予算額が消滅側の要求額の ±30% 以内（どちらも 0 超）、同名に近い候補が 1 対 1 に決まるものを対応づける。そのうち移管元が特定できる次のどちらかは、1 つの行につなぐ（`moved`、年度推移が続く）。
  - 改称: 所管（特別会計名）と勘定が同じで、組織か項名だけが変わった（地方環境事務所 → 地方環境局など）。
  - 移管: 移管先の特別会計 + 勘定がその年度に新設された（前年度に無い）。移管元は消滅側の項（年金特会 → 子ども・子育て支援特会など）。
  - 上の条件を満たさない対応は、つながず候補のまま（`from` / `to`。詳細の「紐づけの候補」と一覧の「紐づけ候補」バッジ。例: 厚労省 → 国交省の水道施設整備事業調査諸費）。
  - FY2023〜2027 で、移管 6、改称 9、候補のまま 1。
- データの状態（UI のフィルタ・バッジ）: 所管コードの変更（前の年度から。つないだ項は除く）、会計・勘定の新設（特別会計 + 勘定がその年度に初出）、移管・改称。会計・勘定の新設は、corpus に前年度の書が無いだけでも立つ（交付税及び譲与税配付金特別会計は FY2024 で立つが、FY2023 の corpus に書が無いため）。
- 事項要求（データの状態のフィルタ・バッジ・詳細の注）: 備考に事項要求（金額を示さない要求）の記載がある項。前年度に額があり要求額が 0 の項は出さない（前年度限りの経費なども含むため）。別のスクリプトが出す `jikou.json.gz` を、ページが取得して合流する（仕様: `docs/budget-request-jikou-youkyu.md`）。
- データの状態に「PDF頁なし」（PDF の頁が引けず、リンクが PDF の先頭を開く載り先がある項。FY2023〜2027 で 18 / 13 / 14 / 12 / 12 件）と「画像頁」（推定した頁に文字層が無い）を持つ。
- 明細表の CSV が無い書（明細表のヘッダが読めなかったもの。FY2023 の個人情報保護委員会は `(補正後予算額)` 付きのヘッダ）は、plain text の明細表の表題の頁から先の各頁の先頭行にある印字頁（`内（個） 3`、`4 内（個）`）から頁ラベルを作り、目次の頁を引き当てる（3 → 7）。明細表の CSV 側の取りこぼしは別に残る。
- 「PDF頁なし」「画像頁」「推定」は、載り先（`src` の各 PDF）ごとの状態で、一覧では所管（府省）のレコードごとに判定する。複数の府省の書に載る項で、片方の書だけ頁が引けなくても、もう片方のレコードには付けない。
