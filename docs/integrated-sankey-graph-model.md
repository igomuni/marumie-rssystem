# 統合サンキーのグラフモデル

`/integrated-sankey` は、MOFの「項」とRS予算事業の対応関係を見る実験ページ。
仕様の正は `docs/tasks/20260913_1555_統合サンキー再構築の確定仕様.md`。本書は実装後の恒久ガイド。

## 2列のノード一覧（帯は描かない）

**項と事業をつなぐ帯（エッジ）は無い。** 左列がMOF項、右列がRS事業の、独立した2つの
ノード一覧。ノードは金額に比例した高さのバーとして描くが、列と列の間を結ぶ線は引かない。

対応関係（どの項がどの事業に接続しているか）は、ノードを選択したときの**詳細パネルの
一覧**でのみ見せる（下記「詳細パネル」）。選択すると、対応するノードが相手列で
淡く強調される（opacityのみ。線は引かない）。

この方針変更の経緯：当初は項×事業を結ぶ帯を描く設計だったが、「ノードのみのページ」
という指示を受けてやり直した。目エッジ（目単位の個別の帯）を廃したあと、項×事業へ
集約した帯も含めて全廃した（`docs/tasks/20260913_1529`・`20260913_1555` 参照）。

## 画面の基準

`/sankey-svg` の「サンキー図そのもの以外」のコントロール一式（検索・フィルタ・ズーム・
パン・サイドパネルの枠・年度切替・ページ切替）をそのまま引き継ぐ。既存ページ・
共有部品は変更しない。

MOF項・RS事業という2ノード型は、`/sankey-svg` の4列（総計/省庁/事業/支出先）レイアウト
エンジン（`app/lib/sankey-svg-filter.ts` の `filterTopN`/`computeLayout`）が前提とする
ノード型と根本的に異なるため、**データ・レイアウトのロジックは `page.tsx` 内に新規で持つ**。
一方、検索ボックス・フィルタパネル・ズームコントロール・サイドパネルヘッダーの
**UI構造とスタイル値は `/sankey-svg` の実装からそのまま移植**する（近似で書き直さない）。

### 項の識別

会計区分・予算種別・所管・組織／特別会計・勘定・項コードの組で識別する
（`app/lib/integrated-sankey.ts` の `itemSectionKey`）。項名または項コード単独をIDにしない。

## 検索とフィルタは別物

`/sankey-svg` と同じ設計を守る。

- **検索（ジャンプ機能）**：`SearchJumpBox`。**1本のボックス**で項名・事業名を横断する
  （`/sankey-svg` の検索が事業名・支出先名を1本で横断するのと同じ考え方。所管・会計区分は
  検索対象に含めない）。グラフを絞り込まない。入力に一致するノードをドロップダウンに
  列挙し、クリックすると該当ノードへ選択・ウィンドウ移動する。部分一致・正規表現の
  2モードを切り替えられる（`.*` トグル）。不正な正規表現は例外を投げず「該当なし」
  として扱う（`buildMatcher` に集約）
- **フィルタ（絞り込み）**：検索ボックスの下に開閉する `filtersOpen` パネル。実際に
  グラフから項・事業を除外する。会計区分・所管はチェックボックス付きコンボボックス
  （`CheckboxCombobox`）、項名・事業名は部分一致テキスト＋正規表現トグル
  （検索ボックスとは別の入力欄、`TextFilterRow`）、項予算・事業予算はそれぞれ
  独立した金額レンジ（`parseAmountToYen` で解釈）

`CheckboxCombobox` の選択状態は `string[] | null`（`null` ＝未操作＝すべて含む、
配列は空配列も含めユーザーが明示的に選んだ状態）で持つ。`.length === 0` を
「絞り込みなし」として扱う設計だと「すべて解除」と「未操作」を区別できず、
「すべて選択/解除」チェックボックスで解除ができない不具合になる。

検索・フィルタのドロップダウンは、全画面の透明レイヤーではなく**外側クリック検知**
（`document.addEventListener('mousedown', ...)` ＋ ルート要素への `ref`）で閉じる。
全画面レイヤーだとトリガーボタン自身もレイヤーの下敷きになり、再クリックで
閉じようとした操作が奪われるため使わない。

## ノードのラベル

`/sankey-svg` と同じく、**名前と金額を1つのラベルとして常に併記**する
（`{name}（{money}）` 形式）。ノード高が一定未満（`LABEL_MIN_PX`）の場合はラベル全体
（名前・金額とも）を隠す。名前だけ表示して金額を隠す、という個別の閾値は持たない。
長い名前は `/sankey-svg` の `name.length > 40 ? slice(0,40)+'…' : name` と同じ考え方で
`NAME_MAX_CHARS` で切り詰める（ガター幅が狭いぶん文字数は少なくしてある）。

## 列見出しの合計金額

`/sankey-svg` の列ヘッダー（ラベル＋合計金額の2行）と同じ構造。各列見出しの下に、
その列の**フィルタ後の全件合計**（表示ウィンドウの外に出た分も含む）を表示する
（`view.sectionColumnTotal`/`projectColumnTotal`）。

## 金額→高さの縮尺・実測ピクセルでの描画

- 金額→高さの縮尺（`ky`）は項・事業の**両列で共有**する（`buildLayout` 内で
  `Math.min(availLeft/leftTotal, availRight/rightTotal)` として算出）。列ごとに
  別の縮尺を使うと、同じ高さのバーが列によって違う金額を表すことになり、
  見た目で比較できなくなるため
- SVGの `viewBox` は固定値ではなく、`ResizeObserver` でコンテナの実測ピクセル
  サイズ（`Dims {w,h}`）を測り、それをそのまま使う（`preserveAspectRatio` に
  よる縮小拡大はしない）。ウィンドウの高さを縮めてもラベルの文字サイズが
  一緒に縮まないようにするため（`/sankey-svg` と同じ考え方）。`ResizeObserver`
  はコンテナ要素の**callback ref**（`useState` + `useCallback`）で張る。
  データ読込中はコンテナ未マウントのため、`useRef` + 空配列 `useEffect` では
  初回マウント時に `current` が `null` のまま observer が張られず、以後
  再実行もされないため `dims` が既定値に固定される不具合があった

## 金額定義

| 対象 | 使用する金額 |
| --- | --- |
| MOF項の総額 | 配下にあるMOF目の `amount` 合計 |
| MOF項の前年度額・増減率 | 配下の目の `previousAmount`/`difference` を合算（null は0扱い） |
| RS事業の予算額 | `initialBudget`（当初予算） |
| RS事業の支出額 | `budgetSummary.executedAmount` |
| RS事業の会計区分 | 接続する目の `mofAccountType` から集計。単一なら一般/特別、複数にまたがれば `mixed` |

項の一覧・事業の一覧は互いに独立してフィルタ・並べ替えする（片方の絞り込みが
もう片方の母集合に影響しない）。帯を描かないため、旧設計にあった
「項の窓を動かすと事業側の母集合が変わらないようにする」調整は不要になった。

### 禁止事項

- MOF目の全額を、接続したRS事業へそのまま流したように見せない（そもそも流れを描かない）
- `MOF目金額 − RS接続額` が負になる場合（超過）を0へ丸めて隠さない。目一覧に表示する

## 年度切替

対応年度はRS2025（MOF2024）・RS2024（MOF2023）の2つ（`app/api/integrated-sankey/route.ts`
の `SUPPORTED_RS_YEARS`）。**紐づけ品質は年度で大きく異なる**（実測: RS2025×MOF2024は
事業紐づけ率92.7%、RS2024×MOF2023は21.3%）。API は `linkageQuality`
（`app/lib/api/mof-rs-kou-moku-linkage-loader.ts` の `linkageQuality()`）を常に返し、
画面右上に隠さず数値で表示する（誇張した注記は付けない）。この紐づけ率バッジは
`pointerEvents: 'none'`（情報表示のみでクリック対象を持たないため、下に重なる
RS事業列上部のノードへのクリックを奪わないようにする）。

紐づけ生成ロジック（`scripts/generate-mof-rs-kou-moku-linkage.ts`）自体の精度改善は
別task doc（未着手）。今回は既存の生成済みデータをそのまま両年度分出している。

## 事項データ（未統合）

MOF予算書には「目」（性質別）とは別に「事項」（目的別、`/mof-jikou` が扱う）という
分類がある。統合には新規のデータ結合パイプラインが要るため今回のスコープから外した
（別task doc、未着手）。現在の項の詳細パネルは「目一覧」「RS事業一覧」の2タブ。

## 詳細パネル

`SidePanelChrome`（`/sankey-svg`・`/subcontracts` と共有）を**左側**に開く
（`/sankey-svg` のノード詳細パネルと同じ側。右側はAIチャット等、本ページには無い）。

`/sankey-svg` の左ノード詳細と同じ構造：ヘッダーは固定（`flexShrink: 0`）、
タブバーも固定、**タブ内容のみが `overflowY: auto` でスクロールする**。

### ヘッダー構成

名前＋閉じるボタン（✕）の行、その下に金額ブロック（ラベル・太字の金額・実数円の
3段組、複数値は横並び）、さらにその下にバッジ行。

- 種別バッジ（色付きピル）：項＝会計区分の色、事業＝緑
- 会計区分バッジ：`getAccountBadgeStyle`（`/sankey-svg`・`/subcontracts`・MOF予算書
  ページと共有のヘルパー。'general'|'special'|'both'|'agency' を受ける。事業の
  `accountType: 'mixed'` は `'both'` に読み替えて渡す）
- 所管・部課局等のメタ情報

### 項選択時

ヘッダー金額：本年度額／前年度額（＋増減・増減率）。
タブ：目一覧（接続先事業・状態・金額）、RS事業一覧（この項から接続する事業の合計額）。

### 事業選択時

ヘッダー金額：予算額／支出額（`/sankey-svg` の予算/支出ペア表示と同じ構造）。
タブ：予算執行一覧（`budgetSummary` の当初・補正・繰越・予備費・執行率等の表形式表示、
接続するMOF項一覧）、目一覧（既存の `budgetItems`、MOF接続済み/未接続バッジ付き）。

**部課局は近似値。** 事業内で複数組織にまたがる場合があり、目内訳の先頭行
（`budgetItems[0].organizationAccount`）を代表値として使っているため厳密ではない。

### 「その他の項」「その他のRS事業」集約ノード選択時

表示ウィンドウの外に出た項・事業そのもの（名前・金額）を一覧する
（`view.hiddenSections`/`hiddenProjects`）。
