# 統合サンキーのグラフモデル

`/integrated-sankey` は、MOF予算書の「目」を介してMOFの項とRS予算事業の対応関係を見る実験ページ。
本書はそのグラフモデルと金額定義を扱う。検討の経緯は `docs/tasks/` の統合サンキー関連 doc を参照。

## 画面の基準

`/sankey-svg` のLook、ズーム、パン、検索、選択、詳細パネルを基準とする独立ルート。
既存ページ・共有部品は変更しない。複製なので基準ページの変更は自動反映されない。

画面まわりの構成も `/sankey-svg` に合わせる。

- 図は全面に置き、操作系は浮かせる（固定ヘッダーのバーは作らない）
- **右上クラスタ**に［検索 - 表示件数 - ズーム - ページ切替］を並べる。
  `PageNavMenu` のドロップダウンは右端基準（`absolute right-0`）で開くので、
  **必ずクラスタの右端に置く**。左端に置くとメニューが画面外へ出る
- 右パネル展開時は `right: 12 + rightControlsOffset` で左へ退避させる
  （`/sankey-svg` の `rightControlsOffset` と同じ方式）。図の領域も同じ幅だけ狭め、
  viewBox の fit で図を描き直すので、パネルが図を覆わない
- 詳細パネルの幅管理そのものも独自実装しない。`/sankey-svg`・`/subcontracts` と同じ
  `client/hooks/useSidePanel.ts`（幅・折りたたみ・リサイズドラッグ・実効幅クランプ）と
  `client/components/SidePanelChrome.tsx`（枠・リサイズハンドル・開閉タブ）を使う。
  `rightControlsOffset` は `detailPanel.effectiveWidth`（折りたたみ時は0）から算出する
- 浮遊UIと列見出しが重ならないよう `PAD_TOP` で上部の余白を確保する。
  重なりは e2e で回帰検証している（左上カードの右端 < 見出しx、右上クラスタの下端 < 見出しy）

## 2列モデル

```text
MOF項 ── 目エッジ ──→ RS予算事業
       ├ 目エッジ ──→ RS未接続
       └ 目エッジ ──→ 超過・要確認
```

左列はMOFの項、右列はRS予算事業と集約ノード。MOFの「目」はノードではなくエッジとして表す。

同じRS事業が複数の項に接続する場合、複数の項から同じ事業ノードへ収束させる。
同じ項と同じRS事業の間に複数の目がある場合も、モデルは目別エッジを保持する（束ねるかは描画側の判断）。

### 項の識別

会計区分・予算種別・所管・組織／特別会計・勘定・項コードの組で識別する。
**項名または項コード単独をIDにしない。** 別会計・別所管に同名同コードの項が存在するため。

### 集約ノード

| ノード | 意味 |
| --- | --- |
| `RS未接続` | MOF目金額のうち、RS事業への接続で説明されない部分 |
| `超過・要確認` | RS計上額がMOF目金額を上回る分。原因未調査 |
| `その他のRS事業` | 表示件数の外に落ちたRS事業の集約（描画側のみ） |

`RS未接続` を「制度上のRS対象外」と断定しない。未接続理由の自動分類は行っていない。

## join

`generate-mof-rs-kou-moku-linkage.ts` が生成する `mof-rs-kou-moku-linkage-{budgetYear}.json` を使う。
一般会計は予算種別・所管・組織・項名・目名、特別会計は予算種別・所管・会計・勘定・項名・目名を
NFKC正規化と空白除去のうえ完全一致で照合する。`carriedOverFrom` を持つ決算引き継ぎリンクは使わない。

RS事業の予算内訳は `generate-sankey-svg-data.ts` の生成物（project-budget ノード）を projectId で参照する。

対応年度はRS 2025／予算年度2024のみ。RS 2025は2024会計年度のMOFを参照する。
他の年度はAPIが400で明示的に拒否する（黙って空を返さない）。

## 金額定義

全金額は1円単位。

| 対象 | 使用する金額 |
| --- | --- |
| MOF項の総額 | 配下にあるMOF目の `amount` 合計 |
| RS事業へ向かう目エッジ | 結合レコードの `rsAmount` |
| RS未接続へ向かう目エッジ | MOF目金額 − その目からRS事業へ向かう `rsAmount` 合計 |
| RS事業ノードの図中流入額 | MOF接続済みの `rsAmount` 合計 |
| RS事業の当初予算総額 | RS側の当初予算合計。詳細パネルで別表示 |

### 禁止事項

- MOF目の全額を、接続したRS事業へそのまま流さない
- 一つでもRS事業がある項について、項全額をRS接続済みと扱わない
- `MOF目金額 − RS接続額` が負になる場合、0へ丸めて隠さない（`超過・要確認` として集計する）
- MOF当初予算とRSの歳出予算現額・執行額を同じエッジで混在させない

次の恒等式が常に成立する。e2eで検証している。

```text
connectedAmount + unconnectedAmount − excessAmount = mofAmount
```

## 描画の約束

金額の視覚符号化はサンキー図の意味そのものなので、次を守る。

- **帯の太さとノード高は金額に線形比例する。** 平方根スケールを使わない。
  平方根だと429兆円と1兆円の比が 429:1 ではなく 20.7:1 に潰れ、図が金額について嘘をつく
- **帯はノードの縦方向へ順に積み上げる。** ノード中心へ集約しない。
  中心固定だと1ノードの全帯が一点へ収束し、どの帯がどこへ向かうか追えなくなる
- 左右の列は同じ帯集合を共有するので、列の合計高は必ず一致する
- 左右で同じ縮尺 `ky` を使う。帯の太さが両端で変わらないようにするため
- `viewBox` は内容の実寸（`contentH`）に合わせる。固定値にすると最大ノードが見切れる

表示件数の外に出た項・事業は捨てず、`その他の項` `その他のRS事業` へ束ねる。
このため**表示件数を変えても図に描かれる金額の合計は変わらない**（ヘッダの「描画」行と一致する）。

### 帯の合計とMOF総額の差

`超過` はMOF目金額を上回った分を項からの独立した流出として描くので、帯の合計は

```text
帯の合計 = 接続 + 未接続 + 超過 = MOF総額 + 2 × 超過
```

となる。2024年度当初予算では超過が502.9億円なので差は約1005億円（MOF総額の0.02%）。
これは超過を0へ丸めない方針の帰結であり、隠さずヘッダに内訳を出す。

## MOF未接続（RS側にだけある目）

RSの歳出予算項目がMOFの目に完全一致しない状態。**Sankeyへ推測エッジを追加しない。**
RS事業ノードを選択した詳細パネルの「目」タブに、MOF接続済みと区別して表示する。

## 基準実測値

2024年度当初予算。実装後の集計検証に使う値で、e2e `tests/e2e/integrated-sankey.spec.ts` が突き合わせている。

| 指標 | 金額 |
| --- | ---: |
| MOF一般会計 | 112.57兆円 |
| MOF特別会計 | 436.04兆円 |
| MOF合計 | 548.61兆円 |
| MOFへ完全一致したRS金額 | 119.37兆円 |

政府関係機関はRS側に対応する会計区分がないため接続対象外。

## 対象外

MOF総計・会計階層・府省庁・組織・勘定の各列、RS府省庁列、支出先列、会計間繰入を含む純計フロー、
補正予算・繰越・予備費・決算、複数年度比較、再委託フロー。
これらは2列の接続表現を確認したうえで段階的に追加する。
