# MOF 予算書（項・事項・目）× 概算要求（TOC・総表・明細表）の突合

MOF の予算書の項・事項・目（[mof-archive-csv.md](mof-archive-csv.md)）と、概算要求の目次（TOC）・総表・明細表（[budget-request-toc-pdf-native-csv.md](budget-request-toc-pdf-native-csv.md)、[budget-request-total-table-csv.md](budget-request-total-table-csv.md)、[budget-request-detail-table-csv.md](budget-request-detail-table-csv.md)）を、名称とコードで対応づける。対象は FY2023（令和5年度）、FY2024（令和6年度）、FY2025（令和7年度）、FY2026（令和8年度）の一般会計・特別会計。

- 実装: `scripts/pipeline-v2/build-mof-budget-request-match.ts`（runner）、`scripts/pipeline-v2/lib/mof-budget-request-match.ts`（木・名称キー・金額の読み取り）
- 出力（git 管理）: `tests/fixtures/mof-budget-request-match/{2023,2024,2025,2025_teishutsu,2026}/`（`manifest.json` に SHA-256）。ディレクトリ名は MOF の版: `2023`＝令和5年度（提出時）、`2024`＝令和6年度（提出時）、`2025_teishutsu`＝令和7年度の提出時、`2025`＝令和7年度の成立後、`2026`＝令和8年度（提出時）。概算要求は FY2023 が `2023`、FY2024 が `2024`、FY2025 が後の 2 つ、FY2026 が `2026` と対になる。
- 旧い突合（J1＋K2、[budget-request-detail-table-mof-match.md](budget-request-detail-table-mof-match.md)）とは別系統。置き換えてはいない。

```bash
# 入力: tests/fixtures/budget-request-csv/{year}/{toc,total-table,detail-table}/sources/*.csv と tests/fixtures/mof-archive-csv/{version}/
npx tsx scripts/pipeline-v2/build-mof-budget-request-match.ts <2024|2025|2026> <2023|2024|2025|2025_teishutsu|2026> <out-dir>
```

## 原則
- **名称は空白を除いた完全一致**。比較の前に、幅の統一だけをする（全角の ASCII 相当 → ASCII、半角カナ・約物 → 全角）と、要求書の PDF の外字（私用領域のコード）を字にする（`PDF_GAIJI`。MOF の予算書の同じ名前で字を確かめたものだけ。今は U+E5E3 → 填: 貨幣交換差減補填金・償還差額補填金・…減収補填特例交付金。目次・総表・明細表の CSV は原文のまま）。それ以外の正規化・部分一致・読み替えはしない。

**PDF の外字について（2026-10-22 に確認）**

- **出どころ:** 外字の字形は、要求書の PDF に埋め込まれた利用者定義のフォントにある。例えば内閣府 FY2026 の分冊（`cao.go.jp/yosan/soshiki/r08/pdf/e2.pdf`）では、`pdffonts` で `FJUSER+FUJ-Minchotai` と出る。名前から富士通系の外字フォントと見ているが、出どころは確かめていない。私用領域（U+E000〜F8FF）のどのコードにどの字を置くかは、このフォントを使う作成環境ごとに決まり、Unicode の字との対応表は PDF に無い。pdftotext はそのコードのまま出すので、ブラウザでは表示されない（例:「貨幣交換差減補金」に見える）。
- **量:** plain text 全体（FY2023〜FY2027）で約 3 万字。大半は備考の積算内訳の中にある（例: U+EF63 は「（Ａ４ ５００枚[外字]５冊）」の「×」）。名前（項・事項・目）に出るのは、ほぼ U+E5E3（填）だけ。
- **対応の決め方:** MOF の予算書に同じ名前があり、字が確かめられたものだけを `PDF_GAIJI` に足す。確かめられない外字は、そのまま残す。名前に残った外字の数は、事項・目の年度推移 CSV の `detail-summary.json`（`gaiji_left_in_names`）で見る（全年度 0）。
- **デジタル庁の「行政事務標準文字」は使えない:** 地方公共団体向けの文字の仕様で、`https://www.digital.go.jp/policies/local_governments/character-specification` にある。公開物は、文字図形の一覧表（PDF）、文字包摂の手引き、MJ に無い約 1 万字の明朝フォント（OFL 1.1 ほか）。ページの説明には、私用領域のコードから字への対応表は見当たらない。また、要求書の PDF の外字は作成環境のフォント（上）の割り当てで、この仕様とは関係がない。
- **金額は対応づけに使わない。** 一致後の整合の診断の列（`amount_diff` など）にだけ使う。概算要求（要求時）と予算書は別時点の額で、不一致は失敗ではない。
- 候補が複数のときは**絞らず**、候補ごとに 1 行ずつ記録する。
- 上位の層が一意に対応しなかったときは、下位は探さない（`PARENT_UNMATCHED`）。

## 層
| 層 | 概算要求側 | MOF 側 | 根拠 |
|---|---|---|---|
| M0 主体 | 明細表の `CONTEXT`、TOC の（所管／会計／勘定／組織） | 所管・組織・特別会計・勘定 | 名称の完全一致 |
| M1 項 | 項（TOC の `（項）`、または下記の位置の木） | 項（kou） | 範囲の中での項名の完全一致。コードは使わない（概算要求の 3 桁は MOF の項コードと一致しない） |
| M2 事項 | 項に続く事項（`NN‑NN 名称`） | 事項（jikou） | 一致した MOF の項の中での事項名の完全一致。`NN‑NN` の後半＝主要経費別分類コードを裏づけの列に記録（除外しない） |
| M3 目 | 明細表の目（`NNNNN‑X‑YY‑ZZZZ 名称`） | 目（moku） | 一致した MOF の項の中で、**項ごとに集約**してから対応づける |

- M3 の集約: MOF の目は項単位で事項の列がなく、項内の複数の事項にまたがる目の合計になり得る。概算要求の目の行を（主要経費2桁＋目的別3桁、`X`、目別 `YY`、目名）で足し合わせ、MOF の目に多対一で対応づける。`X` の桁数で読みが決まる: 4 桁＝財政法＋経済性質別＋使途別（一般会計）、3 桁＝経済性質別＋使途別、1 桁＝使途別（特別会計）。最後の 4 桁 `ZZZZ` に対応する MOF の列はなく、比べない。
- 一般会計は（所管, 組織, 項名）、特別会計は（特別会計, 勘定, 項名）で MOF の項を探す。復興庁の共管など、同じ名称が複数あれば複数候補になる。

## 概算要求側の階層の決め方
1. **TOC を持つ source:** TOC の見出し（`（所管）`・`（会計）`・`（組織）`・`（勘定）`・`（項）`）だけで決める（`hierarchy = toc`）。
2. **文書セット:** 目次・総表・明細表が別 PDF に分かれる文書（文部科学省など）。TOC を持たない source を、同じファミリー（source 名の末尾の数字を除いた共通部分）の TOC の source に、項（コード＋名称）の一致で付ける（付く先がちょうど 1 つのとき）。付いた組は `sets.csv`。
3. **TOC のない source で総表がある（`hierarchy = position`）:** 総表の行の並びから木を作る。項＝`CODE3` の次が `DETAIL` で、下の「総表の小計の構造」で項になるもの（事項の下の見出しを項にしない）、勘定＝`HIER` の先頭が 1 桁、会計＝`HIER` の先頭が 2 桁で名称が MOF の特別会計名に一致するもの。**組織は使わない**ので、一般会計は所管の範囲で項名を探す（同名が複数の組織にあれば複数候補）。明細表だけの source は、同じファミリーでこの木に付ける。
4. **総表も TOC もない明細表だけの source（`hierarchy = position_detail`）:** 自分の明細表の行の並びから、同様に木を作る（項＝`CODE3` の次が `DETAIL`、勘定＝`CODE1`、会計＝`CODE2` の 2 桁で特別会計名に一致）。
- 会計の種類（一般／特別）と所管・特別会計は、その source の最初の明細表の `CONTEXT`（`NN 〇〇所管`／`NNNN 〇〇特別会計`）から取る。`CONTEXT` がなければ対象外（`no_context`）。
- 位置による規則は、TOC を正解として評価した（項: 取りこぼし 0〜2・余分約 2〜3%、勘定・会計: 完全一致。組織の規則は余分が多く不採用）。
5. **目次から漏れた項を総表から補う（`hierarchy = toc_total`）:** 目次が項の見出しを落としている書がある（目的税を財源にした繰入の項。例: 経済産業省 石油石炭税財源燃料安定供給対策及エネルギー需給構造高度化対策費エネルギー対策特別会計へ繰入、環境省・文部科学省の電源開発促進税財源の繰入、警察庁 交通反則者納金財源の繰入、農林水産省 097。明細表では額が空欄で、総表に額がある）。総表の項の見出しの形の行のうち、目次に無く、総表の小計の構造で項になるものを、総表で直前にある目次の項の後ろに足す。所属（所管・組織・会計・勘定）は直前の項から取り、頁（`request_page`）は総表の `明細書頁数`（目次の頁と同じ紙面の印字）。目次がその項の事項を前の項の下に置いているとき（総表で補った項の範囲にある事項名と同じ名前）は、事項を補った項に付け替える。各年度 7〜13 項（FY2026 は 11 項で、すべて MOF の項に対応）。実装は `supplementTocTree`。

**総表の小計の構造**（`totalTableKouHeads`）: 総表の項の行の額は、次の項までの事項の額の合計（小計）で、事項の下の見出し（`CODE3` の次が `DETAIL` の形をとるもの。例: 人事院の「026 諸外国との人事交流及び意見交換に要する経費」、FY2026 環境省 復興特会の「031 帰還困難区域等における鳥獣捕獲等緊急対策事業」）は項の小計の途中にある。そこで、目次に無い項の見出しの形の行は、直前の項の額がその項からこの行までの事項の額の合計（間の `CODE3` は飛ばす）に等しいときだけ項とする。目次のある書では、さらに、この行の額が次の `CODE3` までの事項の額の合計に等しいこと。`TOTAL`・`HIER` の行で直前の項は切れる。額の空欄があれば項にしない。

**組織と同名の項:** 衆議院・会計検査院のように組織と項が同じ名前の機関は、総表で組織の行（組織計）の直後に同じコード・名前の項の行が続く。M1 で項の額を総表から取るとき、組織の行は候補にしない（以前は組織計を項の額にしていた。衆議院 FY2026 は施設費・予備経費の 22.9 億円多かった）。

| ファイル | 内容 |
|---|---|
| `m0-entities.csv` | 主体の対応（`request_source`, `level`, `request_code_name`, `request_name`, `mof_key`, `status`, `reason`） |
| `m1-kou.csv` | 項。概算要求側（`request_source`, `toc_kou_idx`, `request_code3`, `request_name`, `request_page`）、MOF 側（`mof_row`, `mof_name`）、`candidate_count`, `status`, `reason`, 診断の金額（`request_amount`, `mof_amount`, `amount_diff`）、`request_scope`, `hierarchy` |
| `m2-jikou.csv` | 事項。`request_no`, `request_code`（`NN-NN`）, `mof_kou_row`, `mof_jikou_row`, `class_code_agrees`（後半 `NN` が主要経費別分類コードと一致）ほか |
| `m3-moku.csv` | 目（集約後）。`code_main_purpose`, `code_x`, `code_item`, `request_rows`, `request_sum`, `mof_kou_row`, `mof_moku_row`, `mof_amount`, `amount_diff` ほか |
| `unmatched-mof-{kou,jikou,moku}.csv` | 概算要求側のどの行にも対応づかなかった MOF の行。`reason`（`no_request_row`／`kou_matched_no_request_row`／`kou_not_matched`）と `ministry`, `organization`, `special_account`, `sub_account` |
| `sets.csv` | 文書セットで付いた組（`toc_source`, `attached_source`） |
| `request-no-toc.csv` | 木を作れなかった source の行（`OUT_OF_SCOPE`／`no_toc`）。現在は 0 行 |
| `summary.json` | 層ごとの `status` の件数、MOF の網羅、概算要求側の自己整合、入力の SHA-256 |

`status`: `MATCHED`（MOF の候補が 1 つ）、`AMBIGUOUS`（2 つ以上。候補ごとに 1 行）、`NO_CANDIDATE`（名称が一致する候補なし）、`PARENT_UNMATCHED`（上位が一意に対応せず探していない）、`OUT_OF_SCOPE`（`no_context` など）、`NEAR_NAME`（候補なしの項と、どの項にも対応していない MOF の項で、同じ所属・名前が近い・金額 5% 以内で 1 対 1 のもの。MATCHED には数えない）、`ZERO_AMOUNT`（額0の項。下記）。MOF の行の id は `{表}:{行番号}`（例 `kou-general:37`、行番号は CSV のデータ行の 1 始まり）。

**項名の対応表（`KOU_RENAMES`、`reason` = `kou_renamed`）**: 名前で候補が見つからない一般会計の項に、所管|組織|項名の完全一致で、予算書の項名を対応させる。原文と予算書の目で確かめた組だけを入れる。
- FY2023 のこども家庭庁（2023 年 4 月発足）。概算要求（2022 年 8 月）が仮の項名で、予算書で確定した。
  - 改称: 保育等対策費 → 保育対策費、国立児童自立支援施設施設整備費 → 国立児童自立支援施設整備費、児童福祉施設整備費 → 児童福祉施設等整備費
  - 統合（2 つの要求の項が 1 つの予算の項に）: 国立児童自立支援施設費 ＋ 同 運営費 → 国立児童自立支援施設、こども家庭推進費 ＋ こども家庭調査研究等推進費 → こども政策推進費（調査研究の 2 つの目が、予算書ではこども政策推進費にある）
  - 額は一致しない。保育等対策費の目の就学前教育・保育施設整備交付金（要求 333 億）は、予算書では児童福祉施設等整備費（295 億）にある。

**額0の項（`ZERO_AMOUNT`）**: 総表で前年度予算額・概算要求額がともに 0 と印字された項（空欄は含めない）。要求書は額のない科目も項の行として載せる。
- 候補がないものは、名前が見つからないのではなく額のない科目なので、`NO_CANDIDATE` と分けて `ZERO_AMOUNT`（`zero_prev_and_request`）とする。
- 同じ MOF の項に額のある項も対応しているときは、額0の項の対応を外して `ZERO_AMOUNT`（`zero_duplicate_of_nonzero`）とする。同名の額0の項が別の所属にあるときに起きる（例: 厚生労働調査研究等推進費）。
- 額0の項だけが対応する MOF の項は、対応のまま残す。MOF の予算書にも額 0 の項があり（独立行政法人の施設整備費など）、また要求が 0 で編成で額が付く項がある（例: FY2026 の原子力損害賠償支援資金へ繰入）。

## 限界と注意
- 概算要求側に PDF が存在しないため対応づかない項がある: 日本学術会議（FY2024・FY2025。内閣府の掲載ページで「事項要求」とされ、金額つきの要求書がない）、サイバー通信情報監理委員会（FY2026。公開されているのは令和9年度の概算要求書のみ）。
- 一致しなかった行の大半は、MOF の同じ範囲に名称がないもの（概算要求の項目が予算案で統合・改称・新設された等）。全角／半角の違いは幅の統一で一致にしている。
- FY2024 の法務省・金融庁の PDF は文字層がなく（描画パス型）、概算要求側が取れていないため、突合に載っていない。
- 同じ MOF の行が複数の概算要求の source から対応づくことがある（電源開発促進勘定を複数の省庁の PDF が載せる等）。
- 概算要求の目を MOF の目に対応づけたあと、集約した合計と MOF の金額が一致する割合は約 4 割。概算要求と予算書の時点の違いによる。

FY2023（令和5年度）× MOF 2023（提出時）: 項 1,016 件対応づき（曖昧 12、対象外 3、親未対応 5、候補なし 68）、事項 1,558（候補なし 70、親未対応 94）、目（集約後）7,246（候補なし 439、親未対応 280）。MOF の行のうち対応づいた割合は、項 89.9%（938／1,043）、事項 86.7%（1,430／1,650）、目 84.1%（6,771／8,046）。FY2024 以降より低いのは、法務省の PDF（文字層なし）を入力に含まない（MOF 側の未対応の項 105 のうち 35 が法務省）ことと、こども家庭庁の発足年度で複数候補（曖昧 12）があることによる。
