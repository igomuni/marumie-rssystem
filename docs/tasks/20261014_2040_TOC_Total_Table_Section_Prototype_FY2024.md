# TOC・総表から明細表の項を特定する別方式（FY2024）

状態：development prototype。既存CSV間の照合と原本6例の抜き取り確認まで実行。GTではなく、精度評価・MOF突合・正式採用は未実施。FY2025の保留中のGT作成・K2評価は実行していない。

## 問題と別方式

明細表の直前や前5ページに項の見出しを探す方式は、項から離れた事項、内訳のコード行、項の見出しが窓の外にある場合に対応しにくい。ここではTOCの明示された「（項）」を起点に、総表の事項を経由して明細表の事項を結ぶ。

1. 同一PDFのTOCで組織・会計・勘定等の文脈と「（項）」を読む。
2. 項コード・項名・印刷ページ番号で総表の項に一意対応させる。組織と項が同名なら保留。
3. 要求番号・事項コード・事項名でTOC、総表、明細表の事項を一意に対応させる。
4. TOCの事項から読んだ親項と、総表の事項から追ったTOC確認済みの親項が、同一TOC行を指すことを要求する。
5. TOCと総表の事項ページ番号が一致し、明細表にも番号があるなら矛盾しないことを要求する。

名称は空白除去、ハイフンの異体字統一のみ。名称の曖昧一致、金額による選定、別PDFの推測対応はしない。MOFの項名や旧K2の予測は一切読まない。

## 実装・再現

```bash
python3 scripts/research/resolve-detail-sections-via-toc-total.py
```

入力：`data/work/budget-request-csv/2024/{toc,total-table,detail-table}/sources/*.csv`、TOCの`entry-provenance.csv`と`sources.csv`。

既定出力：`/private/tmp/toc-total-section-prototype-2024/`。

- `section-candidates.csv`：明細表DETAIL全行、候補の項、組織・会計等の文脈、保留理由、TOC entry IDと物理ページ、総表行・物理ページ、明細表行・物理ページ。
- `summary.json`：集計、入力全ファイルのSHA-256、source別件数。
- `visual-review-cases.json`：固定の6例と原本PDF・物理ページ。
- `review/case-1.png`〜`case-6.png`：TOC・総表・明細表を並べた目視確認画像（別途Popplerで描画）。

元データ、既存parser、GTは変更しない。候補は`CANDIDATE_CSV_CONSISTENT`であり、matchedやGTへ昇格させない。

## 全明細表DETAILの処理結果

| 状態 | 件数 |
|---|---:|
| CSV間で整合する項候補 | 1,427 |
| 同一sourceの総表なし | 158 |
| TOCで要求番号・コード・名称が一致する事項なし | 48 |
| 項を一意に識別できない | 6 |
| TOCと総表のページ番号が矛盾 | 2 |
| 合計 | 1,641 |

候補coverageは86.96%。これは正解率ではない。候補1,427件のうち明細ページ番号も一致するのが1,363件、明細ページ番号が取得できないのが64件。

ページ番号は頁ラベル中に数字群が1つだけある場合の数字を比較する。府省・勘定の略号や括弧はこの比較で検証していない。同一sourceと項の同一TOC行による制約はあるが、略号の食い違いを許してよいかは正式採用前の課題。

6件の「項を一意に識別できない」は会計検査院・衆議院で組織と項のコード・名称・ページが同一であるため。元の探索ではこれらの事項も親項候補が出たが、試作では総表行を区別できない場合に保留するよう制約した。

## 原本画像の抜き取り確認

予測を見た同じ担当者によるillustrative spot checkであり、blind annotationや独立GTではない。固定した6例すべてについて、TOC・総表・明細表の画像上で事項と項の対応を確認できた。詳細ページに前の項がなくても、TOCと総表から項をたどれる。

| source | 要求番号 | 確認した項 | TOC / 総表 / 明細表の物理ページ |
|---|---:|---|---|
| 国交省 `001630995` | 87 | 376 離島振興事業費 | 5 / 16 / 412 |
| 国交省 `001630995` | 127 | 602 独立行政法人自動車技術総合機構施設整備費 | 5 / 17 / 443 |
| 環境省 `000157010` | 41 | 510 原子力規制委員会共通費 | 4 / 18 / 164 |
| 経産省 `ippan_o` | 1 | 010 経済産業本省共通費 | 3 / 5 / 9 |
| 人事院 `900024096` | 1 | 010 人事院 | 3 / 5 / 7 |
| 環境省 `000157012` | 1 | 010 燃料安定供給対策費 | 3 / 5 / 7 |

環境省`000157010`の総表には事項の下に3桁内訳コードがあるが、TOCの（項）を参照するため内訳を親項に採用していない。エネルギー需給勘定の例は、明細表CSVの頁が空でも要求番号・事項コード・名称の一意対応で候補を出せる。

## 検証

- 入力全ファイルのSHA-256を実行前後で確認し、変更なし。
- 同一入力で2回実行し、3出力ファイルがバイト単位で一致。
- 全1,641 DETAILを1行ずつ出力し、source＋明細表row_indexの重複なし。
- 合成データで、有効な連結、TOC事項の重複、総表事項の重複、明細ページ矛盾、同一sourceの総表不在、同名の組織と項の6ケースを検証。無効・曖昧なケースに項候補が付かないことを確認。
- 出力hash：`section-candidates.csv` は `94306354bae037b5fd3f72ac7bb839d3fc5ed59699ee6ff6509b68e03ec6ce1a`。

## 次の判断に必要なこと

この方式は、明細表の短い画像窓から階層を推定する依存を減らせる。今後の中心候補として検討できるが、86.96%や6例一致だけで正式採用はしない。

1. 既に観察した2024年はdevelopmentとし、独立な対象で項の正しさを検証する。
2. GTの証拠範囲は「TOC＋総表＋必要な明細表ページ」として、旧W=5契約とは別に定義する。
3. 保留214件は、別PDF対応、TOC抽出、同名の組織と項、頁体系に分けて扱う。曖昧一致で一括解消しない。
4. MOF候補を絞る評価は、この方式の項検証と分離する。旧FY2025 candidate/GT/事前登録を更新したり再利用したconfirmatory評価にしない。
