# MOF（項・事項・目）× 概算要求（TOC・総表・明細表）突合の再設計案

状態: **§5 の 5 点はユーザーが確定済み**（下記）。過去の突合（J1+K2、`detail-table-mof-match`、#462 など）は新しい設計では使わないが、削除はせず残す。実装・実行はこれから（最初は記述）。

## 1. 範囲
- MOF 側: 2024・2025 の一般会計・特別会計。`tests/fixtures/mof-archive-csv/{2024,2025,2025_teishutsu}/` の項（kou）・事項（jikou）・目（moku）。
- 概算要求側: FY2024（令和6年度）・FY2025（令和7年度）の TOC・総表・明細表（`data/work/budget-request-csv/{2024,2025}/{toc,total-table,detail-table}/`）。
- 目的: 概算要求の各階層の行を、MOF の対応する階層の行に、**根拠を示して**対応づける。層ごとに独立に評価し、上位の結果を使って下位を補正しない。

## 3. 設計（層ごとに独立）
| 層 | 概算要求側 | MOF 側 | 照合の根拠（案） |
|---|---|---|---|
| M0 主体 | TOC の組織、明細表の `CONTEXT`、総表の `HIER` | 所管・組織・特別会計・勘定 | 名称の exact。対応表を作り、片側だけの主体を全件列挙する |
| M1 項 | TOC の項、総表／明細表の `CODE3` | kou | 主体が M0 で定まった範囲で、項コードと項名 |
| M2 事項 | 総表／明細表の `DETAIL` | jikou | M1 で確定した項の中で、事項名と `NN‑NN` の後半＝主要経費別分類コード |
| M3 目 | 明細表の `CODE_5_4_2_4`（事項ごとに現れる） | moku（キーは項×目のコードで、事項の列はない） | M1 で確定した**項の中で**、概算要求の目を（主要経費＋目的別・使途別・目別・目名）で集約し、MOF の目に多対一で対応づける |

- **M3 の注意（ユーザーの指摘）:** MOF の目は、項内の複数の事項にまたがる目の**合計**になり得る。事項ごとではなく項ごとに探し、概算要求の目の行を集約して対応づける。MOF 側は経済性質別コードも持つが、概算要求のコードには現れないため、同じ組で経済性質別だけ違う MOF の行があれば複数候補として記録し、絞らない。出力には、集約した概算要求の行数と行の位置の一覧を持たせる。
- **根拠の使い方:** 名称は exact（正規化・部分一致をしない）、コードは裏づけ。**金額は選択に使わず**、一致後の整合の診断としてだけ使う。M3 では、集約した概算要求の合計と MOF の目の金額を比べる（`request_sum`・`mof_amount`・`diff`）。版が違うので不一致は失敗とせず、M3 が正しく結べているかの手がかりとして報告する。MOF の金額は版により違う（提出時と成立後）ため、金額一致を必須にしない。
- **出力:** 層ごとに、概算要求側の行 → MOF 側の行の対応表（`status` つき: 一意に対応／候補なし／複数候補／対象外）。複数候補は、無理に絞らず複数のまま記録する。
- **評価:** 正解データ（人手）は作らない。構造の自己整合で見る（一意性、M2 で選んだ事項の項が M1 の項と一致するか、上位が未対応なのに下位が対応していないか）。件数は報告のみで、成功基準にしない。

## 4. 進め方（前と同じ作法）
1. 記述（inventory）: 概算要求と MOF のコード体系の関係（`CODE3` と項コード、`NN‑NN` と主要経費コード、`CODE_5_4_2_4` と目のコード）を、規則を置かずに実例と件数で凍結する。
2. 層ごとに契約を書いて commit → 実装 → 実行 → 結果を報告。M0→M1→M2→M3 の順。層をまたぐ補正はしない。
3. 過去の突合の削除（§5-5）。

## 5. 確定事項（ユーザー）
1. **FY2025 の MOF の版:** 提出時・成立後を**それぞれ**別に突合する（`mof_version` の列で区別）。FY2024 は版が 1 つ。
2. **層の範囲:** M0〜M3 を**一度に**契約する（記述の結果を見て規則を置く前に、契約の本文は M0〜M3 すべてを対象にする）。
3. **特別会計:** 一般会計と**同時に**含める。
4. **金額:** 選択には**使わない**（診断のみ）。
5. **過去の突合:** **残す**（削除しない）。

## 6. 記述の段階で見えていること（規則ではない）
- 明細表の `CODE3` は位置により意味が違う（組織／項／細区分）。例: `010 文部科学本省`（組織）→ `010 文部科学本省共通費`（項）→ `001 既定定員に伴う経費`（細区分）。
- 目のコードは 2 つの形がある: 一般会計の例 `95016‑2111‑02‑0000`（5‑4‑2‑4 桁）、特別会計の例 `95016‑ 5‑14‑9390`。MOF の目の列（主要経費・目的別・経済性質別・使途別・目別）との対応は、記述で確かめる。
