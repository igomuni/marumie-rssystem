# pid=4「情報システムの整備」の予算あり支出なし・予備費等マイナスの調査

## 結論

いずれもマルミエ側のデータ結合バグではなく、**RS（行政事業レビュー）の公式CSVがそう報告している**。原因は同一で、pid=4が「デジタル庁のIT関連予算を一旦プールし、他の事業へ予算を移替える」役割の事業だから。

## 調査1: pid=4は予算あり・支出なし、関連事業群は予算なし・支出あり

`data/year_2025/5-2_RS_2025_支出先_支出ブロックのつながり.csv` の pid=4 の行:

```text
ブロックA: デジタル庁 → 役割「デジタル庁システムの整備・運用」 → 予算の配分
ブロックB: 各府省庁(25先) → 役割「各府省システムの整備・運用」 → 予算の移替
```

両ブロックとも金額欄（支出先名・金額等）は空。つまりRS自身が「この予算は他事業へ配分・移替した」とだけ宣言し、**移替先ごとの内訳（金額・pid）は公開していない**。RS_2024（前年度分）でも同じ構造を確認済み。

移替先は「情報通信技術調達等適正・効率化推進費」を事業名に含む個別システム事業（pid=11 第一期政府共通プラットフォーム、12 電子決裁システム(EASY)、13 共通情報検索システム 等、デジタル庁だけで約20事業）で、これらは自分の予算行（2-1/2-2 CSV）をほぼ持たず（`budgetAmount≈0`）、実際の支出のみ自分のpidで計上している。

`予算の配分/予算の移替` という同じ仕組みは、地方交付金型の事業（社会資本整備総合交付金・防災安全交付金・物価高騰対応重点支援地方創生臨時交付金 等、計20事業前後）にも見られる、RS側の一般的な報告パターン。

**pid⇔pidの対応表がRS側に存在しないため、マルミエのデータでも自動で紐づけることはできない。**

## 調査2: 予算・執行のマイナス（一般 予備費等1 -5,097億円 会計一般会計 勘定- 項- 目-）

`data/year_2025/2-2_RS_2025_予算・執行_予算種別・歳出予算項目.csv` の pid=4 行:

```text
予算年度2024, 会計区分=一般会計, 予算種別=予備費等1, 勘定/項/目=空, 予算額=-509,690,849,950
```

同ファイルの `2-1_RS_2025_予算・執行_サマリ.csv`（pid=4・予算年度2024）:

```text
当初予算(合計)      480,327,293,000
補正予算(合計)      205,412,304,000
予備費等(合計)      -509,690,849,950
前年度からの繰越し(合計)  93,383,296,000
計(歳出予算現額合計)    269,432,043,050  ← アプリの budgetAmount と一致
```

`scripts/generate-sankey-svg-data.ts` はこの `計(歳出予算現額合計)` をそのまま `budgetAmount` として使っており（218-222行目）、RS公式の集計式をそのまま反映している。マイナスの `予備費等1` は「予備費として一旦計上された予算のうち、他事業へ移替えて減額した分」を表す会計処理で、調査1のブロックB（予算の移替）と対応する。RS_2024（予算年度2022・2023）でも同じ符号・同程度の規模で継続しており、単年度の異常値ではない。

## 対応方針

- コード上の不具合ではないため、マルミエ側のバグ修正は不要。
- 移替先の内訳がRS非公開である以上、pid=4と個別システム事業を機械的に対応づけるのは不可能（対応表を作るなら手作業の名寄せになる）。
- UIで「なぜ予算と支出が食い違うのか」が伝わらないのは事実なので、`/subcontracts/4` 等でこのパターン（`予算の配分`/`予算の移替`＝ブロックの役割）が出た場合に注記を出す改善は別途検討可能（今回は調査のみで実装はしていない）。
