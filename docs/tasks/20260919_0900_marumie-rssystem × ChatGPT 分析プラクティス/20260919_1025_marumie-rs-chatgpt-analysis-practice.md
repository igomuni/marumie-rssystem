# marumie-rssystem × ChatGPT 分析プラクティス

## 概要

marumie-rssystemのデータをChatGPTとの対話で探索・分析する過程で得られた実践的なワークフローの記録。

## 今回確認できた流れ

1. 公開UIを基準に分析を始めた。
2. ChatGPT側からUIを直接十分に確認・操作することには制約があった。
3. そこで `integrated-sankey` APIのデータを直接利用する方針に切り替えた。
4. ChatGPT側からAPIを直接取得する経路にも制約があった。
5. ユーザー側でAPIレスポンスや財務省一次データをローカルへダウンロードした。
6. JSON・XML・CSVをZIP圧縮してチャットへアップロードした。
7. アップロードされた実データを共通コンテキストとして、件数比較・構造確認・仮説検証を対話的に進められた。

## 分析で見えてきたこと

- `integrated-sankey?year=2025` のMOF項相当 `sections` は1,056件。
- `mof-kou-2024` は当初予算1,054件、補正予算997件、決算1,270件。
- 補正予算では「○○外N目」のような目の集約表現が多数存在する一方、当初予算では同様の表現が見られなかった。
- 「前年度額0 → 本年度額あり」だけでは、本当に新規の政策・事業なのかを確定できない。
- MOFの「事項」データには本年度額・前年度額・増減額・説明文などがあり、新規候補の意味を調べる手掛かりになる。
- 財務省の一次CSVには「目」単位の本年度額・前年度額・比較増減額などがあり、加工済みJSONより深い検証が可能。

## MOFデータの見方

現時点では「項・事項・目」を単純な階層だと決め打ちせず、それぞれ異なる一次データ／加工データを突き合わせながら関係を確認するのが安全。

- 項: 予算構造の骨格
- 事項: 予算目的・説明と年度比較を確認するための情報
- 目: より細かな費目と金額を確認するための情報

## 得られたプラクティス

重要だったのは、ChatGPTから対象システムへ直接アクセスできるかどうかではなく、分析対象データを再現可能な形でセッションへ持ち込むことだった。

`システム/API → ローカル取得 → 圧縮 → チャットへアップロード → 対話的分析`

という単純なループでも、UIだけを眺める場合より深い探索が可能になった。

## 後で検討する事項

この一連のデータ取得・圧縮・アップロード用データ作成を「分析パッケージ」として自動化する案を別途検討する。
