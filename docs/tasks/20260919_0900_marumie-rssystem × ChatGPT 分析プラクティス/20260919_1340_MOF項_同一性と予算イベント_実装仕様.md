# まるみえRS：MOF「項」同一性・予算イベント 実装仕様

## 1. 目的
当初予算・補正予算・決算を横断して「項」を正しく追跡し、単純な項コード一致では表現できない以下を扱えるようにする。

- 補正による項の新設・増減
- 前年度からの繰越
- 予算決定後の移替
- 行政・組織移管
- 同名項の複数所管への展開
- 項コード変更
- 一般会計・特別会計間の関係

## 2. 基本原則
### 2.1 `項コード` を永続IDにしない
`項コード` は原典上の識別子として保存するが、年度・予算種別を横断する主キーには使用しない。

### 2.2 原典レコードと論理的同一性を分離する
以下を別エンティティとする。

- `BudgetItemRecord`: 原典に存在する1つの項レコード
- `CanonicalItem`: 年度・予算種別・所管変更を超えて「実質的に同じ項」を束ねる論理エンティティ
- `BudgetEvent`: 補正・繰越・移替等の変化
- `ItemRelation`: 項と項の関係

## 4. 同一性判定
### 4.1 自動一致 Level A
以下が一致する場合は原則同一候補。

- 会計
- 所管
- 組織
- 正規化項名

項コードが異なっても同一候補とする。

### 4.2 自動一致 Level B
項名が一致し、所管または組織だけが異なる場合は `same_item` と断定せず、次を検査する。

1. 決算の `予算決定後移替増△減額`
2. 財務省公式移替表
3. 前年度繰越額
4. 行政組織移管情報
5. 金額の source / destination 一致

一致すれば `transferred` / `administrative_transfer` / `carried_over` を付与する。

### 4.3 名称変更
同一会計・所管・組織・項コードで名称だけ異なる場合は `renamed` 候補とする。

### 4.4 禁止事項
- `itemCode` だけで同一項と判定しない。
- `itemName` だけで移替額を推定しない。
- 決算のみ存在する項を自動的に「新設」としない。
- 決算の受け皿側 `歳出予算額` を移替額と解釈しない。

## 5. 金額検証
一般会計決算では検証可能な場合、以下をチェックする。

```text
歳出予算額
+ 前年度繰越額
+ 予備費使用額
+ 予算総則による経費増額
+ 流用等増減額
+ 予算決定後移替増減額
= 歳出予算現額
```

```text
歳出予算現額
= 支出済歳出額
+ 翌年度繰越額
+ 不用額
```

不一致の場合は `validation_error` として記録し、UIで警告可能にする。

## 6. ETL
### Phase 1: Raw import
原典CSV/JSON/XMLを加工せず staging table に投入。

### Phase 2: Normalize
- 金額を円へ統一
- 全角/半角・空白を正規化
- 項名正規化文字列を生成
- 会計・所管・組織をマスタ化

### Phase 3: Candidate matching
当初→補正→決算の候補ペアを生成。

優先順：
1. 同一会計＋所管＋組織＋項名
2. 同一会計＋所管＋組織＋項コード
3. 同一項名＋別所管
4. 前年度同名項

### Phase 4: Relation detection
移替・繰越・補正・名称変更・コード変更を判定。

### Phase 5: Canonicalization
確度の高い関係を `CanonicalItem` に束ねる。

## 7. API案
### GET `/api/budget/items/:canonicalId/timeline`
返却例：
```json
{
  "canonicalItemId": "ci_xxx",
  "name": "科学技術イノベーション創造推進費",
  "records": [],
  "events": [],
  "relations": []
}
```

### GET `/api/budget/items/:recordId/relations`
項の移替元・移替先・繰越元等を返す。

### GET `/api/budget/compare`
パラメータ：
- `from=initial`
- `to=settlement`
- `fiscalYear=2024`
- `mode=raw|canonical`

`raw` は原典項数、`canonical` は同一性解決後の件数を返す。

## 8. UI仕様
項詳細に「予算の履歴」セクションを追加する。

表示例：
```text
令和6年度
当初予算       4803.3億円
   ↓ 補正 +2054.1億円
補正後         6857.4億円
   ↓ 予算総則第15条による移替
決算
 ├ デジタル庁 残額
 ├ 総務省      移替受入
 ├ 法務省      移替受入
 └ ...
```

バッジ：
- `当初`
- `補正新設`
- `補正増額`
- `前年度繰越`
- `移替元`
- `移替先`
- `行政移管`
- `コード変更`
- `名称変更`

## 9. サンキーへの反映
既存の府省庁→局・庁→事業→支出先とは別に、予算推移モードを設ける。

```text
当初項
  ↓ 補正
補正後項
  ↓ 移替 / 繰越 / 行政移管
決算項
  ↓
支出済 / 翌年度繰越 / 不用
```

同一項が複数所管へ展開する場合は、CanonicalItemを論理的な起点として複数の決算レコードへエッジを張る。

## 10. フィルター
追加候補：
- 予算種別：当初 / 補正 / 決算
- 変化種別：新設 / 増額 / 減額 / 移替 / 繰越 / 行政移管
- 原予算年度
- canonical/raw 切替
- 移替あり/なし
- 前年度繰越あり/なし

## 11. 実装順序
### P0
1. `BudgetItemRecord` の統一schema
2. 金額単位の円統一
3. raw ID と canonical ID の分離
4. 2024年度254項分類CSVをfixtureとして導入

### P2

## 12. テスト要件
最低限以下をfixture化する。

1. 情報通信技術調達等適正・効率化推進費 — 多所管展開
2. 科学技術イノベーション創造推進費 — 移替＋前年度繰越
3. 水道施設災害復旧事業費 — 前年度繰越＋行政移管
4. 生活基盤施設耐震化等対策費 — 前年度繰越＋行政移管
5. 東日本大震災復興特別会計 — 項コード変更
6. 半導体・人工知能関連技術基盤強化対策費 — 補正新設
7. 防衛力強化資金へ繰入 — 補正新設・名称差ケース

各ケースで以下をassertする。
- raw record数
- canonical item数
- relation type
- event amount
- 金額恒等式
- source provenance
