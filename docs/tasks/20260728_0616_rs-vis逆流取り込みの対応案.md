## 2. 対応案（推奨）

**1本の巨大 PR にせず、衝突リスク順に3本へ分割する。** 全体を1PRにすると sankey-svg の設計衝突がボトルネックになり、独立している `/project-bubble` まで止まる。

### PR-1: 独立追加物（衝突ゼロ）

対象: `app/project-bubble/`、`client/components/ProjectMap/`、`app/lib/project-map*.ts`、`app/api/project-map`・`policy-summary`・`execution-history`、`app/lib/policy-evaluation.ts`、`scripts/*.py`・分析スクリプト群、`docs/*.md`（`policy-decision-scoring.md`・`quality-evaluation-benchmark.md` 等）、`data/exports/*.csv`、新規データ `.gz`、`package.json`・`.gitignore`・`scripts/decompress-data.sh`（自動マージ済み）

手順: cherry-pick 後に衝突6ファイルを `git checkout --ours` で一旦戻し、残りをコミット。`npm run build` と `/project-bubble` の単独動作を確認。

注意点:

- `rs2025-project-outcomes.json.gz` は 8.4MB。**関数バンドル 250MB 問題**（`docs/tasks/20260718_1421_*`）の設計ルールに照らして、`/project-bubble` と `/api/project-map` のトレースに巻き込まれないか `check-traces` で確認する
- `scripts/*.py` は Python 依存（embedding・UMAP・KMeans）。marumie 側に Python パイプラインの運用手順がないため `docs/data-pipeline-guide.md` への追記が要る

### PR-2: 品質スコア再設計の取り込み（UI側）

対象: `app/quality/page.tsx`、`app/api/quality-scores/route.ts`

> **実施時に変更**: `scripts/score-project-quality-ai.py`・`public/data/project-quality-scores-2025.json.gz`・`docs/quality-scoring-guide.md` は PR-1 へ移した（下記「実施記録」参照）。PR-2 は `/quality` の UI 再設計とスコアAPIのみ。

解決方針: **rs-vis 側を基本ベースに採り、marumie 固有の資産（`client/components/quality/*`・`useScoreDetailData`・`SidePanelChrome`・`/sankey-svg` からのダイアログ起動）を上に載せ直す**。rs-vis は marumie の #245〜#262 を知らずに書かれているため、単純な「どちらか採用」では marumie 側の連携が壊れる。

宿題の解消: memory の「2024データは旧世代で再生成が宿題」がここに直結する。`project-quality-scores-2024.json.gz` は rs-vis でも未再生成（626KB）なので、**本 PR では 2025 のみ新世代とし、2024 再生成は別タスク**として明示的に切り出す（年度切替で採点世代が混在する旨を UI かドキュメントに注記）。

## 3. rs-vis への逆流（取り込み後）

これまで通り「marumie の状態を rs-vis へ反映」する片方向コピー運用を踏襲する。取り込み後は rs-vis 由来の変更が marumie に入っているので、差分は marumie 独自分（#239〜#290：再委託UI刷新、AIチャットBYOK、探索履歴、支出先名寄せ、間接経費ノード等）＋ PR-2/PR-3 のマージ結果になる。

## 5. 実施記録 — PR-1（2026-07-28）

ブランチ `feat/rsvis-project-bubble-and-policy-eval`。当初案から3点、実装中に境界を動かした。

1. **`public/data/project-quality-scores-2025.json.gz` と `scripts/score-project-quality-ai.py` を PR-1 に含めた**。新API3本と `/project-bubble` は `designClarity`・`evidenceReadiness`・`budgetProportionality`・`necessity`・`policyCategory`・`policyFindings` を読むが、これらは**新世代スコアにしか無い**（旧世代には axis1-5・totalScore まで）。型は全て optional なので `tsc` は通るが、旧データのままだとバブルの推奨判断・大きさが全件 null になり機能しない。生成スクリプトもデータと揃えて入れ、`docs/quality-scoring-guide.md` も同伴させた。旧 `/quality` ページは新データでも動く（読む列は全て残っており、消えた列 `cnVerifiedCount` は非AI版スクリプトとコメントでしか使われていない）ため、UI 再設計を PR-2 に残す境界は保てる。
2. **`components/navigation/PageNavMenu.tsx` を PR-1 に含めた**。`/project-bubble` が import しており、外すと PR-1 単体でビルドが通らない。PR-3 は「既存3ページへの配線」だけになり、設計衝突の範囲がむしろ絞れた。
3. **`components/filters/MinMaxInput.tsx`**: 当初は rs-vis 側の差分（`〜`→`~` の1文字置換）を表記の後退と見て取り込まなかったが、**「rs-vis はそのままの形を維持して取り込む」方針に切り替えたため取り込んだ**（2026-07-28）。

追加で1点修正した。**`rs{YEAR}-project-outcomes.json.gz`（8.4MB）を `data/server` の同期対象から除外**（`scripts/decompress-data.sh`）。AI採点スクリプトの入力専用でサーバ関数からは一切読まないが、`public/data/*.json.gz` を一括コピーする作りのため全30関数のバンドルに乗っていた。除外で関数あたり 45.3MB → 37.2MB。

（PR #291 は当初レビュー対応の修正コミットを含んでいたが、上記の方針転換により `fix/policy-eval-corrections` ブランチへ退避した。既知不具合の一覧は `20260728_0741_rs-vis由来の既知不具合18件の棚卸し.md`。）
