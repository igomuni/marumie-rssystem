# 科目別内訳ページの行単位スクレイピング実装

`/mof-kou-moku`（[20260826_0809](20260826_0809_項の単独事項構造による紐づけ拡張の調査.md)で新設）の出典リンクを、`/mof-jikou`と同じ行単位の正確なページリンクにした記録。

## 発端

「事項と同じようにURLリンクを一覧に付けたい」との要望を受け、まず`/data`配下の既存キャッシュを調査した。

## 調査 — 科目別内訳はWeb帳票としても公開されている

財務省の予算書DBは「〔組織別事項別内訳〕」（`/mof-jikou`がスクレイピング対象）と「科目別内訳」を**同じ帳票ツリーの並列文書**として公開している。両方とも同一の`documentId`（例: 一般会計当初予算=11001）の目次（`{documentId}menu.html`）にページリンクが列挙されており、XML内の`title_for_list`要素で判別できる：

```text
title_for_list = "〔組織別事項別内訳〕" → 事項別内訳（/mof-jikou が使用）
title_for_list = "科目別内訳"          → 科目別内訳（一般会計）
title_for_list = "歳入歳出予定額科目別表" → 科目別内訳相当（特別会計）
title_for_list = "収入支出予定額科目別表" → 科目別内訳相当（政府関係機関）
```

`/mof-jikou`のスクレイパ（`generate-mof-jikou-data.ts`）は目次の全リンクを無条件に取得してから`title_for_list`で絞り込むため、**科目別内訳のページも副産物として`data/download/mof_{年度}/xml/`に既にキャッシュされていた**（一般会計当初予算で94ページ、実測で確認）。このため一般会計は追加のネットワークアクセスなしにページ特定ができた。

## 実装

### 1. 共通ユーティリティの切り出し

`generate-mof-jikou-data.ts`に埋め込まれていたネットワーク取得・キャッシュ・XMLテーブル復元ロジック（`fetchText`/`extractXmlNames`/`parseTable`/`textAt`/`numberAt`/`splitRunningTitle`/`listTitle`等）を`scripts/mof-budget-xml.ts`に切り出し、両スクリプトで共用できるようにした。jikou側は`npm run validate-mof-jikou`（100項目）と全10年度の再生成で、リファクタ前後の出力が`generatedAt`以外バイト単位で完全一致することを確認済み。

### 2. 科目別内訳ページの行単位スキャン（`generate-mof-kou-moku-data.ts`）

表の列構成を実測で特定（一般会計・当初/暫定/補正で共通、複数所管で確認）:

```text
col1(colSub=1) = 項コード（項の行にのみ印字）
col1(colSub=2,3) = 主要経費等の合成コード（目の行。項に目が1件のみの場合はプレースホルダとして項の行にも同居）
col2 = 項名（項の行にのみ印字）
col3 = 目名（目の行にのみ印字）
```

`(項コード, 目名)` の組から出典XMLのURLを引けるマップを構築し、CSV由来の各`MOFKouMokuItem`の`sourceUrl`を帳票トップページのフォールバックから行単位のURLへ差し替える。金額等のデータそのものはCSVを正とし、XMLからは再抽出しない（スクレイピングは出典リンクの精度向上だけが目的）。

### つまずき: 同一行の複数セル連結によるバグ

項に目が1件しかない場合、同じ`(page,row)`に「項コード」（colSub=1）と「プレースホルダの合成コード」（colSub=2）の2セルが同居する。`textAt()`は同一列の複数セルを連結する仕様（本来は折り返し行の結合のため）のため、`"001" + "(95011-2129-‥)"` → `"001(95011-2129-‥)"`という文字列になり、項コード判定の正規表現`/^\d+$/`に失敗していた。**先頭セル（colSub=1）だけを見る**よう修正して解消（一致率97.9%→99.98%）。

もう1つ、CSVのプレースホルダ表現がレイアウトにより異なる問題があった（当初/暫定=`"(項名)"`、補正=空文字`""`）。両方をマップに登録することで対応。

## 結果

10年度すべてで**キャッシュのみから**（新規ネットワークアクセスなし、生成2.7秒）一般会計の行単位URL特定に成功。

```text
2017: 99.98%（8,424/8,426）
2018: 99.98%（9,214/9,216）
2019: 99.98%（8,799/8,801）
2020: 99.98%（10,797/10,799）
2021: 99.98%（9,205/9,207）
2022: 99.98%（9,738/9,740）
2023: 99.97%（9,602/9,605）
2024: 99.98%（9,594/9,596）
2025: 99.98%（9,828/9,830）
2026: 99.96%（10,385/10,389）
```

未一致は毎年ごく少数（国会予備経費など、CSVのプレースホルダが項名と異なる共通ラベルを使うケース）で、帳票トップページへのフォールバックのまま残す。

## 未対応（範囲外）

- **特別会計・政府関係機関**: 科目別内訳相当のページ（「歳入歳出予定額科目別表」等）は歳入・歳出が同一ページに混在する可能性があり、列構成も未検証。帳票トップページへのフォールバックのまま。
- **決算**: `title_for_list`が組織名になり事項別内訳と同じ判別方法が使えない（settlement特有の構造）。同様に未対応。

いずれも一般会計より優先度が低いと判断し今回は見送った。必要になれば同じ枠組み（`mof-budget-xml.ts`）を使って追加できる。
