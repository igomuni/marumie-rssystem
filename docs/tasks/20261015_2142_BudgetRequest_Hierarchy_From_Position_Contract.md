# 概算要求（TOC のない PDF）の階層を行の位置から決める規則の評価 — 契約

状態: 実行前に commit する。**TOC を持つ source（FY2025 55・FY2024 55）では TOC の見出しが正解になる**ことを使い、行の位置から階層を決める規則が TOC をどれだけ再現するかを数える（記述）。その結果を見てから、TOC のない source（内閣府・内閣官房など）にその規則を使うかを、ユーザーが決める。規則は下の 4 つに固定し、結果を見て増やさない。なお、規則 項-A だけは、契約を書く前に FY2025 で一度、非公式に数えた（975 件中 975 件が一致、余分 26）。

## 規則（総表の行の並びだけを見る。`row_type` は総表 CSV のもの）
- **項-A:** `CODE3` の次の行が `DETAIL` のとき、その `CODE3`（コード3桁と名称）を項とする。
- **組織-A:** `CODE3` の次の行が `CODE3` のとき、その `CODE3` を組織とする。
- **会計-A:** `HIER` の行のうち、先頭の数字が 2 桁のもの（`09 自動車安全`）を会計とする。
- **勘定-A:** `HIER` の行のうち、先頭の数字が 1 桁のもの（`1 自動車事故対策勘定`）を勘定とする。

## 評価（TOC を持ち、総表を持つ source ごと。FY2024・FY2025）
正解は TOC の `（項）`・`（組織）`・`（会計）`・`（勘定）` の見出し（コードと名称。幅の統一と空白除去をした名称）。規則ごとに、正解の集合と規則の集合を source ごとに比べ、一致（tp）、正解にあって規則にない（fn）、規則にあって正解にない（fp）の件数を合計する。fn・fp の例を記録する。
補足: TOC を持つ source のうち総表を持たないもの、総表の `HIER` を持たない一般会計の source は、該当する規則の評価から外す（件数を記録）。
