## 反映前に片付けること

### 1. `package.json` の依存3件

rs-vis に無い依存が増える。rs-vis 側で `npm install` が必要。

```text
react-markdown ^10.1.0    AIチャットのMarkdown描画
remark-gfm     ^4.0.1     同上
vitest         ^4.1.10    テスト（rs-vis では実行しないが devDependencies に入る）
```

`vitest` は `tests/` を除外する運用と噛み合わないので、**rsync 後に rs-vis の `package.json` から落とすか、そのまま入れるかを決める**。入れても実害はない（`npm run test` を叩かなければよい）が、`tests/` が無いのに vitest がある状態は説明が要る。

### 2. `scripts/check-function-traces.mjs` が rs-vis に無い

`package.json` の `check-traces` スクリプトが参照する。rsync でファイル自体は入るので問題ないが、**rs-vis でも関数バンドル 250MB の制約は同じ**なので、反映後に一度は回しておきたい。

### 3. 環境変数（rs-vis 側の Vercel 設定）

**`NEXT_PUBLIC_FEATURE_AI_CHAT` と `NEXT_PUBLIC_FEATURE_EXPLORATION_HISTORY` を設定しない。** 未設定＝UI が出ない。設定してしまうと公開先にAIチャットが露出する。

サーバ側の `OPENROUTER_API_KEY` 等も設定しない（BYOK 経路のみが残る）。

### 4. 既知不具合18件の扱い — **当てない（2026-08-11 決定）**

`origin/fix/policy-eval-corrections` に退避したままで、marumie にも rs-vis にも入っていない。**本反映では当てない**方針が決まった。

したがって rs-vis にも同じ不具合が入る。特に `percentileRank` の同点バグにより、`/quality`・`/project-bubble`・`/sankey-svg` の推奨判断が数百件ずれた状態で公開される（継続 2,245→2,127 など。最下位帯の31件は不変）。

一覧は `20260728_0741_rs-vis由来の既知不具合18件の棚卸し.md`。修正を当てるときは marumie → rs-vis の順に流すか、両リポジトリへ個別に cherry-pick する。

## 手順

`.agents/skills/sync-rs-vis` の流れに沿う。ただし手順1（前回反映コミットの特定）は記録が無く機能しないため、**本ドキュメントを起点記録として使う**。

```bash
# 1. rs-vis にブランチを作る
cd /Users/igomuni/MyGitHub/rs-vis
git checkout main && git pull origin main
git checkout -b sync/20260811

# 2. ソースをコピー（docs・tests・.agents・data は除外）
rsync -av \
  --exclude='.git' --exclude='node_modules' --exclude='.next' \
  --exclude='.agents' --exclude='tests' --exclude='playwright.config.ts' \
  --exclude='playwright-report' --exclude='test-results' \
  --exclude='docs' --exclude='public/data/*.json' \
  --exclude='data/' --exclude='README.md' --exclude='walkthrough.md' \
  /Users/igomuni/MyGitHub/marumie-rssystem/ ./

# 3. 差分のある .gz を個別コピー（上記10ファイル）

# 4. ビルド確認
npm install && npm run build
npm run check-traces
```

その後 PR を作る。**rs-vis の `origin` は `team-mirai-volunteer/rs-vis` なので、PR を出す前にユーザー確認を取る。**
