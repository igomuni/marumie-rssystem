# 明細表（歳出概算要求額明細表）の備考以外を raw text から CSV にできるか（FY2024）

状態: 調査（read-only、実装なし）。結論: **備考を除く左側（要求番号・事項・前年度予算額・６年度概算要求額・対前年度比較増△減）は、raw text だけから CSV にできる見込み。** 検算が通る3つの金額を持つ行が3万9千行あり、検算の不一致は0。ただし、空欄セル、名称の継続行、見出し行の扱いに決めることがあり、法務省と金融庁の計814ページは、text layer が無く対象外。
再現: `python3 -I scripts/research/scan-budget-request-detail-table.py`（2回実行して出力が一致。標準出力の SHA-256 `6a207297…2162`）。

## 1. 目的と範囲

素材（primitive）フェーズとして、明細表を原本の形のまま CSV にできるかを確かめる。ユーザーは、備考列は CSV に向かないと判断済みなので、備考は対象外にする。親子関係の復元や意味付けは、このフェーズの範囲外。

## 2. 方法

- 入力: FY2024 の plain text zip（`data/work/budget-request-plain-text.zip`。82 source、9,899ページ、Form Feed でページ区切り。最後の Form Feed の後ろの空の断片は、ページに数えない）。
- 判定に使ったのは、行の文法と、検算（要求額 − 前年度予算額 ＝ 比較増△減）だけ。補完、推測、外部知識、PDF の目視は使っていない。
- これは記述的な集計であり、精度の評価ではない。検算が通ることは、金額の列の取り違えが無いことの必要条件であって、コードと名称が正しく読めていることの証明ではない。

- text はあるが、明細表の表頭が無い: 7 source。確認した3つ（`cas…r6_01`、`mext…000031817_01`、`cao…f1`）は表紙と目次だった。残りは、表紙・目次・総表だけと見られるが、未確認。

```text

     010 内 閣 本 府
```

左側の表（要求番号・事項・3つの金額）と、右側の備考（予算額の推移、要求要旨、積算の内訳）が、同じ行に並ぶ。備考側の行は、左側が空で、右側だけに文字がある。

## 5. 結果

### 5.1 左側と備考側を分けられる

各ページの表頭の「前年度」の見出しの開始位置を境にして、行頭の位置が境より左にあるかで分けた。

- 備考側の行: 226,123行（これは対象外）。そのうち、行頭付きで、検算の通る3つの金額を持つ行は1行だけだった。つまり、金額を持つ表の行が備考側に紛れる例は、ほぼ無い。
- 表頭の見出しが見つからないページが11ページある（この11ページは境が決まらないので、別の扱いが要る）。

### 5.2 左側の行の種類（8,574ページ）

| 種類 | 行数 | 内容 |
|---|---|---|
| 金額3つ、検算 OK | **39,274** | 行頭（要求番号・コード）＋名称＋3つの金額。**検算の不一致は0** |
| 金額2つ（1つが空欄） | 1,097 | 下記 5.3 |
| 金額なしの見出し行 | 7,598 | コード＋名称だけ（組織・項・事項などの見出し） |
| 名称の継続行（の候補） | 23,235 | 行頭にコードが無い、左側の行。名称の続きと見られる |
| ヘッダ領域（ページラベル・表題・所管会計・単位・表頭） | 25,830 | 表頭の行は、境を決める手がかりにもなる。所管・会計の行（62）は、行として出す案 |
| 脚注の日時 | 2,927 | `2023/09/12 20:27:48` の形（左側にあるもの）。除外 |
| 金額が1つ・4つの行 | 5 / 3 | 例外（個別に確認が要る） |

全73 source で、左側の行（金額3つ、または2つ）が取れた。取れない source は無い。

### 5.3 空欄セル（金額2つの行、1,097行）

0 が印字されずに空欄になっている行がある（例: `63  △63` は、前年度63、要求額が空欄、比較△63）。補完はしない前提で、どの列が空欄かを決める方法は2つある。

- 検算: 2つの金額 x, y から、`x＝y` なら前年度が空欄（352行）、`x＝−y` なら要求額が空欄（467行）と決まる。`x＝y＝0` は決まらない（277行）。1行はどれにも当てはまらない。比較が空欄の行は無かった。
- ページ内の列の位置: 同じページの3列の右端は、中央値でほぼ揃う（ページ内の最大のずれは、前年度4・要求額3・比較5文字。多くは1文字）。この位置で空欄の列を決められたのは612行。うち、検算で決まらない `0 0` の行が133行ある。
- 決まらない行が残る: 位置合わせの基準にできる行が3行未満のページに、483行がある。検算でも決まらない `0 0` は277−133＝144行ほどが、位置でも決まらない。これらは、未確定（空欄の列は決めず、unresolved）として残すのが安全。

### 5.4 名称の継続行（23,235行）

- 直前の見出し・項目の名称の開始位置と揃っている: 22,418行（96.5%）。
- 揃っていない: 572行（2.5%）。
- ページの先頭にあり、そのページに直前の行が無い（前のページから続く）: 245行（1.1%）。

総表（#430）と同じ連結の規則（開始位置が揃う、間に別の行を挟まない）に近いが、明細表では、継続行と親の行の間に、備考側だけの行が挟まる。備考側の行を飛ばして、左側の行だけで連結する規則が要る。

### 5.5 行頭の形（コード）

| 形 | 行数 |
|---|---|
| 目（5桁-4桁-2桁-4桁、例 `95016‑2111‑05‑0710`） | 25,010 |
| 3桁 | 13,499 |
| 目の略記（NN-NNNN） | 8,424 |
| 2桁 | 2,877 |
| 要求番号＋事項コード（NN-NN） | 1,643 |
| 1桁 | 136 |

- 先頭の数字が要求番号かコードかは、後ろに NN-NN の形のコードが続くかで決まる。
- 全角数字は名称や備考の一部であり、ASCII の数字だけを金額とみなす（総表と同じ）。
- 目のコードの途中が空白で割れる行がある（例: `95016‑   2‑08‑2010`）。raw text の表記のまま保持する（補完しない）。

### 5.6 金額の表記

- `△` は、金額から離れて付くことがある（例: `△           63,014`、`0△  32,160`）。金額の前の `△` と、前の金額の直後の `△` の両方を、金額の符号として読む必要がある。
- 要求額が負になる行も、実際にある（例: `0  △32,160  △32,160`）。

## 6. 判断が要る点（実装の前に決める）

1. **見出し行（コード＋名称だけで、金額が無い行、7,598行）を CSV の行にするか。** 総表の CSV は、すべての行が金額を持っていた。明細表の見出し行は、組織・項・事項の見出しにあたる。行にするなら、金額の列は空欄（補完しない）。
2. **空欄セルの扱い。** 空欄のまま、列は検算または列の位置で決める。決まらない行（約144行）は、unresolved にする。
3. **名称の継続行の連結。** 備考側の行を飛ばして、左側の行だけで連結する。ページ先頭の継続行（174行）は、前のページの最後の行に連結する。
4. **text layer の無い2 source（814ページ）。** raw text の範囲外として、対象外にする。
5. **列名。** 総表の方針と同じく、明細表の見出しを日本語のまま使う（`要求番号`、`事項`、`前年度予算額`、`６年度概算要求額`、`対前年度比較増△減`）。「事項」は、コードと名称を合わせた原文にする案。

## 7. 次の一手（提案）

実装の前に、上の判断を決めてもらう。そのうえで、総表の v0（#419、#430）と同じ形で、次を進める。

- pure な抽出（`scripts/pipeline-v2/lib/`）と、runner、仕様書、テスト。
- 検算の不一致、未解決、行の取りこぼしがないことの証跡（行分類の監査ファイル）を、総表と同じ形で出す。
- 検収は、3つの金額が全行で検算に通ること、行数が決定的に再現できること、備考側の行を取り込んでいないこと。

## 8. 限界

- 検算が通ることは、列の取り違えが無いことの必要条件にすぎない。コード・名称の誤読は、この調査では確かめていない（PDF の目視は使っていない）。
- 左側と備考側の境は、表頭の「前年度」の見出しの位置という、ひとつの手がかりに依っている。11ページは、この手がかりが無い。
- 明細表を持たない7 source は、4つ分が未確認。
