# Web（Readツール）とローカルテキスト化（pdf-parse）の見え方の違い

[デジタル庁予算資料18点の内容確認レポート](20260907_0756_デジタル庁予算資料18点の内容確認レポート.md)で「Web」（Claude Readツール＝サーバー側でマルチモーダルにPDFページを認識する方式）を使って読んだ内容と、`scripts/extract-digital-agency-budget-text.ts`（`pdf-parse`によるテキストレイヤー抽出）でローカル生成した`.txt`を突き合わせ、どこが一致しどこが失われたかを確認した。

## 比較方法

PDF（01〜13）全件について、`.local.txt`（`pdf-parse`によるローカルのテキストレイヤー抽出）と`.web.txt`（Claude ReadツールでのマルチモーダルPDF読み取り結果の書き起こし）を両方作成し、`data/download/digital_agency_budget_2024/`に並べて保存した。Excel（14〜18）は、Web時点でも`.xlsx`をzip内XML（sharedStrings・worksheet）として手動パースしており、ローカル抽出スクリプトも同じ方式のため**比較対象にならない**（両方とも同じ処理。単一の`.txt`のまま）。

> **注記**: 本ドキュメントの初稿では07（省庁別財務書類の概要）の組織図ページについて「Webは正しく認識した」という誤った記述をしていた。実際にはWebでもそのページは文字化けしており、以下は訂正済みの内容。事実と異なる記述を書いてしまったことをお詫びし、以後は`.web.txt`として実際の応答を保存した上で記述するようにしている。

## 数値は残るが日本語ラベルが失われるケース: 03・05（各目明細書系）

項003の目「情報処理業務庁費」の金額（453,911,195等）や項コード「001」「95」等の**数字は正確に抽出できる**が、「デジタル庁共通」「デジタル庁一般行政に必要な経費」「職員基本給」といった**項名・事項名・目名の漢字ラベルが軒並み欠落**する。

Web（Readツール）:
  001 デジタル庁共通 15,046,161
  95 デジタル庁一般行政に必要な経費 14,481,137
  95016-2111-02 職員基本給 2,511,673

ローカル（pdf-parse）:

金額・項コード等の数字だけが残り、日本語の名称列がまるごと消える。03のPDF内部メタデータ（`/CreationDate`等）も他のPDFと違い暗号化されたようなバイナリ文字列になっており（前回レポート参照）、フォント埋め込み・文字コードの扱いが他の資料と根本的に異なることが分かる。

## 文字化け（意味不明な記号列）になるケース: 07の組織図ページ（WebでもNG）

> **訂正**: 本節の初稿では「Webは組織図ラベルを正しく認識・報告した」と書いたが誤り。会話を遡って実際のReadツール応答を確認したところ、**このページはWebでも文字化けしたままで、正しく読めていなかった**。「戦略・組織グループ」等の具体的な組織名は、その誤った前提のもとで作成側が推測で埋めてしまったもので、実データではない。訂正して以下に修正する。

07（省庁別財務書類の概要）の1ページ目・4ページ目以降は正常に抽出できるが、**「デジタル庁の組織体制」組織図ページだけ、Web・ローカルのどちらで読んでも意味不明な記号列になる**。

```text
Web（Readツール）:  !"#$%&'()!"#*+,-./!"012 >?@ABCDEFGEHIJB KL@MBNOPHIJB
              QERMSTKLHIJBULFIOHIJB ...（意味不明な記号列）

ローカル（pdf-parse）: 1$/0.)*('&%" -%" ,#%"!+ 3764 =<;: =<;:> =<;:ED
                TVRSUONMPLMKJQU a_R[U^`ZKJQU kMj[dma_KJQU ...（意味不明な記号列）
```

03・05が「文字が消える（空白になる）」のに対し、07の組織図ページは「別の文字に化ける（文字化け）」という**異なる壊れ方**をしているが、**この壊れ方はWeb・ローカルどちらの方式でも起きている**点が03・05とは違う（03・05はWebなら正しく読める）。これは、ページ自体の描画（フォントのグリフ選択）が壊れているためテキスト抽出方式に関わらず読めないことを示唆する。テキスト抽出ツールの限界というより、**PDFファイル自体がこのページだけ壊れている可能性がある**。

**追記（原因の手がかり）**: 生のPDFバイト列を直接確認したところ、このページを含む全ページで`/Rotate`フラグは`0`（回転なし）、`/MediaBox`もA4縦（595×842pt）で他ページと同一だった。つまり**ページ自体は回転指定されていない**。組織図はレイアウト上あきらかに横長の資料（フローチャート）で、それが縦向きのページにそのまま収まっているように見えることから、**組織図オブジェクト自体がコンテンツストリーム内部で回転行列をかけて埋め込まれている**（ページの向きではなく、埋め込まれた図形の中身だけが回転して配置されている）と考えられる。この種の「ページ全体ではなく埋め込みオブジェクト単位の回転」は、pdf-parseのテキストレイヤー抽出はもちろん、ReadツールのマルチモーダルなPDF読み取りでも正しく扱えなかった（テキストが正しい向き・順序で認識されなかった）ことになる。ページ回転（`/Rotate`）ですら難しい既存のPDF処理系は多いが、**オブジェクト単位の回転にはさらに輪をかけて対応が追いついていない**というのが実情のようだ。

## 一見情報が失われたようで実は失われていないケース: 07の6〜8ページ目（棒グラフ）

07の貸借対照表・業務費用計算書の棒グラフ部分は、グラフ内部の軸ラベルや積み上げ内訳の数字はローカル抽出では取れない（画像/ベクター図形のため）。しかし**グラフの直前にある説明文ボックスに同じ数値が文章として重複して書かれている**ため、実質的な情報の欠落は無い。

```text
ローカル抽出で残った説明文（グラフの補足):
  資 産（176億円）
  ◎有形固定資産（81億円：対前年度末＋22億円）
  ◎無形固定資産（95億円：対前年度末＋24億円）
  費 用（1,963億円）
  ◎庁費等（1,514億円：対前年度末＋216億円）
  ◎補助金等（301億円：対前年度末＋119億円）
```

グラフ内のラベル（縦軸目盛りの「200/180/160...」等）は失われるが、これは元々グラフの読み取り補助であり、本文の説明文だけで数値は再構成できる。

## 考察: 日本語PDF特有のクセ

- **漢字とASCII（数字・記号）で抽出の生死が分かれる**。03・05のケースでは数字・項コード・ハイフン等は残るが漢字だけが消えている。これは、日本語PDFでフォントを埋め込む際に**字形（グリフ）をUnicodeへ逆引きするための対応表（ToUnicode CMap）が無い、または不完全な埋め込み**をしている場合に典型的に起きる症状で、テキスト抽出ツールは「その位置に何らかの字形が描画された」ことは分かっても「それがどの文字か」を復元できない。数字は基本ラテン文字コードポイントのまま埋め込まれることが多いため生き残りやすい
- **横長の図がページ内部で回転して埋め込まれている場合、Web・ローカルどちらの抽出方式でも読めないことがある**。07・08の組織図はページ自体（`/Rotate`・`/MediaBox`）は他ページと同じ縦向きA4だが、図そのものが横長資料としてコンテンツストリーム内部で回転配置されていると見られる。ページ単位の回転（`/Rotate`）はPDF処理系が比較的対応しやすいのに対し、**埋め込みオブジェクト単位の回転**はテキストレイヤー抽出はもちろん、マルチモーダルな読み取りでも正しく扱えなかった。この変則的なケースへの対応は、抽出ツール側・マルチモーダルモデル側どちらもまだ発展途上と見られる

## 今回のドキュメント特有のクセ

- **各目明細書（03・05）だけが漢字ロスト系の不具合を持つ**。同じ「令和6年度デジタル庁所管」でも、概算要求・予算決定・補正概要（01・02・06）は問題なく、各目明細書だけがこの症状を示す。各目明細書は財務省が国会提出用に**専用の組版システム（予算書XML→PDF変換パイプライン）**で一括生成する帳票であることが、[docs/mof-budget-data-guide.md](../mof-budget-data-guide.md)で確認済みのXML帳票（`<clm>``<l>`タグでの複雑な段組み構造）と符合する。他省庁の各目明細書PDFでも同様の症状が起きる可能性が高い（未検証）
- **省庁別財務書類（07・08）は本文と図表で抽出品質が分かれる**。本文（説明文・脚注・附属明細書の個別金額）はWeb・ローカルとも問題ないが、**組織図ページ（07・08共通の同一図版）だけはWeb・ローカルどちらでも文字化けし読めない**（03・05のようにWebなら読める、というケースとは異なる）。棒グラフ側は画像内のラベル自体は失われるが、直前の説明文に同じ数値が重複しているため実害は小さい
- **Excel由来PDF（12・13）が最も抽出品質が良い**。ExcelはPDF化してもセルの文字列がそのままテキストオブジェクトとして埋め込まれるため、複雑な組版システムより機械的なテキスト抽出との相性が良いと考えられる
