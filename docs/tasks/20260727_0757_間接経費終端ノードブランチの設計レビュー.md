## 良い点

- レイヤ分離が設計どおり。集計は純関数 `app/lib/subcontracts/indirect-costs.ts` 1本に集約され、
  レイアウト・側パネル・ツールチップが同じ数字を参照する。`scripts/` の変更は
  `attachedToBlock` の写像のみで UI ロジックを持ち込んでいない。
- `indirectNode` / `indirectFlow` を `bars` / `flows` に混ぜず別枠にしたことで、
  `blockId` 前提のロジック（`barByBlockId`・`ribbonShiftOf` など）を汚していない。
- 二重計上防止（`attachedToBlock !== true`）が型・パイプライン・集計の3点で一貫。
  未定義の旧 JSON がオフサンキー扱いになるフォールバックも実測（2年度とも該当0件）で裏取り済み。
- 金額は全て1円単位のまま扱われ、表示は `formatYen` 経由。負値は `Math.max(0, amount)` で吸収。
- 設計で挙げた既存計算への影響5点（k・rootH・積み順・SVGサイズ・別財源レーン基準）が
  すべて実装され、対応するテストが付いている。`any` なし。

## 改善提案

### 1. 間接経費リボンがホバー不可（`app/subcontracts/[projectId]/page.tsx:2253-2263`）

`style={{ pointerEvents: 'none' }}` のため、リボン上ではツールチップが出ない。
順方向フロー（同ファイル 2266-2308）は全て `cursor: pointer` + `onMouseEnter` を持つので
挙動が不揃いで、設計 F-1 の「リボン側のホバーも同じツールチップを出す」とも異なる。
なお `fillOpacity` には `hoveredNodeRaw?.kind === 'indirect' ? 0.55` の分岐があるが、
現状ノード側ホバー時にしか発火しない。

提案: 他フローと同じく `onMouseEnter`/`onMouseLeave` で `{ kind: 'indirect' }` を立てる
（クリックは `handleIndirectClick` を付けるか、ノードのみに留めるかは要判断）。

### 2. `depth1Extra` の加算条件が「深度1が存在するか」に依存（`app/lib/subcontract-ribbon-layout.ts:203-208`）

ループ内は `depth === 1` のときだけ加算し、フォールバックは `byDepth.size === 0` のときのみ。
`byDepth` に深度2以上のみが入る（深度1ブロックが `blocks[]` に無く子だけ存在する不整合データ）
場合、間接経費が k の決定から漏れ、深度1列が `RIBBON_TARGET_COL_H` を超える。

提案: 深度1合計を明示的に取り出して常に候補にする。

```ts
const depth1Total = (byDepth.get(1) ?? []).reduce((s, n) => s + Math.max(0, n.totalAmount), 0);
// ループ後
maxColTotal = Math.max(maxColTotal, depth1Total + Math.max(0, depth1Extra));
```

### 3. 極小額のとき root の支出側が実額より膨らむ（`app/lib/subcontract-ribbon-layout.ts:487, 502`）

`indirectH` は `ribbonAmountScale` 経由なので `RIBBON_BAR_MIN_H` の床が効く。一方
`rootBlockOutH` はテーパー配分の実値（床なし）。両者を足した `rootH` は、間接経費が極小の事業で
床の分だけ支出側が広くなる。図としては閉じているので破綻はしないが、
「支出側の高さ＝金額比」を厳密に読むと誤差になる。

提案: 許容するなら現状維持でよいが、`rootH` にはスケール値（床なし）を、
ノード描画にだけ床を効かせる分離も選べる。判断を1行コメントで残しておくと後で迷わない。

### 4. 同じ集計を1描画で3回計算（`page.tsx:520`, `page.tsx:2455`, `subcontract-ribbon-layout.ts:361`）

`summarizeOffFlowIndirectCosts` は `filter` + 配列コピー + `sort` を行う。SidePane・ページ本体・
レイアウトでそれぞれ実行され、いずれも `useMemo` の外。件数は数十件規模なので実害は小さく、
周辺の `ribbonBarShift` 等も同じくインライン計算なので既存の書き方には沿っている。

提案: 気になるなら `page.tsx:2455` の `indirectSummary` を `useMemo([graph.indirectCosts])` にする、
または `indirectNode.amount/count` を使い回してツールチップの上位項目だけ別途取る。

### 5. 描画時シフトが別財源レーンの基準に反映されない（`page.tsx:1747-1760`, `subcontract-ribbon-layout.ts:587`）

`ribbonIndirectShift` は描画時に下方向へずらすが、`separateLane.top` はレイアウト時の
シフト前の値。深度1に少額ノードが多い事業では、間接経費ノードがレーン区切り線に近づく／
またぐ可能性がある。既存のブロックバーにも同じ性質があるため新規の退行ではないが、
今回ノードが「レーン直前の最下段」に来るので当たりやすくなる。

提案: 実データで深度1が密な事業（別財源レーンあり）を1件目視確認する。必要ならレーン基準に
シフト最大値を足す。テストはシフト前の値を検証しているのでここは拾えない。

### 6. 設計ドキュメントのラベル記述が実装と不一致

設計 F-1 は `間接経費（国が直接支出） (金額)` だが、実装は `79ad1f1` で `間接経費` に簡素化済み。
task doc は追記も改稿もされていない。恒久ドキュメントではないので実害はないが、
設計を後から読む人向けに1行注記があるとよい。
