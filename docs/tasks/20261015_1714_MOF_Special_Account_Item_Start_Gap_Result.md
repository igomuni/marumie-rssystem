# MOF 特別会計 — 項の開始行 245 と公式 CSV 250 の差の原因

状態: 原因を特定。結論: **差の5項は、食糧管理勘定の1ファイル（FY2024 `202412001000313a.xml`）で、説明欄に入れ子の表がある行の後ろにあり、正規表現で読んだ先行の記述（`row-classes.csv` と inventory の行数）がそこで切れていた。XML を木として読むと、項の開始行は公式 CSV の項と FY2024 250/250、FY2025 254/254（成立後・提出時）で、差は 0。**

## 経緯
- #474 の `row-classes.csv` は、`<clm>…</clm>` を正規表現で拾って行を作った。説明欄（`11.1`）の中に `<body><table>…<data>…` が入れ子で入るファイルでは、最初の入れ子の `</clm>` と `</data>` で読みが切れ、**入れ子の後ろの行が行の集計に入らなかった**。
- 影響を受けるのは、入れ子の表を持つファイル（FY2024 `…313a`、FY2025 `…337a` の食糧管理勘定）だけ。`row-classes.csv` の他のファイルの行は、入れ子がないので正しい。inventory（#472）の同ファイルの行数も同様に不足している（ファイル数・見出し・SHA は影響なし）。凍結済みの出力は書き換えず、この文書で訂正する。
- 食糧管理勘定の項は 01 食糧買入費 のあと、入れ子の表（数量表）をはさんで 02 食糧管理費、03 交付金等他勘定へ繰入、04 融通証券等事務取扱費一般会計へ繰入、05 国債整理基金特別会計へ繰入、09 予備費 が続く。差の5項はこれ。

- 行の文法の入力として、**説明欄に入れ子の表がある行**を明示的に扱う必要がある（parser v0 の `readCell` は「`clm` の子が単一の `<p>`」を要求し、入れ子の表は例外にする）。文法の選択肢は、(a) 説明欄の入れ子の表は読まずに無視し、他の列は通常どおり読む、(b) その勘定のファイルを STOP にする、の2つ。判断はユーザー。
