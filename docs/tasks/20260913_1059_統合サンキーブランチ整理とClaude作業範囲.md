同一ディレクトリで作業するため、Codex復帰時のファイルはClaudeの変更後の状態になる。
元の状態から再開する場合は `git checkout feature/integrated-sankey-first-cut` で戻す。

競合を最小化するため、**1〜4に限定し、5は行わない**。

| # | 内容 | 実施 |

整形するならCodexがファーストカットを完了させた後、独立した変更として行う。

## 実施結果（2026-09-13）

### 1. ビルドエラーの解消

page.tsx の波括弧を直した時点で、route.ts の別エラーが露出した。
`readDataJson` は再生成ヒントが第2引数に必須（`TS2554`）。同じデータを読む専用ローダー
`app/lib/api/mof-kou-moku-loader.ts` の `loadYear()` へ置換し、他APIと作法を揃えた。

### 2・3. テスト整備

実測値の突き合わせは実データを要するため、ユニットテスト（実データ非依存が本リポジトリの方針）
ではなくe2eのAPI検証として書いた。結果は仕様書の基準と一致（`20260913_1031` の実装後の検証結果を参照）。

ユニットテストには仕様書「最低限のテストケース」の未カバー分4件を追加し、8件へ。
e2eは5件。サンキー図はエッジ・ラベルが必然的に重なるため、クリックとホバーは `force` 指定が要る。

検証のため page.tsx へ `data-testid` を3つ追加した（`integrated-edge` / `integrated-detail` /
`integrated-hover`）。描画・ロジックには手を入れていない。

### 4. ドキュメント整合

`docs/integrated-sankey-graph-model.md` が旧設計（MOF→RS府省庁→事業→支出先の4列、項の選択欄）
のままで実装と食い違っていたため、2列モデルへ全面的に書き直した。
恒久的な仕様（項の識別規則・金額定義・禁止事項・基準実測値）はこの恒久ガイド側に置き、
task doc は検討記録として残す。
