前提: P0-A（#448）・P1（#449、マージ済み）。J1（所管＋事項名の exact）、eligible の定義、入力 hash guard は P1 から**変えない**。
位置づけ: 以前 PAUSED にした H1（親子関係の復元全体）の再開ではなく、MOF 突合に必要な **DETAIL → 項（`sectionName`）・組織（`organization`）** の関係だけを、観測できる構造で試す狭い feasibility（H1 の preregistration §14.3「MOF 突合に必要になった時」）。relation GT は作らない。

## 問い
P1 で複数候補になった215行（候補間で `organization` / `sectionCode` / `sectionName` が異なる）は、明細表の行の並びから取れる「直前の項・組織」の名称と MOF の `sectionName` / `organization` との exact 一致で、どこまで候補が絞れるか。その構造の前提（直前の行が項である）は、候補が1件だった694行で成り立つか。

## 構造的な抽出（事前固定。これ以外は使わない）
- 対象は eligible の DETAIL 行（982行）。同じ source の CSV の行順（`row_index`）だけを使う。
- **X（項の候補）:** DETAIL の**直前の行**（`row_index` が1つ前）の `row_type` が `CODE3` または `CODE2` で、`事項` が `^([0-9]{2,3}) (.+)$` に合うとき、その名称部。それ以外は X なし（直前の `row_type` の種類を数える）。
- **O（組織の候補）:** X の行より前を逆順に探し、`row_type` が `CODE3` / `CODE2` で名称部が**同じ所管の MOF の `organization` の集合に exact に含まれる**最初の行の名称。見つからなければ O なし。
- 名称・MOF 側の `sectionName` / `organization` に、正規化・部分一致・NFKC は適用しない。金額・親子の復元・辞書は使わない。

## 集計（P1 の J1 クラスごと: 単一 694 ／ 複数 215）
- X の有無と、X なしの場合の直前の `row_type` の分布。O の有無。
- **K2a:** J1 候補のうち `sectionName == X` の数（0 / 1 / 2+）。**K2b:** K2a かつ `organization == O` の数（0 / 1 / 2+）。
- **単一 694（構造の前提の対照）:** `sectionName == X`、`organization == O` が成り立つ行数。X のコード（`NNN`）と `sectionCode` が等しい行数（記述のみ。コード体系が違う可能性があり、一致を前提にしない）。
- **複数 215:** K2a・K2b の0/1/2+ の分布。K2b で2+のまま残る行は、候補間で異なるフィールドの組合せ。K2b で1件になる行は、その候補の `col4Raw` が末尾2桁と一致する数（K3 との整合の記述）。所管別。
- 結果は、単一での前提の成立度を先に示し、複数での絞り込みはその前提の下での記述として示す。前提が単一で成り立たなければ、複数の結果は解釈しない。

## 禁止・限界
- K2a/K2b で1件になっても matched に昇格しない。X が「項」であることは仮説で、単一での一致度で見るだけ。
- 結果を見た後に抽出規則・集計を変えない。昇格や正規化の採否は、結果のレビュー後に別の事前登録で決める。
