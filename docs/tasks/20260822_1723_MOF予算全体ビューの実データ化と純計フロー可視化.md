# MOF予算全体ビューの実データ化と純計フロー可視化 実装計画

> **実装済み（2026-08-22）。**段階1〜3を実装し、`npm run validate-mof-data` が10年度140項目で
> 配布CSVと1円単位一致。実装の結果と設計からの変更点は末尾の「実装結果」を参照。

## 目的

**予算データを見る人が「特別会計は一般会計の4倍もある隠し財布」という誤解を解き、
なぜ会計をまたいで合算できないのかを自分の目で確かめられるようにするため。**

副次的に、開発者が `/mof-budget-overview` の数値を検証できる状態にする。
現状は手打ちのため、値が正しいかを誰も確認できない。

**扱うのは MOF 側の構造だけ**とし、RS 対象範囲の区分は対象外にする（理由は「対象外とするもの」）。

## 現状の問題

### 数値がすべて手打ち

`scripts/generate-mof-budget-overview-data.ts` は CSV を読まず、定数を返すだけの関数になっている。

```ts
function generateMOFBudgetData(): MOFBudgetData {
  return {
    fiscalYear: 2023,
    generalAccount: {
      total: 114_380_000_000_000, // 114.38兆円
      revenue: { taxes: { consumptionTax: 23_380_000_000_000, ... } }
```

出典は `docs/20260202_0000_MOF予算全体とRS対象範囲の可視化.md` の分析結果の転記。
**辻褄合わせの項目が残っている。**

```ts
other: 114_310_000_000_000, // 114.31兆円（調整用）
```

`scripts/parse-mof-transfer-data.ts` は CSV を読むが、繰入の一部にしか使われていない。

### 単年度固定

`fiscalYear: 2023` のハードコード。API も `mof-budget-overview-2023.json` を決め打ちで読む。
事項別内訳（`mof-jikou`）が2017〜2026の10年度に揃ったのに、この画面だけ2023に取り残されている。

### 繰入が「線」になっていない

現在の Sankey は 財源 → 会計 → RS対象区分 → 詳細 という一方向の流れ。
一般会計から特別会計への繰入69.66兆が独立した流れとして表現されておらず、
**二重計上がどこで起きているかが画面から読み取れない。**

## 設計方針

### 方針1: 捕捉ロジックは `docs/mof-budget-data-guide.md` §6 に確立済みのものを使う

実測で確定した規則をそのまま実装する。新たに決めることはない。

| 対象 | 捕捉方法 |
|---|---|
| 一般会計 → 他会計 繰入（送） | 歳出 `使途別分類コード = 6` |
| 特会 受入（受） | 歳入 款 `他会計より受入` **または** 目 `一般会計より受入` の**和集合** |
| 特会 → 一般会計 繰入 | 一般会計歳入 款 `諸収入` の目 `◯◯特別会計受入金`（歳出には載らない） |
| 勘定間 | 特会歳入 款 `他勘定より受入` |

**款名だけで受入を拾うと年金特会の13兆円を毎年落とす。**和集合が必須。
逆方向を歳出側から探しても7億円しか出ない。原資が剰余金で歳出予算を通らないため。

### 方針2: 純計を「控除の線」として明示する

グロスと純計を別画面にせず、**同じ図の中で控除が見える**構成にする。

```text
租税      ─┐
公債金     ├→ 一般会計 ─┬→ 他会計へ繰入 ────┐（控除対象として明示）
その他     ┘             └→ 一般会計の実支出  │
                                              ↓
保険収入   ─┐                          特別会計 ─┬→ 他会計へ繰入（控除対象）
借換債等   ├→ 特会の自前財源 ───────────┘        └→ 特会の実支出
```

繰入のリンクに「控除対象」の属性を持たせ、UI 側でハイライト・合計表示を切り替えられるようにする。
`単純合計 568.75兆 / 一次純計 441.13兆` を画面上で対比できることを要件とする。

### 方針3: 粒度は「款」を基本とし、税目だけ「目」まで下ろす

歳入に事項は存在しない（事項別内訳は歳出のみ）。科目は 款 > 項 > 目 の3階層。

- 一般会計 歳入: 款（租税・公債金・諸収入…）＋ 租税は目まで（消費税・所得税…）
- 特別会計 歳入: 款（公債金・他会計より受入・保険収入…）＋ 会計別
- 歳出: 会計別 ＋ 使途別分類（繰入か実支出か）

税目を目まで下ろすのは、現行画面が既に税目別を出しており後退させないため。

### 方針4: 特定財源を可視化する

特別会計の設置理由（財政法13条2項の区分経理）が読めるよう、自前財源の比率を出す。

```text
エネルギー対策  ← 石油石炭税・電源開発促進税
特許           ← 特許料
自動車安全      ← 自動車重量税
労働保険        ← 保険料
```

「入ってくる金が決まっているので使い切る圧力が働く」構造が評価の論点になるため、
各特会の歳入に占める `他会計より受入` の比率を持たせる。実測値は §6-3 にある
（子ども・子育て支援44.2% / 交付税41.3% / 国債整理基金39.1% / エネルギー対策4.8%）。

## レイヤ配置

CLAUDE.md の Layer Design Rules に従う。**現状 `scripts/` に残っている手打ちデータは
CSV 処理に置き換わるため、レイヤ違反は解消される。**

| Layer | ファイル | 責務 |
|---|---|---|
| Data Pipeline | `scripts/generate-mof-budget-overview-data.ts` | ZIP 内 CSV を読み、会計別・款別・繰入の集計 JSON を出す。**Sankey のノード・リンク生成はしない** |
| Data Pipeline | `scripts/parse-mof-transfer-data.ts` | 繰入の抽出。年度引数対応・列名解決・分類コードベースに改める |
| Data Pipeline | `scripts/validate-mof-budget-overview-data.ts`（新規） | 生成物と CSV の突合。1円でもずれたら失敗 |
| Domain Logic | `app/lib/mof-sankey-generator.ts` | 集計 JSON から Sankey のノード・リンクを組む（Pure。HTTP 禁止） |
| API Layer | `app/api/sankey/mof-overview/route.ts` | `year` クエリを受け、ロジックは `app/lib/` に委譲 |
| UI | `client/components/mof-budget/` | 年度セレクタ・純計トグル・凡例。API を直接叩かない |
| Page | `app/mof-budget-overview/page.tsx` | 状態管理と API 呼び出しとレイアウトのみ |
| Types | `types/mof-budget-overview.ts` | 集計 JSON と Sankey の型 |

## データ構造の方針

生成 JSON は**集計値だけを持ち、Sankey の形は持たない**。現行は生成物が
すでに画面構造に寄っているため、可視化を変えるとデータ再生成が必要になっている。
これを分離する。

保持する軸:

- 年度・予算種別（当初予算に限定。補正・決算は対象外とする）
- 会計区分（一般 / 特別 / 政府関係機関）と特別会計名
- 歳入: 款別（租税のみ目別）
- 歳出: 会計別 × 繰入か実支出か（`使途別分類コード = 6` で分岐）
- 繰入: 送り手（会計・宛先名）と受け手（特会名）の両側
- 逆方向繰入: 一般会計歳入の `◯◯特別会計受入金`

年度は `mof-jikou` と同じく `public/data/mof-budget-overview-{YEAR}.json` に分割する。
`availableYears` は API が応答時に付与する（`mof-jikou-loader.ts` と同じ方式）。

## 入力データ

`data/download/mof_{YEAR}/` の ZIP を `scripts/zip-reader.ts` で直接読む。

| 帳票 | 用途 |
|---|---|
| `DL{YYYY}11001a.csv` | 一般会計 歳入（租税・公債金・諸収入・特別会計受入金） |
| `DL{YYYY}11001b.csv` | 一般会計 歳出（使途別で繰入と実支出に分ける） |
| `DL{YYYY}12001a.csv` | 特別会計 歳入（他会計より受入・保険収入・公債金） |
| `DL{YYYY}12001b.csv` | 特別会計 歳出（使途別で繰入と実支出に分ける） |
| `DL{YYYY}13001b.csv` | 政府関係機関 支出 |

10年度分の ZIP は `mof_2017`〜`mof_2026` に取得済み。ただし**全帳票が揃っていない年度がある**
（検証用に落としたものだけの年度がある）。不足分は取得が要る。

金額列の見出しは年度で揺れるため `/^(令和|平成)(元|\d+)年度/` で解決する
（`mof-jikou` の生成・検証と同じ規則）。令和6年度だけ `(千円)` が付かない。

## 検証

`mof-jikou` と同じく、**生成物と配布 CSV を1円単位で突き合わせる**検証スクリプトを新設する。
突合が通らなければ失敗させ、部分的な JSON を出さない。

| 検証項目 | 突合先 |
|---|---|
| 一般会計 歳入合計 | `11001a` の金額列合計 |
| 一般会計 歳出合計 | `11001b` の金額列合計 |
| 特別会計 歳入合計 / 歳出合計 | `12001a` / `12001b` |
| 政府関係機関 支出合計 | `13001b` |
| 一般会計の繰入 | `11001b` の `使途別分類コード = 6` の合計 |
| 特会の受入 | `12001a` の款・目の和集合 |

さらに**構造的な整合チェック**を入れる。実測で成立が確認できているもの。

- 宛先別に 送り手（一般会計＋特会）と 受け手（特会別受入）が突き合うこと
  （令和8年度: 年金は1円単位で一致、国債整理基金の差は特会からの繰入と一致）
- `単純合計 − 他会計より受入 − 他勘定より受入 = 一次純計` が成立すること

## 段階

独立して価値が出る順に3段階に分ける。**段階1だけでも現状の「検証不能な手打ち」は解消する。**

### 段階1: 実データ生成への置き換え（単年度のまま）

- `generate-mof-budget-overview-data.ts` の手打ち定数を CSV 集計に置き換える
- `parse-mof-transfer-data.ts` を年度引数対応・列名解決・分類コードベースに改める
- 逆方向繰入（一般会計歳入の `◯◯特別会計受入金`）を追加する
- 検証スクリプトを新設し、1円単位の突合を通す
- **「調整用」項目を消す**

この段階で画面の見た目は変えない。値が実データに置き換わり、検証可能になることが成果。

### 段階2: 10年度対応

- 生成を `mof-budget-overview-{YEAR}.json` の年度分割にする
- API に `year` クエリを追加し、`availableYears` を付与する
- UI に年度セレクタを置く

`mof-jikou` の `availableYears()` と同じ実装方式に揃える。

### 段階3: 純計フローの可視化

- 繰入リンクに「控除対象」属性を持たせる
- 単純合計と一次純計を対比表示する
- 特会別の自前財源比率を出す

ここは可視化の設計判断が要るため、段階2の完了後に画面設計を別途詰める。

## 対象外とするもの

### RS 対象範囲は実データ化しない

現行画面は `rsTarget: 72.56兆` / `rsExcluded` の区分を手打ちで持ち、
`createRSCategoryNodes()` `createRSSummaryNodes()` がそれを描いている。
**この区分は実データ化の対象から外す。**

理由は**年度が噛み合わない**こと。RS システムのデータが現在の形式になったのは2024年度シートからで、
本ビューが対象とする MOF の2017〜2026（10年度）のうち RS 側に対応年度があるのは
実質2年度分しかない（RS_2024シート = 予算年度2023、RS_2025シート = 予算年度2024。
`docs/rs-data-scope.md` 2節）。10年度のうち2年度だけ RS 区分が出る画面は、
年度をまたいで比較する用途に耐えない。

2023年度以前の行政事業レビューのデータも取り込む構想はあるが、
**超ワイド型 Excel のフォーマット化が重く保留中**のため、当面この状況は変わらない。

段階1〜3では MOF 側の構造（会計区分・繰入・純計）だけを扱う。
RS との突き合わせは `docs/mof-budget-data-guide.md` 5節の結合キーで別途行えるため、
本ビューから外しても RS 連携そのものが失われるわけではない。

**影響**: `app/lib/mof-sankey-generator.ts` の RS 区分に関わるノード・リンク生成
（`createRSCategoryNodes` / `createRSSummaryNodes` / `createAggregateToRSCategoryLinks` /
`createRSCategoryToDetailLinks`）と、`types/mof-budget-overview.ts` の
`rs-category` / `rs-summary` ノード種別、`rsTargetAmount` 等の詳細フィールドが不要になる。
段階1で除去するか、段階3の画面設計まで残すかは実装時に判断する。

## 決めていないこと

- 段階3の画面表現（控除をどう見せるか）は段階2完了後に別途設計する
- 補正予算・決算への対応。当初予算に限定して始める

## 実装結果（2026-08-22）

段階1〜3を実装した。設計から変えた点と、実装して初めて分かった点を残す。

### 設計から変えた点

**特別会計の財源に「自前財源」を別途持たせた。**当初は款「他会計より受入」を除けば
自前財源になると考えていたが、**年金特会は「一般会計より受入」が款「保険収入」の下にある**ため、
款で除くと13兆円の受入が自前財源に混ざる。行単位で除いた `revenue.own` を集計 JSON に追加した。

**サンキーのフローを閉じるためのノードを3つ追加した。**会計ノードで流入と流出が一致しないと
図が破綻するが、辻褄合わせの項目は作らないという方針があるため、実在する差額に名前を付けた。

| ノード | 内容 |
|---|---|
| 特別会計間の繰入（再掲） | 受入のうち一般会計からの繰入で説明できない分。出し手も特別会計で閉路になるためリンクにできない |
| 勘定間の繰入（再掲） | 款「他勘定より受入」 |
| 政府関係機関の収入不足 | 支出が収入を上回る分（借入等で賄われる） |

結果として全10年度で `流入 = 流出` が成立している。

**`view=transfer` クエリを既存ルートに足した。**transfer-detail 用に別ルートを立てず、
`/api/sankey/mof-overview?view=transfer` で財源内訳を返す。
transfer-detail ページは `/data/mof-budget-overview-2023.json` を直接 fetch していたが、
これはページ層がデータファイルを直接読む形でレイヤ規約から外れていたため API 経由に改めた。

### 削除したもの

- `scripts/parse-mof-transfer-data.ts` — 2023年度固定・列位置決め打ち・特会名ハードコード。
  新しい生成スクリプトに統合した
- `scripts/validate-mof-transfer-data.ts` — 参照先が2023固定。新しい検証スクリプトに統合した
- `types/mof-budget-overview.ts` の RS 区分（`rs-category` / `rs-summary` / `rsTargetAmount` 等）と
  `app/lib/mof-sankey-generator.ts` の対応するノード生成（989行 → 約420行）
- `types/mof-transfer.ts` の固定フィールド構造（特会名を型に埋め込んでいた）。
  新設・廃止に型変更なしで追随できるよう名前と金額の組の配列に変えた

### 実装して分かったこと

**特別会計の数は年度で変わる。**令和6年度（2024）は13会計、令和7・8年度は14会計。
子ども・子育て支援特別会計が令和6年度に新設されたため。会計名を型やコードに埋め込むと
毎年壊れるので、一覧は CSV から動的に作っている。

**自前財源比率は「区分経理が実質的に成立しているか」の指標になる。**令和8年度の下位は
子ども・子育て支援56% / 交付税及び譲与税配付金59% / 国債整理基金61%。
いずれも一般会計から回ってきた金を通す性格が強い。

### 検証

`npm run validate-mof-data` が10年度140項目で配布 CSV と1円単位一致。
歳入歳出合計・繰入の送受に加え、`単純合計 − 受入 = 一次純計` と
会計別の積み上げが総額に一致することも確認している。

サイズは JSON 計0.29MB / `.gz` 計0.05MB。事項別内訳（2.91MB）に比べて小さい。
