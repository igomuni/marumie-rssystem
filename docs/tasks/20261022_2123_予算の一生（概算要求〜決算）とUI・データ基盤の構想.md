# 予算の一生（概算要求〜決算）と UI・データ基盤の構想

状態: 構想（未着手）。PR #548 のレビュー（方向性は GO）の 4 点を反映済み。結論: まず「項 × 年度 × 出来事（イベント）」の 1 本の表（予算の一生の表）を作る。UI のリッチ化と /integrated-sankey の改善は、どちらもこの表の上に載せる。FY2023・FY2024 は概算要求から決算までのデータがそろっている。

## 1. いま何があるか

### 段階ごとのデータ（年度 = 予算の年度）

| 年度 | 概算要求 | 当初（政府案） | 補正 | 決算 | RS（事業） |
|---|---|---|---|---|---|
| FY2023 | ○ | ○ | ○ | ○ | 執行実績（RS 2024 年度提出） |
| FY2024 | ○ | ○ | ○ | ○ | 執行実績（RS 2025 年度提出） |
| FY2025 | ○ | ○（提出時と成立後の 2 版） | ○ | 未公表 | 当初・補正（RS 2025 年度提出） |
| FY2026 | ○ | ○ | アーカイブの 2026 版に一般会計の CSV あり（中身は要確認） | 未公表 | 要求額（RS 2025 年度提出） |
| FY2027 | ○ | — | — | — | — |

- 概算要求: `tests/fixtures/budget-request-trend/`（項・事項・目）と MOF 突合。
- 当初・補正・決算: `tests/fixtures/mof-archive-csv/{ver}/`。当初は項・目・事項、補正・決算は項・目。
- RS: 1 回の提出に、前年度の執行・当年度の予算・翌年度の要求額が同居する（`docs/data-pipeline-v2.md` 3 節）。

### 通しで追えることの確認（FY2024 消費者庁共通費、千円）

```text
概算要求     4,991,087（要求書）
政府案       5,028,079（予算書。FY2025 の要求書の前年度予算額と一致）
補正         −63,381 → 改予算額 4,964,698
決算         歳出予算額 4,964,698（= 改予算額）→ 現額 4,964,698
             → 支出済 4,549,177 ＋ 翌年度繰越 0 ＋ 不用 415,521
```

この項では、段と段が額でつながる。補正の改予算額は決算の歳出予算額と一致し、FY2025 の要求書の前年度予算額は FY2024 の政府案と一致する。予算書の前年度予算額は、多くの項で前年度の補正後の額だが、例外がある（FY2026 の予算書で、当初とも補正後とも合わない項が一般会計 114・特別会計 15。原因は未確認）。

### MOF のデータが 3 系統ある

| 系統 | 中身 | 年度 | 使っている画面 |
|---|---|---|---|
| V1 `public/data/mof-kou-moku-{年度}.json.gz` | 項・目（当初・補正・決算） | 2017〜2026 | /mof-kou-moku、/integrated-sankey ほか |
| V2 `public/data/v2/mof/fy{年度}/` | 項の出来事（当初・現額・支出済・繰越・不用など） | 2023〜2025（2025 は当初のみ） | V2 の links・RS 突合 |
| `tests/fixtures/mof-archive-csv/{ver}/` | 原本の形の CSV（当初・補正・決算・事項） | 2023〜2026 | 概算要求の突合、/budget-request-mof |

- 3 つとも予算書アーカイブが元で、合計は合う。例: FY2023 一般会計の当初は、V2 も CSV も 114 兆円台。
- 項の数は数え方で違う。決算にしかない項が一般会計で約 200 あり、FY2023 の V2 の一般会計は 994 項、当初の CSV は 800 項。
- V1 はローカルで再生成できない状態（メモリの記録）。V2 は事項を FY2024 一般会計しか持たない。
- 新しい作業は CSV の系統に寄ってきているが、/integrated-sankey などは V1 のまま。

## 2. データ基盤: 予算の一生の表

### 形

項（識別）と、項に起きた出来事（イベント）を分ける。いまの V2 の `BudgetEntity` / `BudgetEvent`（`docs/data-pipeline-v2.md` 5 節）の考え方を引き継ぐ。「段階」の列 1 つでは、同じ年度・同じ項に補正が複数あるときや、累計の額（成立予算額・改予算額）を表せないため。目の粒度は第 2 段。

| 要素 | 内容 |
|---|---|
| 項の識別 | 年度・会計区分・所管（特別会計名）・組織／勘定・項コード・項名（いまの突合と同じ鍵） |
| 出来事の種類 | 概算要求 / 政府案 / 成立 / 補正 / 決算の各列（歳出予算額・前年度繰越・予備費使用・流用等・移替・現額・支出済・翌年度繰越・不用） |
| 出来事の識別 | 補正の号、版（例: FY2025 の提出時・成立後）、起きた順 |
| 額 | 正規化した円と、原本の値・単位（当初・補正は千円、決算は円） |
| 出典 | データセットの版・原本のファイル・行・SHA-256 |
| 状態 | 原本の値 / 導出した値 / 未解決 を分ける |

- **空欄と 0 を区別する。計算で値を補わない。** 空欄は空欄のまま持ち、0 にしない。差額などの導出値は「導出」と印を付け、原本の値と混ぜない（いまの CSV の作り方と同じ原則）。
- **補正は、原本の累計の値と、号ごとの差額を両方持つ。** 補正の CSV の成立予算額・改予算額は累計なので、足すと二重になる。差額は導出値。
- **恒等式で検算する。** 改予算額 ＝ 当初 ＋ 補正の差額、決算の歳出予算額 ＝ 改予算額、現額 ＝ 歳出予算額 ＋ 繰越等、不用 ＝ 現額 − 支出済 − 翌年度繰越。原本の列の恒等式は、作成時に全件で成り立つことを確認済み。段をまたぐ式（改予算額 ＝ 決算の歳出予算額 など）は未検算で、合わない項は理由つきで一覧にする。
- **概算要求は、いまの MOF 突合でつなぐ。** 要求のみ・予算のみの項も残す。

### 年度をまたぐ項のつながり

年度推移の図（面積図・ヒートマップ）には、「FY2024 のこの項は FY2025 のどの項か」が要る。項コードや項名は年度で変わる（改称・統合・新設）。

- 根拠に使えるもの:
  - 同じ鍵
  - 突合の項名の対応表（`kou_renamed`）
  - 前年度予算額の一致（予算書の前年度予算額と前年度の改予算額、要求書の前年度予算額と前年度の政府案）
- **額の一致は、対応の候補を支える証拠であって、同じ項であることの保証ではない。** 予算書の前年度予算額は、当初とも補正後とも合わない項がある（FY2026 で 129 項）。たまたま同じ額の別の項もありうる。目の粒度では、要求書の前年度額の 91〜95% が前年度の予算書と一致した（FY2024〜2026。#547 の設計で確認）が、残りは合わない。
- つながりは「根拠つきの対応表」として別に持ち、表の本体には混ぜない。対応ごとに状態を持つ: `RESOLVED`（根拠がそろい 1 対 1）/ `AMBIGUOUS`（候補が複数、または根拠が食い違う）/ `UNRESOLVED`（候補なし）。根拠の種類も残す。

### 置き場と既存の系統

- **正は CSV の系統にする（推奨）。** 原本の形のまま人が確かめられ、概算要求の突合もこれで動いている。
- V2 の系統は、合計の照合相手にする（決算の段階を独自に持つので、突き合わせると検算になる）。
- V1 は、10 年分の当初の履歴として読むだけにする。新しい画面からは使わず、/integrated-sankey は新しい表に移す。
- `docs/*.md` にガイドを 1 本置く（段階の定義、補正の累計、単位、恒等式）。

## 3. UI のリッチ化

表で読む画面はできてきたので、次は「形で気づく」図を足す。どれも予算の一生の表から作れる。

| 図 | 何が見えるか | 置き場 |
|---|---|---|
| **ブリッジ（滝グラフ）** | 1 つの項の、要求から決算までの**額の変化**: 要求 → 査定 → 補正 → 繰越・予備費 → 現額 → 支出済・繰越・不用 | /budget-request-mof の詳細に「一生」タブ。所管・全体の集計にも使える |
| **現額のサンキー** | 決算の**現額の構成と配分だけ**: 歳出予算額・前年度繰越・予備費使用・流用等・移替 → 現額 → 支出済・翌年度繰越・不用 | 新しいページ、または /integrated-sankey の表示の 1 つ（4 節） |
| **ヒートマップ（所管 × 年度）** | 査定率（当初 ÷ 要求）、補正の大きさ、執行率（支出済 ÷ 現額）、不用率 | 新しいページ。項 × 年度にも降りられる |
| **表のセルの色付け** | 年度推移・事項・目の表の増減を色の濃さで | /budget-request-trend の年度の表（小さな変更ですぐ効く） |
| **面積図** | 所管別の当初予算の推移、目の性質（人件費・物件費・補助金など）の構成比 | 新しいページ。性質は予算書の目の経済性質別分類コードから引ける |
| **一覧の行の中の小さな推移線** | 項ごとの要求額の年度推移 | /budget-request-trend の一覧 |
| **スロープ図** | 所管ごとの要求 → 当初 | /budget-request-mof の分布図の横 |

- 色は、#541 で決めた 3 色の考え方（判別できる数に絞る、ダークでも検査する）を引き継ぐ。作るときは dataviz のスキルに沿う。
- 図は、表の代わりではなく、表への入口にする。図で選ぶと、いまの一覧と詳細が開く。
- **要求から決算までを 1 本のサンキーにしない。** 要求 → 政府案は査定による増減で、お金の移動ではない。当初 → 補正 → 改予算額は累計の額の変化で、減額の補正もある。帯の幅が保存されるのは、決算の現額の内訳（恒等式が成り立つ部分）だけ。変化はブリッジ、配分はサンキーと、図を分ける。

## 4. /integrated-sankey の改善

### いまの状態

- MOF の項（V1）と RS の事業の 2 列。帯は描かない。対応は詳細パネルの一覧で見せる。
- 帯をやめたのは、項と事業の対応が多対多で、額を分けられないため。
- 紐づけ率は年度で大きく違う。RS 2025 × MOF 2024 は 92.7%、RS 2024 × MOF 2023 は 21.3%。
- 事項は「未統合（別 task）」のまま。

### 改善の案

1. **データを予算の一生の表に移す。** V1 への依存を外す。項のノードに、段階の切り替え（当初 / 現額 / 支出済）を付ける。
2. **帯を描ける図を足す。** 決算の現額の内訳は恒等式で保存されるので、「歳出予算額・繰越等 → 現額 → 支出済・繰越・不用」は帯にしてよい。所管でまとめる。要求から現額までの変化は帯にせず、ブリッジで見せる（3 節）。項と事業の 2 列はそのまま残し、表示を切り替える。
3. **事項を入れる。** 予算書の事項は、額つきで CSV にそろった（FY2023〜2026 の両会計）。項の詳細に事項のタブを足し、/budget-request-mof と同じく要求と並べる。
4. **紐づけを根拠つきにする。** RS 2024 × MOF 2023 の 21.3% を上げる。
   - RS の歳出予算科目（所管・組織／勘定・項・目の名前）と、予算書の項・目を、いまの突合と同じ鍵と表記の揃え方でつなぎ直す。
   - RS の翌年度要求額と、概算要求書の項・事項との対応も見られる（推測。RS 側に事項の粒度が無ければ、項まで）。
5. **決算と RS の執行を並べる。** 決算の支出済（項）と、RS の執行額（事業）の合計を、項ごとに比べる。差をそのまま「RS に載らない事業の額」とは読まない。紐づけの漏れ、集計の範囲、年度のずれ、重複を切り分けてから解釈する（人件費など RS に載らない支出が含まれるというのは推測）。

## 5. 進め方（案）

| 段 | 内容 | 依存 |
|---|---|---|
| P0 | 予算の一生の表（FY2023・2024 は全段階、FY2025・2026 はある段階まで）、恒等式の検算、V2 との合計の照合、ガイド | なし |
| P0' | 年度をまたぐ項の対応表（根拠の種類と RESOLVED / AMBIGUOUS / UNRESOLVED の状態つき） | P0 |
| P1 | すぐ効く UI: 年度推移の表の色付け、/budget-request-mof の詳細に「一生」タブ（ブリッジ） | P0 |
| P2 | 新しいページ: 所管 × 年度のヒートマップ、現額のサンキー、面積図 | P0・P0' |
| P3 | /integrated-sankey: データの移行、段階の切り替え、事項、紐づけの改善 | P0。紐づけは独立に始められる |
| P4 | 長い履歴（V1 の 2017〜2022、またはアーカイブの再取得）で面積図を伸ばす | P0' |

- P0 は、#547 までと同じく、原本の形・根拠・検算を先に作る作業。在庫（件数・分布）を先に恒久化してから工程を決める方針（メモリの「inventory を研究の前に」）に沿う。
- 新リポジトリへの移行（2026-10-19 の議題 5）をするなら、P0 は新リポジトリで始めるのがよい。古い 2 系統（V1・V2 の MOF）を持ち込まずに済む。
