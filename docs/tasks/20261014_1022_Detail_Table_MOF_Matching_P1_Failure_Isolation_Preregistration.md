## U（未突合73行）の分類
各行を、次の**順序で最初に当てはまるもの1つ**に分類する（診断のための関係の記述で、突合・正規化の採用ではない）。比較対象は MOF `budget-jikou` の `jikouName`。
1. **U1 他所管に同名:** 名称が exact に一致する MOF 行が他の所管にある（同じ所管には無い）。
2. **U2 NFKC で一致（同所管）:** 同じ所管の MOF 行に、両者に Unicode NFKC のみを施すと一致するものがある。
3. **U3 記号・括弧を除いて一致（同所管）:** NFKC の後、Unicode カテゴリ P*・S*・Z* の文字を除くと一致。
4. **U4 前方一致（同所管）:** 同所管の MOF 行の名称が、明細表の名称の真の前方部分（または逆）。短い方が4文字以上。
5. **U5 部分文字列（同所管）:** 一方が他方の部分文字列（短い方が4文字以上）。U4 を除く。
6. **U6 該当なし:** 上のいずれにも当てはまらない。
- 各行に、該当した関係のMOF行の数（distinct）も出す。**U2〜U5 は関係の記述であり、一致とは扱わない。**
- 別軸（K3 診断）: 全73行について、同所管で `col4Raw` が DETAIL の末尾2桁と exact 一致する MOF 行の数（0 / 1 / 2+）。分類（U1〜U6）とは独立に集計する。
- 73行の一覧（所管・DETAIL コード・名称・U 分類・K3 数）を出力に含める。

## M（複数候補215行）の分類
- **M1 候補間で異なるフィールド:** 候補の MOF 行どうしで値が異なるフィールドの組合せ（`organization` / `sectionCode` / `sectionName` / `col4Raw` のうち、候補間で全一致しないもの）。全て同じなら `none (identical rows)`。
- **M2 K3 診断:** `col4Raw` が DETAIL の末尾2桁と exact 一致する候補の数（0 / 1 / 2+）。**1件でも matched には昇格しない。** 2+ のものは、その残りの候補間で異なるフィールドの組合せを M1 と同様に出す。
