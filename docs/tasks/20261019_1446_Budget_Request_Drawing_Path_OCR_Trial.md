# 描画パス型頁の OCR 試行（macOS Vision と tesseract）

FY2025 法務省の描画パス型 15 頁で、macOS Vision と tesseract を試した。どちらも漢字・表見出し・金額の一部を誤読し、手元の環境では OCR で精度を出すのは現実的でないと判断して打ち切り。正解値のある誤読率は出していない。

## 対象と方法

- 対象: `data/download/moj.go.jp/content/001424470.pdf`（FY2025 法務省、747 頁）の描画パス型 15 頁（731〜741、743〜745、747）。棚卸しは別の task doc（描画パス型頁の棚卸し）。
- 前処理: `pdftoppm -r 200 -gray -png` で 1 頁ずつ画像化。
- macOS Vision: Swift（`VNRecognizeTextRequest`、`accurate`、`ja-JP`・`en-US`、言語補正なし）。1 頁約 1 秒。
- tesseract: `brew install tesseract tesseract-lang`、`-l jpn+eng --psm 11`。15 頁で約 15 秒。
- どちらも無料で、PDF・画像を外部へ送らない。

## 結果

正しい形の金額（`1,234` のような桁区切り）の数:

| 頁の範囲 | Vision | tesseract | 両者一致 |
|---|---:|---:|---:|
| 15 頁合計 | 299 | 185 | 164 |

- tesseract が拾った金額の 89% は Vision も同じ値で拾った。Vision が拾った金額の 55% は tesseract と一致した。
- 定員表（743 頁）は桁区切りのない小さい数が主で、この指標では 0 件。

731 頁の下半分（約 31 個の数字）を、画像を見て筆者が読んだ暫定の値と比べた: Vision 27、tesseract 21 が一致。1 領域だけで、正解を凍結したものではない。

誤読の傾向:

- Vision: 桁区切りのカンマがピリオドになる（`2,847` → `2.847`）、括弧内の値の誤り（`(9,700)` → `9,701`）、数値の欠け（`@ 9,800` → `9,80`）、漢字の誤り（`公安調査庁` → `会家調奈庁`）、表見出しの崩れ。確信度は 0.3 / 0.5 / 1.0 の 3 段階で、指標にならない。
- tesseract: 漢字がほぼ読めない。数字も末尾が違うことがある（`17,391` → `17,39]`）。括弧つきの `(9,700)`・`@ 9,800` は正しく読めた。

## 判断

- 手元の環境（macOS Vision・tesseract）では、金額を機械で信頼できる精度で読めない。2 つが一致した金額だけが使える見込みだが、残りは画像を見て人が直す必要がある。
- 打ち切り。検算（内訳の合計と計、概算要求額 − 前年度予算額 と比較増減）による自動検証は、実装していない。
- 根本の対処は、所管に文字層付きの PDF を出してもらうこと（問い合わせ）。

## 試さなかったもの

- NDLOCR-Lite（国立国会図書館）: 公式ページに Mac（Apple M4）での動作確認、GPU 不要、画像入力（PDF は不可）、CC BY 4.0 とある。ディスク容量・速度の数値は書かれておらず、動かしていない。
- NDLOCR 本家（v2 系）: Docker と NVIDIA GPU（CUDA 11.1）が前提で、Mac の記載がない。
- PaddleOCR・EasyOCR: 試していない。
