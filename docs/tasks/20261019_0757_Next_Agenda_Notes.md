## 1. 事項要求の検知ができるかの検証
- 概算要求書には、金額を持たない「事項要求」があるはずで、日本学術会議だけでなく、**すべての所管**に存在すると考えている。その存在と数を確かめるための検証。
- 日本学術会議は例の 1 つ（FY2024・FY2025 は、内閣府の掲載ページに「事項要求」とだけ書かれ、要求書の PDF がない）。
- 概算要求書の PDF（総表・明細表・目次など）で、「事項要求」と書かれた項・事項を機械的に検知できるか、所管ごとにどれだけあるかを見る。

### 触りの結果
- plain text（FY2023〜FY2026）に「事項要求」は、年あたり 80〜138 箇所・19〜28 PDF に現れる（FY2023 138／FY2024 107／FY2025 91／FY2026 80）。空白入りの表記は、空白を除いて数える。
- FY2025 の 91 箇所の書かれ方: 括弧書き `（事項要求）` が 71、文中の `事項要求とする`・`事項要求を行い` が 18、その他 7。括弧書きは、組織・項・事項・勘定の行の右端に付く（例: 厚労省 `子ども・子育て支援勘定 … （事項要求）`、内閣府 `内閣本府共通費 … （事項要求）`）。
- 所管ドメイン別（FY2025）: 文科省 25、国交省 20、外務省 11、総務省 8、防衛省 8、内閣府 6、厚労省 4、こども家庭庁 4、ほか。
- 総表・明細表・TOC・表紙の CSV には、事項要求が列として出ていない（明細表の `unresolved.csv` に 1 件だけ現れる）。
- 見立て: 括弧書きは行単位で機械的に拾えそうで、まず行に紐づけて数えるのが最初の一歩。文中の記述は、対象の項・事項が文脈で決まるため、別の扱いになる。

## 4. rs-vis の概算要求機能の確認
- リポジトリ `rs-vis` に、概算要求に関する機能があるかを確認する。この repo の成果（概算要求 CSV・MOF との突合）との関係を見る。

### 触りの結果（2026-10-19。最初の確認は、更新していない rs-vis のローカルを見ていて誤っていた。訂正済み）
- ローカルの rs-vis は `origin/main` から 477 コミット遅れ（ローカルだけの 186 コミットもあり、枝分かれしている）。最初に「概算要求の機能はない」と書いたのは、この古いローカルを見たためで、誤り。`origin/main` には、概算要求の機能が一式ある。
- **`/budget-requests`**（`app/budget-requests/`、`app/api/budget-requests/`、`app/lib/budget-requests.ts`）: 財務省の年度索引から各府省の掲載ページをたどり、概算要求資料（PDF・CSV・XML）を自動収集する独立ビュー。初期対象は **2027 年度（令和9年度）**。仕様は rs-vis の `docs/budget-requests.md`。
  - 収集: `scripts/budget-requests-discover.ts`・`budget-requests-extract.ts`、取得は `npm run fetch:budget-requests`。手動起動の GitHub Actions（`.github/workflows/budget-requests.yml`）。原本は SHA-256 で保存し、改訂番号と取得日時を持つ。
  - 抽出: PDF は「歳出概算要求額明細表」の標準列を、座標で切り出す（pdfjs。poppler・OCR・LLM は使わない）。数値は 1 円単位。
  - **値の種類を区別: `numeric` / `事項要求` / `blank` / `extraction_failed`**。空欄や取得失敗を 0 円にしない。（項目 1 と直接関係する。）
  - 各行に PDF ページまたはセル、原文抜粋、原本ハッシュ、抽出方法、検証警告を持つ。
  - 資料を横断した金額の合計は作らない（親子・概要・通常要求・要望・投資枠に重複があるため）。
- **RS 事業との対応**（`scripts/generate-budget-request-links.ts`、`public/data/budget-request-links-2027.json.gz`、`/api/budget-request-links/[pid]`）: RS レビューシートの歳出予算項目（所管・組織・勘定・項・目）と、明細表の目の行を名前で突き合わせ、事業ごとに「その事業が使う目の要求額」を出す。目は複数の事業で共有されるので按分しない。統合サンキーの事業パネル（`client/components/unified-budget/ProjectBudgetRequest.tsx`）にも出ている。
- この repo との違い: 対象年度が rs-vis は 2027 年度のみで、この repo は FY2023〜FY2026。方式も違う（rs-vis は PDF を座標で直接切り出す。この repo は pdftotext の plain text から階層をたどり、MOF の予算書と名称の完全一致で突合する）。MOF の予算書との突合・過去年度の概算要求は、rs-vis にない。
- 見立て: 二つの実装に重なり（取得・抽出・事項要求の区別）があり、5（新リポジトリ）の判断に関わる。まず、rs-vis の抽出結果を見て、両者の突き合わせ（同じ年度で、何が一致し、何が違うか）をやる価値がある。FY2027 の PDF は rs-vis 側に原本（Git 管理外）があるはず。
