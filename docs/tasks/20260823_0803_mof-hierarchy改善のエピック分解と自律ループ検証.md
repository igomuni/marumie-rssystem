# /mof-hierarchy 改善のエピック分解と自律ループの成立条件

## 結論

**ループは回せる。ただし今のままでは回らない。** 前提である「緑のベースライン」が e2e で崩れており（11 failed / 23）、
さらに前スプリントの受入条件が「イケてない」「まだまだです」という人間の目でしか判定できない形だったため、
1周ごとに人間の判定を待つ構造になっていた。これはループではなく単なる逐次指示である。

自律ループの成立条件は1つに集約される。

> **US の受入条件が、コマンド1本で真偽を返せること。**

この条件を満たさない US は、どれだけ小さく割っても自律実行できない。逆に満たしていれば、
エージェントは「失敗するテストを書く → 実装 → 検証チェーンを流す → 緑ならコミット」を無人で反復できる。

したがって最初のエピックには、**受入判定の基盤を作る作業を第1フィーチャーとして含める**。
これは回り道ではなく、以降の全 US の実行可能性を決める前提条件である。

## 1. ベースライン実測（2026-08-23 08:00 JST, `main` = c9e564a）

| 検証 | コマンド | 結果 |
|---|---|---|
| Lint | `npm run lint` | ✅ 警告のみ（既知の exhaustive-deps） |
| 型 | `npx tsc --noEmit` | ✅ エラーなし |
| ユニット | `npm test` | ✅ 126 passed / 13 files（343ms） |
| E2E | `npx playwright test` | ❌ **11 failed / 12 passed**（1.1m） |

### E2E の失敗はすべてテスト側の陳腐化

製品の回帰ではない。11件の内訳は以下の4種類だった（初回の見立てでは7件の原因を
フォントサイズUIのせいだと誤って書いていたので、実測に基づいて訂正した）。

| 件数 | 原因 | 実測ログ |
|---|---|---|
| 7 | **ラベル上に透明なヒット領域が乗った** | `<rect fill="transparent"> intercepts pointer events` |
| 1 | 文字サイズUIの置き場所が変わった | `waiting for getByLabel('基準フォントサイズ編集を開始')` |
| 2 | 検索と絞り込みが別UIに分離された | `waiting for getByTestId('search-mode-toggle')` / `unexpected value ""` |
| 1 | `/` がリダイレクトになった | `getByRole('heading', ...)` element(s) not found |

**(a) ラベルのクリック領域（7件・最多）**

`renderLabelHitRect()` が文字より広い透明な `<rect>` をラベルの上に重ねている
（`app/sankey-svg/page.tsx`）。実際に `onClick` を持つのはこの rect の方で、
`<text>` を直接クリックしようとすると Playwright は永久に待つ。

```text
- attempting click action
  - <rect fill="transparent" ...> intercepts pointer events
- retrying click action
```

これは製品の改善（クリックしやすくした）であって不具合ではない。テスト側が
「ラベルを押す」をヒット領域として表現し直す必要がある。

**(b) 文字サイズUIの置き場所（1件）**

`基準フォントサイズ編集を開始` は今も存在するが、デスクトップ幅では
表示設定ダイアログではなく左下のフローティングに出る
（ダイアログに入るのは `isCompactWidth` のときだけ）。テストは
`表示設定を開く` → `基準フォントサイズ編集を開始` の経路を前提にしていた。

**(c) 検索と絞り込みの分離（2件）**

`search-mode-toggle`（検索⇄絞り込みの切替）と `filter-target-select`（絞り込み対象）は
廃止され、検索ボックスとは別のフィルタパネルになった。URLパラメータも
`f` / `nft` / `nf` → `fp`（パネル開閉） / `fnp`（事業名） / `fnr`（支出先名）に変わり、
`q` は検索専用になっている。

**(d) `/` のリダイレクト（1件）**

`app/page.tsx` は `redirect('/sankey-svg')` のみで、テストが探す見出しは存在しない。

つまり **`/sankey-svg` は壊れていないが、それを守る網は UI 変更に追随しておらず、
現時点で回帰を検知する能力を失っていた**。

### 検証チェーンが作業ツリーを汚していた

計画時には見えていなかった問題が、実行して分かった。

`tests/e2e/responsive-investigation.spec.ts` は `expect` を1つも持たない調査用スペックで、
走らせるたびに `docs/tasks/_assets/20260528_responsive/*.png` を上書きする。
つまり **`npx playwright test` を流すと必ず6ファイルが変更済みになり、作業ツリーが
決して綺麗にならない**。これはループの手順5「全部緑ならコミット」と正面から衝突し、
放置すると毎周おなじ無関係な差分を巻き込む。

### /mof-hierarchy 側の観測

- e2e テスト: **0件**（`tests/e2e/` に spec なし）
- `data-testid`: **0件**（`/sankey-svg` は `testId()` ヘルパで開発時のみ付与する仕組みを持つ）
- ユニット: 26件（sankey 10 / focus 10 / layout 6）— ドメインロジックは既に自動検証されている

**描画と操作にだけ自動判定の手段が無い。** そして前スプリントで指摘が集中したのは、まさにその領域だった。

## 2. エピックの選定

候補を3つ挙げ、1つに絞る。

| ID | エピック | 価値 | 今やるべきか |
|---|---|---|---|
| **E1** | **/mof-hierarchy を「事項まで自力で辿り着ける」探索ツールにする** | 既にあるデータが使える状態になる | **◎ 今回** |
| E2 | 収録範囲を広げる（特会の決算＝区分78、政府関係機関の補正＝区分23） | 見られる年度・種別が増える | △ 操作できない図にデータを足しても価値が出ない |
| E3 | `/mof-budget-overview` と統合し、財源から事項までを1枚にする | 全体像が1枚で追える | ✕ 両ページが固まる前に統合すると設計が二度手間 |

**E1 を選ぶ。** 理由は、データは既に10年度ぶん揃っているのに、
図が読めず操作もできないために「持っているが使えない」状態にあるから。E2 と E3 はどちらも E1 の完了を前提にする。

### E1 の完了条件（アウトカム、人間が判定する唯一の関門）

> 令和8年度当初予算で、任意の省庁から任意の事項まで **検索を使わずに** 辿り着けて、
> その事項の金額と説明が読め、その画面状態を URL で共有して再現できる。

これはエピック単位のゴールであり、スプリント内の各 US はすべて機械判定に落とす。

## 3. フィーチャーとユーザーストーリー

最低限として **2フィーチャー・4 US** に絞る。第3フィーチャー以降は次スプリント候補として §5 に置く。

### F1: 回帰の網（受入判定の基盤）

これが無いと以降の US を自律実行できない。**スプリント内で最優先。**

---

#### F1-US1: 陳腐化した e2e を現行 UI に合わせ、緑のベースラインを取り戻す

> 開発者として、`npx playwright test` の赤を「自分の変更が壊した」と読めるようにしたい。
> 常時赤だと、赤が何の情報も持たなくなるから。

**受入条件（機械判定）**

```bash
npx playwright test
# → exit code 0
```

**やらないこと**

- 製品の**挙動**を変えない。今回の赤はテスト側の陳腐化であり、
  製品を変えて赤を消すのは因果が逆になる。
- ただし `testId()` で開発時のみ付与される `data-testid` の追加は挙動の変更ではないので許す。
  透明なヒット領域やフィルタ入力には掴む手がかりが無く、これ無しでは
  テストが現行UIを指せない（`force: true` で座標を殴るのは、本物の重なり事故を隠すので採らない）。

### 実施結果（2026-08-23 完了）

`npx playwright test` → **exit 0 / 17 passed / 6 skipped**。lint・tsc・unit 126 も緑。

| 対応 | 内容 |
|---|---|
| ラベルのクリック（7件） | `renderLabelHitRect` に `testId('node-label-hit')` を付け、テスト側に `nodeLabel()` ヘルパを追加。`svg text` への click / hover 10箇所を置換 |
| 文字サイズ（1件） | 導線を `表示設定を開く` → `フォントサイズ設定` に変更 |
| 検索と絞り込みの分離（2件） | フィルタ入力に `testId('filter-project-name')` / `filter-recipient-name` を付与。deep link を `f/nft/nf` → `fp/fnp` に書き換え |
| `/` のリダイレクト（1件） | 見出しの確認をやめ、`/sankey-svg` への到達と canvas の描画を見る |
| ツリー汚染 | `responsive-investigation.spec.ts` を `test.skip(!process.env.CAPTURE_SCREENSHOTS)` で既定から外した（6 skipped はこれ） |

**旧テストの意図は落としていない。** 例えば「年度を切り替えても選択が同じ支出先に追従する」
（2025 は `sel=r-10`、2024 は `sel=r-6`）という不変条件は実測で今も成立しており、
絞り込みの導線だけを差し替えて同じ表明を残した。

#### F1-US2: /mof-hierarchy に e2e の足場を作る

> 開発者として、階層サンキーの描画と操作を自動で検証したい。
> 表示の完成度に関する US は、この足場なしには受入条件を書けないから。

**受入条件（機械判定）**

```bash
npx playwright test tests/e2e/mof-hierarchy.spec.ts
# → exit code 0
```

新規 spec が最低限これを検証すること。

```ts
await page.goto('/mof-hierarchy');
await expect(page.getByTestId('hierarchy-canvas')).toBeVisible();
await expect(page.getByTestId('hierarchy-node').first()).toBeVisible({ timeout: 30_000 });

await expect(page.getByTestId('hierarchy-column')).toHaveCount(6);
// ノードを選ぶと URL に残り、戻るで1つ前に戻る
await page.getByTestId('hierarchy-node').first().click();
await expect(page).toHaveURL(/sel=/);
await page.goBack();
await expect(page).not.toHaveURL(/sel=/);
expect(pageErrors).toEqual([]);
```

- `HierarchyChart.tsx` に `testId()` 相当のヘルパで `data-testid` を付ける
  （`/sankey-svg` の `E2E_TEST_IDS_ENABLED` と同じ方式に揃える。本番バンドルに残さない）

#### F2-US1: 文字サイズを変えられる

> 予算を調べる人として、事項名が小さすぎて読めないので文字を大きくしたい。
> 6列だとラベルが密で、既定サイズでは事項名がほぼ判読できないから。

**受入条件（機械判定）**

```ts
const label = page.getByTestId('hierarchy-label').first();
const before = await label.evaluate(el => parseFloat(getComputedStyle(el).fontSize));
await page.getByLabel('文字サイズ').selectOption('large');
const after = await label.evaluate(el => parseFloat(getComputedStyle(el).fontSize));
expect(after).toBeGreaterThan(before);
// 大きくしてもラベル同士が重ならない
await expect(page.getByTestId('hierarchy-label-overlap')).toHaveCount(0);
```

**補足**: 重なり判定は描画側で持たせる。`LABEL_SLOT`（現在 13px）を文字サイズに連動させ、
それでも重なる場合にだけ `data-testid="hierarchy-label-overlap"` を出す。
「重なっていない」を目視ではなく DOM で言い切れるようにするための仕掛けである。

---

#### F2-US2: ラベルの表示量を選べる

> 予算を調べる人として、全ノードの名前を出すか、大きいものだけにするかを切り替えたい。
> 全部出すと潰れ、出さないと何の図か分からないという両方の不満があるから。

**受入条件（機械判定）**

```ts
const few = await page.getByTestId('hierarchy-label').count();
await page.getByLabel('ラベル表示').selectOption('all');
const many = await page.getByTestId('hierarchy-label').count();
expect(many).toBeGreaterThan(few);
```

`/sankey-svg` の `すべてのノードラベルを表示` に相当する。既存の挙動に名前と粒度を合わせる。

## 4. ループの回し方

### 1周の定義

```text
1. バックログ最上位の US を1本取る
2. 受入条件をテストとして先に書き、失敗することを確認する（赤の確認）
3. 実装する
4. 検証チェーンを流す:
     npm run lint && npx tsc --noEmit && npm test && npx playwright test
5. 全部緑 → コミットして次の US へ
   赤    → 原因を直して 4 に戻る
```

手順2の「赤の確認」を省かない。これを飛ばすと、常に真を返すテストを書いて緑にしてしまう事故が起きる。
テストが一度も赤にならなかった US は、受入判定として無効である。

### 停止条件（人間に上げる条件）

エージェントが自分で判断を続けてよい範囲を、あらかじめ閉じておく。

| 条件 | 動作 |
|---|---|
| 同じ US で検証チェーンが**2回連続**失敗 | 停止して報告。原因の推測ではなく実測ログを添える |
| 受入条件をテストで書けない US に当たった | **着手せず**「要human判定」に積み、次の US へ進む |
| スプリントの US を全部消化した | 停止して報告 |
| 製品コードを変えないと既存テストが緑にならない、と判断した | 停止して報告（テストを緩めて緑にしない） |

最後の1つが最も重要である。緑にする最短経路は常に「テストを緩める」であり、
自律ループはそこへ吸い込まれる。ここを塞がないとループは自分を騙し始める。

### 前スプリントとの違い

| | 前スプリント | 今回 |
|---|---|---|
| 受入条件 | 「イケてない」「まだまだです」 | `exit code 0` |
| 判定者 | 人間（毎周） | コマンド（毎周）→ 人間はエピック完了時のみ |
| 1周の長さ | 人間の応答待ちに律速 | 検証チェーン ≒ 2分 |
| 失敗の扱い | 次の指示を待つ | 停止条件に従って自己判断 |

### この分解の限界（正直に書いておく）

**「読みやすい」は機械判定に落とし切れない。** F2-US1 の受入条件は
「文字が大きくなった」「重なりが0件」までしか言えず、「読みやすくなった」は言えていない。
これは分解の不備ではなく、自動判定の原理的な上限である。

したがって現実的な運用はこうなる。

- **ループが回すのは「言い切れる部分」**（描画が壊れていない、操作が効く、重なりが無い、回帰が無い）
- **人間が判定するのはエピック完了時の1点**（§2 のアウトカム）

「全部を自律で」ではなく「人間の判定回数を、US 4本ぶんから エピック1回に減らす」のが、
このスプリントで検証したい仮説である。

## 6. 未確定事項

- **F2-US1 の文字サイズ UI の形**: `/sankey-svg` は数値入力、本案はセレクト（`selectOption('large')`）を前提に書いた。
  `/sankey-svg` に揃えるなら受入条件の書き方も変わる。実装時に既存 UI を実測して合わせる。
- **`hierarchy-label-overlap` の判定精度**: 実測した描画幅ではなく `LABEL_SLOT` ベースの近似で判定する想定。
  日本語の文字幅は等幅でないため、近似が甘いと重なりを見逃す。まず近似で入れ、見逃しが出たら実測に切り替える。
