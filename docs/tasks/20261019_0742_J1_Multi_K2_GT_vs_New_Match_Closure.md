# J1 複数 × K2 の visual GT と新しい突合の突き合わせ、#462 のクローズ

状態: 完了（参考値）。有効な GT（annotator A）の「事項 → 項」は、新しい MOF 突合の request 側の階層と 85%（34/40）一致。#462 の評価は行わず、旧い J1 方式の「複数 142 行の昇格」は不要として #462 を閉じる。

## 背景
- #462 は、旧い突合（明細表の J1 と K2）で J1 に複数候補があった FY2025 の 147 行を、blind visual GT（annotator A・B と adjudication）で検証する準備だった。GT は暫定（凍結前）で止まっていた。
- その後、突合は TOC → 総表 → 明細表の位置で階層をたどり、名称の完全一致だけで MOF に対応づける方式（`mof-budget-request-match.md`）に置き換わった。J1 複数の昇格は、この方式では対象にならない。
- B と adjudication の GT は、窓の外を参照した疑いで無効（`#462` の記録）。有効なのは A だけ。

## 方法
`scripts/research/compare-visual-gt-with-mof-match-hierarchy.py`。GT の RESOLVED の各行を明細表 CSV の行にたどり、事項のコードと名称で m2-jikou の行を探して、`toc_kou_idx` から m1-kou の項（コード・名称）を得る。GT の項コード・項名と比べる。同じコード・名称の事項が 1 つの source に複数あると親が複数になる。そのときは、どれか 1 つが一致すれば一致とする。

```bash
git show pr462:tests/fixtures/detail-table-j1-multi-k2-visual-gt/2025/gt-a.csv > /tmp/gt-a.csv   # pr462 = #462 の head（856b655c）
python3 -I scripts/research/compare-visual-gt-with-mof-match-hierarchy.py /tmp/gt-a.csv 2025
```

## 結果（FY2025 × MOF 2025 の突合）
| GT | RESOLVED | 行が見つかった | 一致 | 不一致 | 行なし |
|---|---:|---:|---:|---:|---:|
| A（有効） | 43 | 40 | 34（85.0%。うち親が複数で 1 つが一致 3） | 6 | 3 |
| 暫定（A・B・adjudication 混在。無効なラベルを含む） | 100 | 97 | 82（84.5%） | 15 | 3 |

- 行なし 3 は、事項の名称が複数行に折り返された行（T105〜T107）。
- 不一致 6（A）は、いずれも新しい突合の親が MOF の事項にも対応づいている（status MATCHED、主要経費コード一致）。GT が窓の制約で別の項を選んだ可能性がある。どちらが正しいかは判定していない。
- 暫定 GT の不一致の多くは、B と adjudication 由来の同じ項（`374` 附帯・受託工事費、15 行中 12 行）。

## 限界
- 参考値であって評価ではない。GT は凍結前で、A 1 名のラベル。事前登録の判定基準（95%）は旧い方式のもので、新しい方式の基準は決めていない。
- 母集団は、項が窓（対象頁と前の 5 頁）の中にある行だけ（A の RESOLVED 43、全 147 行の 29%）。全体の精度は表さない。

## 結論
- 新しい突合の「事項 → 項」は、この範囲ではおおむね妥当。新しい GT の取り直しはしない。
- 旧い J1 方式の「複数 142 行の昇格」は、新しい方式に置き換わったため不要。#462 はクローズする（ブランチと GT は履歴に残る）。
