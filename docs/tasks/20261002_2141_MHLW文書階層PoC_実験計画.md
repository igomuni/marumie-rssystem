research repo の Engine Selection Research（merge `6ff0b08`）の next experiment（report §21.9–21.10）の実験契約。engine選定ではなく、概算要求PDFの文書階層（組織→項→要求）を、pdf.js由来の SourceToken / TableGeometry / LogicalRow だけから復元できるかを検証する。成果物は PoC の観測 artifact であり、最終 schema ではない。

## Hypothesis

文書自身の見出し構造（左端コードの形・x インデントの階段・文書順）を、総表と明細の両方で、ページをまたいで追えば、組織→項→要求の親エッジを、GT・コード値のlookup・上位凍結層なしで復元できる。親見出しが再掲されないページ（例: 物理 p1595 の 189、p1600 の 193）では、文書順の見出し stack が前ページの親へ辿る。過年度表など見出し形状を持たない行は親にならない。

## Inputs

- SourceToken → TableGeometry → LogicalRow（#355–#357）のみ。pdf.js 5.4.296。
- 対象: MHLW `05-1b-01.pdf`（manifest の canonical URL）。
- 総表view: 物理 p19–p20。明細view: 物理 p1555–p1700（070 と 080 の部分木を覆う範囲。目次の頁数から決めた**走査範囲の指定**であり、親子関係は注入しない）。
- view（summary / detail）は入力として与える（ページ種別の自動判別は今回の対象外）。

## Development / Holdout（実装前に固定）

- development: 組織 070 の部分木（拡張GT 16ノード、research GT 8ノード）。
- holdout: 組織 080 の部分木（拡張GT 21ノード、research GT 3ノード）。
- 閾値・ルールは development の観測だけで決める。holdout 結果を見てルールを足して再採点しない。追加iterationをする場合は v1/v2 に分けて記録する。
- **開示**: 計画固定前の探索で、holdout の先頭ページ（p20 と p1603 の見出し行）を目視していた。したがって p1603 と p20 は弱いholdoutで、holdout の主な根拠は未観察の p1604–p1700（要求 196–206、項 015–045）。

## Allowed evidence

x位置（key token の xMin）、縦順序、行の形（先頭トークンの形）、コードの形（3桁 / 要求番号+NN-NN）、文書順、ページ遷移、総表の頁数列（印字された page reference）。

## Forbidden evidence

GT（research / 拡張）、コード値のlookup（070・010・186 等を条件にしない）、「code 010 だから項」のような規則、目次の親子関係、SpatialRegion / RegionRelation / SemanticRecordCandidate / RecordAnchor / PageTemplate の出力、金額の解釈（△/▲/- の推定、blank→0、差額計算）。

## Method（v1）

1. 各ページを下位3層に通し、LogicalRow の先頭トークンから見出し候補行を拾う。形A=先頭が `^\d{3}$` で後続あり、形B=先頭が `^\d{1,3}$` で2番目が `^\d{2}-\d{2}$`。key token は A=先頭、B=2番目（コード）。
2. view ごとに key token の xMin を文書内で単一連結クラスタリング（隣接差 ≤ 0.25×基準フォントサイズ。基準=各ページ基準サイズの中央値）。支持が2行未満のクラスタは階層位置を与えない（unplaced）。クラスタをx昇順に並べた順位を level とする。
3. 文書順（ページ昇順→行順）に stack で処理。level 以上の stack top を pop し、残った top を親候補とする。level が連続（親=子-1）なら `resolved_by_indent_sequence`、飛ぶなら `level_gap`（ambiguous）、親無しなら `unresolved`。祖先候補（stack全体）も保持する。
4. 各 node / edge は sourceRowRefs・sourceTokenRefs（SourceToken.index / LogicalRowCandidate / PhysicalRowCandidate）を持つ。

x-clustering 係数 0.25 は、development の観測で detail の階段が約1em（6.9pt）、総表が約0.5em（3.45pt）刻みだったため「刻みより十分小さいサブem揺れ」として置いた document 内部の比。Golden に合わせた微調整はしない。

## Expected outputs

`data/work/budget-request-document-hierarchy/{year}/{view}.json`（PoC schema `budget-request-document-hierarchy-poc/v1`。`data/derived` へは昇格しない）。

## Metrics（development / holdout を分け、x/N 併記）

exact parent edge、exact ancestor relation、hierarchy depth、false parent、unresolved、parent edge precision / recall / F1。研究GT部分集合と拡張GTを別集計。評価は推論と分離した evaluator（GTを読むのは evaluator のみ）。

## Stop conditions

report §21.10 と指示書 §24 に従う。下位3層に必要情報が無い／body側から復元する根拠が不足／holdout で一般化しない／GTを見ないとルールを決められない／コード値の lookup が要る／凍結層へ戻らないと成立しない → 場当たり修正せず STOP して不足evidenceを報告。結果をよく見せるための基準変更はしない。

## 下位3層の確認（§14、実測済み）

p19 / p1555 / p1603 で SourceToken・LogicalRow に見出しトークンの rawText・x位置・行参照が残ることを確認。detail の見出し格子は 51.8/58.7/65.6/72.5/79.4（約6.9pt刻み）、総表は 62.1/65.6/69.0（約3.45pt刻み）。p1555 の過年度表の行（物理行13–33）は見出し形状を持たない。STOP条件には該当しない。
