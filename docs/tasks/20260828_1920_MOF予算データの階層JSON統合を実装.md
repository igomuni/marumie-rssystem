# MOF予算データの階層JSON統合を実装

`docs/tasks/20260828_1719_MOF予算データの階層JSONスキーマ案.md`で設計した、項を頂点に
事項・目を子として持つ統合JSONを実装した。既存の事項・目それぞれの生成物を維持したまま、
それらを統合するだけの新しいマージ専用スクリプトとして追加している（スクレイピング・
CSV解析ロジックには一切手を入れていない）。

## 実装

- `scripts/mof-classification-tables.ts`（新規）: 目的別・財政法公債金対象非対象別・
  経済性質別の3分類コード表（`docs/mof-budget-data-guide.md` 4-3〜4-5節）
- `scripts/generate-mof-kou-moku-data.ts`: 上記3分類を追加で読み込むよう拡張
  （CSVには列として存在するのに今まで読んでいなかった。特別会計は財政法が無く、
  政府関係機関は3つとも無い）。`types/mof-kou-moku.ts`の`MOFKouMokuItem`に
  `objectiveCode/Name`・`fiscalLawCode/Name`・`economicNatureCode/Name`を追加
- `types/mof-budget.ts`（新規）: 統合スキーマ（`MOFSection`が`jikou[]`・`koumoku[]`を子に持つ）
- `scripts/generate-mof-budget-data.ts`（新規）: 既存の`mof-jikou-{年度}.json`・
  `mof-kou-moku-{年度}.json`・`mof-section-pages-{年度}.json`を読み、項単位へ結合して
  `mof-budget-{年度}.json`（本体）・`mof-budget-descriptions-{年度}.json`（事項の説明文、
  長文のため分離）を出力する

## スキーマ案からの変更点

- `sourceUrl`は出典ページを特定できないとき空文字列（帳票トップURLでは埋めない。
  以前の指示どおり）

## 検証

新しく生成した`mof-budget-2024.json`の`sections`配列と、既存の`/api/mof-kou?year=2024`
（`app/lib/api/mof-kou-loader.ts`が独自に項単位へ集計したもの）を突き合わせ、
`id`・`amount`・事項数・目数・出典ページが**3,321件全件で完全一致**することを確認した
（2つの独立した実装が同じ結果になることの相互検証）。10年度分すべて生成済み。

## まだやっていないこと（意図的にスコープ外）

**`/mof-jikou`・`/mof-kou-moku`・`/mof-kou`の各ページ・ローダーはまだ新しい統合ファイルを
読んでいない**。既存の3ファイル（`mof-jikou-*`・`mof-kou-moku-*`・`mof-kou-loader.ts`の
実行時結合）を引き続き使っている。理由:

- 既存パイプラインは安定して稼働しており、ローダーの移行は独立したリスクのある変更
- 統合ファイルの正しさをまず検証してから移行するほうが安全（今回の検証で担保できた）
- ローダー移行（3ファイル読み込み→1ファイル読み込みへの置き換え、フラットビューの
  導出方法の決定など）は、そのぶんの動作確認とセットで別途行うのが適切

新しい`mof-budget-{年度}.json`は現時点では「検証済みの正準データ」として存在するのみで、
実際にアプリが依存する形にはまだなっていない。ローダー移行を進めるかどうかは別途判断。
