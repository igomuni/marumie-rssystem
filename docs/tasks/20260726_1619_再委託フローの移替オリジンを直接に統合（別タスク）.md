# 再委託フローの「移替」オリジンを「直接」に統合（別タスク・要データ再生成）

## 背景・要望（2026-07-26）

再委託フロー図・支出先タブで、フローのオリジン種別に「移替」バッジが出るが**違和感がある**。
「直接」にした方が自然、という要望。ユーザー確認済み。

パイプライン修正（＝データ再生成）を伴うため、UI改修（Top揃え・凡例削除・座標系）とは分けて
**別タスク**として実施する。

## 現状の仕組み

- **型**: `FlowOrigin`（`types/subcontract.ts`）に `'transfer'` がある。
- **分類（パイプライン）**: `scripts/generate-subcontracts.ts`
  - L124: `const TRANSFER_KEYWORDS = /移替/;`
  - L451: `origin = rf.hasTransferNote ? 'transfer' : 'direct';`
    （再委託先ノートに「移替」を含むフローを `transfer` に分類。含まなければ `direct`）
- **UI 表示（`app/subcontracts/[projectId]/page.tsx`）**:
  - フロー行ラベル L1063 `{flowOriginLabel(f.origin)}`（'移替'）
  - ツールチップの TagChip L2472 `flowOriginToTagKind(rf.origin)` / `flowOriginLabel`
  - フローフィルタのボタン L662 付近 `['transfer', '移替']`
  - `flowOriginLabel`（L146）/ `flowOriginToTagKind`（`client/components/subcontract/origin-kind`）

## 対応方針（案）

「移替」を独立オリジンとして扱わず「直接」に統合する。**データ再生成が必須**。

1. **パイプライン**: `generate-subcontracts.ts` L451 を `origin = 'direct'`（transfer 分類を廃止）に。
   - `hasTransferNote` / `TRANSFER_KEYWORDS` が他で使われていなければ併せて整理。
   - `/data-update` スキルの作法で JSON 再生成 → `.gz` 更新 → 検証。
2. **UI**: フローフィルタから `['transfer','移替']` を除去。`flowOriginLabel`/`flowOriginToTagKind`/型 `FlowOrigin`
   から `'transfer'` を削除（型を消す場合は残参照を掃除）。
3. **検証**: 旧 `transfer` フローが `direct` として表示され、バッジ・フィルタから「移替」が消えること。
   金額・本数の合計が変わらないこと（分類変更のみで集計は不変のはず）。

## 留意

- **データ整合性優先**（memory: パイプライン精度が最優先・近道禁止）。UI だけで transfer を「直接」と
  ラベル偽装する対応は取らず、データ分類そのものを直す。
- 「移替」は府省庁間の予算移替。ドメイン的に「直接」に含める判断はユーザー合意済み。
- 影響範囲: 再委託フロー図・支出先タブのみ（メイン `/sankey-svg` は無関係）。
