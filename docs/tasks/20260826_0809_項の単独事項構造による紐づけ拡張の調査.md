# 項の「単独事項」構造による MOF↔RS 紐づけ拡張の調査

## きっかけ

ユーザーが `/sankey-svg` で「労働条件の確保・改善に必要な経費」（厚生労働本省 PID:2397）を見たところ、予算・執行の内訳に MOF の目名（監督旅費・参考人等旅費・委員手当…）がそのまま現れていることに気づいた。RS の `2-2_予算・執行_予算種別・歳出予算項目` は `所管/組織・勘定/項/目` を MOF と同じ語彙で持つ（既存実装 [generate-mof-rs-linkage.ts](../../scripts/generate-mof-rs-linkage.ts) の構造キーそのもの）。この気づきを起点に、項の構造だけで事項↔事業の紐づけを増やせないか調査した。

## 仮説

**項に事項が1件しかないなら、名前が一致しなくてもその項に計上されたRS事業は構造的にその事項に属する。**

根拠: MOF の一般会計歳出は100%が何らかの事項に属する（[20260818_2138](20260818_2138_MOF側にRS事業名に相当する項目はあるか.md) §7-1で実証済み・0.014%差）。つまり事項別内訳は項の予算を漏れなく分割している。項の下に事項が1件しかなければ、その項の全額（＝定義上100%）がその1件の事項に帰属する。これは名前の一致・不一致とは無関係に成り立つ会計構造上の必然。

## 実測（予算年度2024・一般会計・当初予算）

### 1. MOF側: 項に事項が1件だけの割合

```text
構造キー（所管×組織×項名）総数: 784
  単独事項（1件）: 575件 / 47.04兆円
  複数事項（2件以上）: 209件 / 65.53兆円
```

7割以上の項が単独事項。ただし金額は複数事項側（大口項目が集中）が上回る。

### 2. RS側: 単独事項キーに乗るRS事業の量

```text
対象RS事業: 3,861 / 42.22兆円（一般会計・当初予算・予算年度2024）
単独事項キーに乗る事業: 1,335事業（重複除く）/ 11.19兆円
  うち既に「事業名==事項名」で一致済み: 63件
```

### 3. 金額の整合性チェック（RS合計 vs MOF事項額、単独事項キーのみ）

新手法を「確定」扱いしてよいかの裏取り。RS側の項ごとの予算合計が、対応するMOF事項の金額を超えていないか（＝キーの取り違えがないか）を確認した。

```text
RS合計 > MOF事項額×105%（キー不一致の疑い）: 0件
RS合計が MOF事項額の 50%未満: 24件（405件中）
RS合計が MOF事項額の 50%〜105%: 381件
```

超過は0件。多くはほぼ一致（ratio=1.00の例が多数）。50%未満の24件も「その事項に属する」という結論自体は揺るがない（RS事業側が事項の予算全額を捕捉していないだけで、対応する事項が単独である事実は変わらない）。

### 4. 既存手法との比較（名前一致+語幹一致 vs 構造拡張後）

```text
既存手法（構造キー内 名前完全一致+語幹一致）:
  226事業 / 14.04兆円（33.3%）

既存手法 + 単独事項構造リンク:
  1,401事業 / 23.03兆円（54.6%）
```

事業数で6.2倍、金額カバレッジで21.3ポイントの増加。

## 結論と実装方針

単独事項リンクは名前照合ではなく構造的必然（MOFの会計上の完全分割性）に基づくため、`status: confirmed` として扱ってよい。ただし監査可能性のため既存の `exact-name` とは別の `method` 値として区別する。

- 新規 `method: 'section-unique'`（項に事項1件のみ→構造的に確定）を追加
- 優先順位は `manual > exact-name > section-unique > stem-in-name > exact-name-cross-section`
  （名前が実際に一致する場合はより直接的な `exact-name` を優先表示するが、判定結果としての confirmed 扱いは変わらない）
- 複数事項の項（209件・65.53兆円）は従来どおり名前照合 or 意味的照合（未実装）に委ねる

**2026-08-26 追記**: 実装済み。`scripts/generate-mof-rs-linkage.ts` に `section-unique` 判定を追加し、`npm run generate-mof-rs-linkage` で再生成。実測どおり事業カバレッジ 33.3%→54.6%（14.04兆円→23.03兆円）に拡大したことを確認。

**2026-08-26 追記2**: MOF側にも項・目の一覧ページ `/mof-kou-moku` を新設した（`/mof-jikou` の項・事項と対になる項・目のビュー）。ZIP同梱の科目別内訳CSVをそのまま使うため事項のようなスクレイピングは不要。生成は `npm run generate-mof-kou-moku`（`scripts/generate-mof-kou-moku-data.ts`）。ZIPがローカルに当初予算しか無いため当初予算のみ・10年度分（2017〜2026）を収録。一般会計の合計金額（112.57兆円・令和6年度）は既存実測（本書§7-1、20260818_2138 §7-1）と一致することを確認済み。

**2026-08-26 追記3**: 目レベルでの直接突合を実装した。RS の `2-2` CSV が所管/組織・勘定/項/目をMOFの科目別内訳と**同じ語彙**で持つため、事項と違って名前照合・語幹一致は不要で、**完全一致キーで直接突き合わせられる**。実測（予算年度2024・一般会計・当初予算）:

```text
RS行の一致率: 9,496 / 10,242 行（92.7%）
金額の一致率: 41.31 / 42.22 兆円（97.9%）
事業カバレッジ: 3,597 / 3,861 事業（93.2%）
```

事項側の紐づけ（`section-unique` 等）より遥かに高いカバレッジで、かつ誤検出が原理上ない（完全一致キーのため）。`scripts/generate-mof-rs-kou-moku-linkage.ts`（`npm run generate-mof-rs-kou-moku-linkage`）で生成し、`/mof-kou-moku` にRS列・RSフィルタ・詳細パネルとして表示。事項側の紐づけ（事業↔MOF事項）とは別のデータセット（事業↔MOF目）として独立させている（対象entityが違うため）。

**2026-08-26 追記4**: `/mof-kou-moku` の予算種別を「当初予算のみ」から `/mof-jikou` と同じ当初・暫定・補正・決算のフル対応に拡張した。当初のZIPしか調べていなかったが、実際は補正（21xxx/22xxx、号数は年度で変動）・決算（76001/77001/78001）のZIPもローカルに大半の年度分あり、暫定（31001/32001/33001）も令和8年度分だけ存在した。列構成が予算種別ごとに異なる（補正は成立予算額/改予算額/差引額の3本、決算は円単位で歳出予算現額・支出済・繰越・不用額を持つ）ため `generate-mof-kou-moku-data.ts` を全面書き換え。`MOFBudgetType`（`types/mof-jikou.ts`）を共有し、予算種別セレクタをページに追加。RS紐づけ（`generate-mof-rs-kou-moku-linkage.ts`）は引き続き一般会計・当初予算のみ対象（RS側の予算種別表記がMOFと異なる：「第1次補正予算」対「補正予算（第1号）」等のため、拡張には変換テーブルが別途必要）。

**2026-08-26 追記5**: ユーザーが「基礎年金給付費」で検索したところ紐づかないケースを発見。原因は紐づけスクリプトが一般会計のみ対応で、特別会計（基礎年金給付は年金特別会計・基礎年金勘定）を除外していたため。RSの `2-2` CSVは特別会計だと `所管/会計/勘定` という一般会計とは別の列を使う（`組織・勘定` は `勘定` と重複するため使わない）ため、キー構成を会計区分で分岐して特別会計にも対応した。

実測（予算年度2024・当初予算）:

```text
一般会計単独: 行92.7%・金額97.9%（既出）
特別会計単独: 行86.6%・金額98.9%（新規実測。1,225目中645事業がヒット）
合計（一般＋特別）: 行91.8%・金額98.6%・事業4,205/4,602（91.4%）
```

「基礎年金給付に必要な経費」（PID:2826）が `special|年金|基礎年金勘定|基礎年金給付費|基礎年金給付費` の完全一致で30.04兆円リンクすることを確認。政府関係機関はRSの `会計区分` に該当値が無いため対象外のまま。

**2026-08-26 追記6**: 「当初予算以外も紐づけしてほしい」との指示で、RSの他予算種別（第1次補正予算・前年度から繰越し・予備費等1〜4）を調査。

```text
第1次補正予算    : 行94.4%・金額88.5%が一致（MOFの「補正予算（第1号）」に対応）
前年度から繰越し  : 0%（RS側の所管/組織・勘定/項/目が全行空欄。突合対象データが無い）
予備費等1〜4      : 0%（同上）
```

「前年度から繰越し」「予備費等N」はRSの `2-2` CSVで科目情報そのものが記録されておらず（`予算額` だけが単独で載る）、原理的に項×目キーでは突合不可能と判明。実装は第N次補正予算（RS）↔補正予算（第N号）（MOF）の対応だけを追加した。

結果（予算年度2024・当初予算＋補正予算）:

```text
行カバレッジ: 13,070 / 14,179（92.2%）
金額カバレッジ: 131.39 / 134.70兆円（97.5%）
事業カバレッジ: 4,536 / 4,892（92.7%）
```

「物価高騰対応重点支援地方創生臨時交付金」（PID:7629、補正予算第1号・1.74兆円）等で正しくリンクすることを確認。

**2026-08-26 追記7**: 「紐づいている予算は金額で見て一致するか」との質問を受け、目単位でRS計上額の合計とMOF側の金額を突き合わせた（紐づいた目4,897件が対象）。

```text
誤差0.1%未満で完全一致: 3,023件（61.7%）
RS計上額がMOF金額より少ない: 1,800件（36.8%）— 正常。RSは目の予算全額を個別事業に割り振るとは限らない
RS計上額がMOF金額を超過: 74件（1.5%）— 異常値
```

集計すると、紐づいた目のMOF金額合計157.55兆円に対しRS計上額は131.39兆円（83.4%）。差額26.15兆円は「RS側が目の全額を特定事業に紐づけていない」という正常な差で、超過側の異常値はわずか0.55兆円分。

超過の異常値を1件検証（経済産業省・補正予算第1号「国立研究開発法人新エネルギー・産業技術総合開発機構一般勘定運営費交付金」）: MOFの生CSVでは253.57億円（改令和6年度予算額）だが、RSは4事業（うちPID:19958「先端半導体の国内生産拠点の確保」が4,713.9億円）で合計4,841.9億円を同じ所管×組織×項×目に計上しており、約19倍のズレがある。MOF側の値はZIP原本と一致（パースミスではない）ため、原因はRS側の項/目記載（大型の半導体補助金を実態と異なる科目名で登録している可能性）とみられる。件数・金額とも僅少（74件・0.55兆円）だが、金額検証の指標として `rsAmount(合算) / kouMokuAmount` の乖離率は将来的に紐づけの信頼度スコアとして使える。
