# RS Normalize 全15CSV対応完了と全件一致検証

前回（`20260920_1708_...`）の4件修正・budgetMinistry分離に続き、残り9データセット（1-3/1-4/1-5/3-1/3-2/4-1/5-3/5-4/6-1）とreview-sheetsマージを実装した。ブランチ `feat/pipeline-v2-mof-source-preserving`、コミット`c94c816`。

## 実装内容

- **1-3(policies-laws)/1-4(subsidy-rules)/1-5(project-relations)/3-2(logic-model-relations)/4-1(evaluations)/5-3(expense-uses)/5-4(multi-year-contracts)/6-1(notes)**: 1行入力→1行出力のためstreaming generator化（既存の1-1/1-2/2-2と同じ設計）。
- **3-1(logic-model)**: 「アクティビティ・アウトプット・アウトカムの番号＋種別」が同一の行をnode（`logic-model-nodes.jsonl`）へ集約し、20xx形式の年度別実績列を観測値（`logic-model-observations.jsonl`）へ分離する（5-1のblock集約と同じ考え方）。
- **review-sheets**: download-csv ZIPとは別に、`sheets/{year}/**/*.csv`を再帰的に読む専用の正規化（`rs-review-sheets.ts`）。様式1（前年度事業・新規開始事業）・様式2（新規要求事業）のみを対象とし、様式3・4は`ignoredFiles`に記録して対象外にする。
- **mergeProjects()のreview-sheetsマージ**: 1-2 CSV側の値を優先し、空欄の項目（projectName/startYear/endYear/accountClass/officialProjectUrl）のみレビューシートで補完する。値が食い違う場合は断定せず`project-sheet-conflicts.jsonl`へ記録し、1-2側の値を残す（Python参照実装の`_merge_projects`と同じロジック）。

### 参照実装との既知の意図的な相違

1-2側で同一projectIdが複数行に現れる場合、Python参照実装は最後の行の`sources`で完全に上書きし、それ以前の行の証跡を失う。TS実装はsource-preservingの原則を優先し、`sources`を蓄積して全ての重複行の証跡を残す（レコード件数には影響しない）。

### sheets-only年度（2026等）の扱いの変更

前回（`20260920_1708`）はCSVバルク未公開のsheets-only年度を丸ごとスキップしていたが、review-sheets実装により部分的な出力が可能になったため、`normalize-rs.ts`の`main()`を変更し、sheets-onlyの年度もprocessYear()の対象に含めるようにした。zipベースのデータセットは0件のままだが、`review-sheets.jsonl`・`projects.jsonl`（レビューシート由来の事業）は生成される（Python参照実装と同じ挙動）。
