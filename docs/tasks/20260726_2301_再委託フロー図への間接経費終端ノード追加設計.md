# 再委託フロー図への間接経費終端ノード追加（設計）

対象: `/subcontracts/[projectId]` のリボン（サンキー風）フロー図＋側パネル。
20260722_0818 の「対応アイデア（未着手）」3点をまとめて設計する。

## 目的

**「この事業の支出はどこへ行ったのか」を見に来た利用者が、図に描かれない支出（間接経費）の存在に
気づけないまま「支出＝支出先への支払い」と誤読する状態を解消するため。**

現状、国が直接支払う間接経費（講師謝金・委員等旅費・事務費など）は支出先ブロックを持たないため
フロー図に一切現れない。事業単位では直接費の1割を超えることもあり（PID:1 2025 で約11%）、
図の外に落ちていることが利用者からは見えない。図の中に終端ノードとして描いて金の流れを閉じ、
同じ数字を側パネル（ヘッダ内訳・間接経費タブ）でも一貫して見せる。

## データ前提の確認（実測）

`scripts/generate-subcontracts.ts:154-176` は、5-2 CSV の間接経費行を
「targetBlock が空 → `indirectCosts[]` へ退避して flows から除外」「targetBlock がある →
flows にも残しつつ `indirectCosts[]` にも寄せる」の2経路で処理している。後者があると
「フローに乗っている分」と二重計上になるため、実データで比率を確認した。

| 年度 | 間接経費行 | うち targetBlock あり | 合計金額 | 事業数 |
|------|-----------|----------------------|---------|--------|
| 2024 | 2,359 | **0** | 57,161,676,374円 | 1,046 |
| 2025 | 2,432 | **0** | 32,896,230,966円 | 1,045 |

**結論: 現行2年度のデータでは間接経費行はすべて targetBlock が空**。すなわち
`graph.indirectCosts[]` は全件がオフサンキー（＝フローに一切現れない）で、
そのまま合計してよい。二重計上は起きない。

ただしパイプライン側の「targetBlock あり」分岐は将来データで発火し得るため、
無防備に合計する実装は残さない（下記 D-1）。

## スコープ

- 対象は **リボンビュー（`viewMode === 'ribbon'`、フロー図）のみ**。カードビュー
  （`app/lib/subcontract-layout.ts` の A案）は今回変更しない。
- 側パネルは「事業ヘッダの支出内訳」と「間接経費タブの扱い」の2点。
- `/subcontracts` 一覧ページ（絞り込み・列追加など）は対象外。

## D-1. データ層: オフサンキー判定の明示化

`types/subcontract.ts` の `IndirectCost` に任意フィールドを1つ追加する。

- `attachedToBlock?: boolean` — 対応する支出先ブロック（targetBlock）を持つ行か。
  パイプラインは targetBlock ありの経路で `true`、空の経路で `false` を書く。

集計側（D-2）は `attachedToBlock !== true` の項目だけを「オフサンキー間接経費」として合計する。
既存 JSON はこのフィールドを持たないが、実測どおり全件 targetBlock 空なので
`undefined` → オフサンキー扱いで正しい値になる。**したがって本設計の実装に
JSON 再生成は必須ではない**（次回のデータ更新時に自然に埋まる）。

`scripts/` の変更は CSV → JSON の写像のみで、UI・API ロジックは持ち込まない（Layer Design Rules 準拠）。

## D-2. ドメイン層: 集計ヘルパ

`app/lib/subcontracts/` に純関数を1本置く（HTTP・React 非依存）。

- 入力: `IndirectCost[]`
- 出力: `{ total: number; count: number; items: IndirectCost[] }`
  - `total` は `amount > 0` の項目のみの合計（負値・空欄は 0 扱い）
  - `items` は金額降順（ツールチップの上位表示用）
  - `attachedToBlock === true` の項目は除外する

ヘッダ内訳・タブバッジ・レイアウト計算はすべてこの1本を参照し、数字がずれないようにする。

## F-1. フロー図: 間接経費の終端ノード

### 位置づけ

- **列**: depth 1（現状の「支出先」列）。事業ノードから直接出る兄弟として扱う。
- **縦位置**: 直接系バンド群の**最下段**（direct/subcontract の depth1 バンドをすべて置いた後、
  別財源レーンより上）。別財源レーンの基準となる `directContentBottom` は
  この終端ノードの下端も含めて算出する。
- **形**: 他ノードと同じスリムバー（幅 `RIBBON_BAR_W`）。高さ = `total * k`。
- **色**: 支出先でも別財源でもないことを示すニュートラルグレー（既存の
  `COLOR_REFERENCE_EDGE` 系のグレー階調に合わせる。赤＝直接／橙＝再委託／紫＝別財源／緑＝予算 と
  意味色が埋まっているため、間接経費は無彩色で「受け手が無い」ことを表す）。
- **ラベル**: `間接経費（国が直接支出） (金額)`。既存の `truncateRibbonLabelName` を通す。
- **下流を持たない終端**。クリックしてもブロック選択には入らない。

### レイアウト出力の追加（`app/lib/subcontract-ribbon-layout.ts`）

`SubcontractRibbonLayout` に以下を追加する。ブロックバー（`bars`）や `flows` には混ぜない
（`blockId` を持たない別種のノードなので、`barByBlockId` などブロック前提のロジックを汚さない）。

- `indirectNode: { key: '__indirect__'; label: string; amount: number; count: number; x, y, w, h } | null`
- `indirectFlow: { x1, y1Top, y1Bot, x2, y2Top, y2Bot } | null`（事業ノード支出側 → 終端ノード）

生成条件: `total > 0`。`total === 0`（行はあるが金額が全て0）の場合はノードを描かない
（タブ側では件数を出す）。

### 既存計算への影響（すべて明示的に対処する）

1. **スケール係数 k**: `computeRibbonK(byDepth, extraColTotal)` の depth1 列合計に
   間接経費 `total` を加算する。加算しないと depth1 列の実描画高さが目標高さを超える。
   引数の増やし方は「列ごとの追加加算」を渡せる形にする（予算列の `extraColTotal` と同じ流儀）。
2. **事業ノードの支出側高さ `rootH`**: 現状は「ルートからの出口リボン太さの合計」。
   ここに間接経費リボンの太さ（`total * k`）を加える。結果として事業ノードのオレンジ側は
   「支出先ブロックへの流出＋間接経費」の合計高さになり、**図として金が閉じる**。
3. **リボンの積み順**: 事業ノードの出口カーソル（`outCursor[ROOT_KEY]`）は
   ブロック向けフローを積んだ**最後**に間接経費リボンを積む（縦位置がノード最下段と揃う）。
4. **SVG サイズ**: ブロックが1つも無く間接経費のみの事業では `byDepth` が空になり
   `maxColDepth = 0` のまま幅が depth1 列に届かない。`indirectNode` がある場合は
   depth1 列を含めた幅・高さを確保する。
5. **別財源レーン**: `directContentBottom` の計算に間接経費ノードの下端を含める（上述）。

### ページ側の描画（`app/subcontracts/[projectId]/page.tsx`）

- **ラベル衝突回避シフト**: `ribbonBarShift` は depth ごとに y昇順でシフトを計算している。
  間接経費ノードは depth1 の並びに（最下段として）加えて同じ計算に通し、
  得たシフトを `ribbonShiftOf('__indirect__')` として参照できるようにする。
  シフトを共有しないと、depth1 の少額ノードが下へずれた分だけ終端ノードと重なる。
- **ホバー**: `HoveredNode` に `{ kind: 'indirect' }` を追加。ツールチップは
  「間接経費（国が直接支出）／合計金額／件数／上位項目（category・kind・金額）数件」。
  リボン側のホバーも同じツールチップを出す（既存 `ribbonFlow` と同じ遅延・抑制ロジックに乗せる）。
- **クリック**: ブロック選択を解除したうえで、側パネルのタブを `indirect-cost` に切り替える。
  URL 同期は既存の `pushSelTabUrl(null, 'indirect-cost')`（短縮コード `ic`）をそのまま使う。
- **ディミング**: ブロック選択中は関連ブロック以外を減光しているが、間接経費ノードは
  どのブロックとも関係を持たないため、ブロック選択中は常に減光対象とする（既存の
  `isDimmed` と同じ濃度）。
- **列見出し**: depth1 列の見出し金額はブロック合計＋間接経費の合計にする
  （見出しの数字と描画高さを一致させるため）。列ラベル `支出先` は変更しない。

## F-2. 事業ヘッダの支出内訳（側パネル）

現状ヘッダは `予算額` / `支出額` の2列のみ（`page.tsx:549-562`）。ここに支出の内訳を足す。

- `支出額`（= `graph.execution`）の下に、既存のメタ行と同じ小さい書体で
  `支出先 {directExpenseTotal} ／ 間接経費 {total}` を併記する。
- 内訳は**合計が支出額に一致するとは限らない**（5-1 のブロック支出合計と 2-1 の執行額は
  出典が別）。したがって「支出額 = 支出先 + 間接経費」と読める式表現にはせず、
  ラベル併記に留める。予算・執行の乖離警告は `BudgetExecutionSection` 側に既にあるため、
  ここでは新たな警告は出さない。
- 間接経費が 0 件の事業では `間接経費` 側を出さない（`支出先` のみ）。

## F-3. 間接経費タブの扱い

`page.tsx:524-529` のタブ定義と本体（`940-968`）を次のように変える。

- **0件でも disabled にしない**。現状 `disabled: indirectCount === 0` で押せない＝存在自体が
  見えないが、「間接経費が無い事業である」ことも情報なので、開いて
  `間接経費の記録はありません`（既存文言）を読ませる。
- **タブに金額を出す**。現状のカウント表示（件数）に加えて、タブ本体先頭の説明行を
  `国自らが支出する間接経費 N件・合計 X円` にする。タブのチップ部分は幅が厳しいため件数のままとし、
  金額はタブ本体の先頭行で見せる。
- タブの並び順は変更しない（フロー／ブロック／支出先／間接経費）。
- フロー図の終端ノードから遷移してきた場合も同じタブを出す（F-1 のクリック挙動）。

  - 間接経費あり: `rootH` がブロック流出分＋間接経費分になること、`indirectFlow` の
