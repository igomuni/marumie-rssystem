# 項自体の出典ページを追加

これまで事項・目の明細には出典ページがあったが、項（`/mof-kou`のMOFSection）自体は
出典を持たなかった。「甲号歳入歳出予算」（一般会計）・「歳入歳出予算」（特別会計）・
「収入支出予算」（政府関係機関）という、事項別内訳・科目別内訳とは完全に独立した
別帳票（同じdocumentId内の別ページ・単独ファイル）から項名一致で突合し、項自体の
出典ページ・URLを取得できるようにした。

背景の調査は`docs/プロンプトログ.ignore.md`参照（ユーザーがPDF上の項目「p.28」の
出典を辿ろうとしたところリンクが無く、原因調査から発見）。

## 実装

- `scripts/generate-mof-section-page-data.ts`（新規）: 3種類の帳票を`title_for_list`で
  判別してパース。項コードを持たないため所管×組織/特別会計/勘定×項名の名前一致でのみ
  突合できる
  - 一般会計: 所管(1)｜組織(2)｜項(3)｜金額(4)の4列。皇室費のように組織欄が印字されない
    場合は所管をそのまま組織名とする（kou-moku側と同じ規約）
  - 特別会計: 所管(1)｜特別会計/勘定(2)｜款歳入(3)｜項歳入(4)｜金額歳入(5)｜項歳出(7)｜
    金額歳出(8)の8列。列2は列内連番1=特別会計名・連番2=勘定名を共有する
  - 政府関係機関: 機関(1)｜款収入(2)｜項収入(3)｜金額収入(4)｜項支出(6)｜金額支出(7)の
    7列。列1は列内連番1=機関名・連番3=業務区分を共有する
  - 出力: `mof-section-pages-{年度}.json`
- `app/lib/api/mof-kou-loader.ts`: `buildYear()`で項の集計後、上記データを
  所管×組織/特別会計/勘定×項名（正規化済み）で名前一致させ、`page`/`sourceUrl`を
  バックフィルする。同名の項が複数あって突合先が曖昧な場合は最初の1件のみ対象にする
- `types/mof-kou.ts`: `MOFKouSectionSummary`に`page: number | null`・`sourceUrl: string`を追加
- `client/components/mof-kou/KouSidePanel.tsx`: サイドパネルのヘッダーに
  「出典 p.NN」リンクを表示

## v1のスコープ外（意図的）

- **歳入側は未取得**。表には歳入の値も載っているが、対応する既存データ（事項・目とも
  歳出のみ）が無く単独では突合検証できないため見送った
- **当初予算のみ**。暫定・補正・決算は対象帳票の存在・`title_for_list`未確認
- **東日本大震災復興特別会計は非対応**。この特別会計だけ1つの行番号（例:
  `p41-420`）に複数の項を列内行連番（`420.1`・`420.2`…）でまとめて印字しており、
  共通実装`parseTable()`（`mof-budget-xml.ts`）がページ・行番号だけで行をグルーピング
  するため複数の項名が1行に混ざってしまう。事項別内訳・科目別内訳が使う共通実装への
  影響を避けるため、この会計だけ突合できないことを許容した（該当4〜7件・全体の1%未満）

アクセスは発生しなかった（既知のパターンの再現）。

| 2020 | 1,017 | 1,012 | 0 | 5 |
| 2024 | 996 | 991 | 0 | 5 |
| 2026 | 1,032 | 1,027 | 0 | 5 |

不一致0件（金額の実測誤差なし）。突合先が見つからない5〜7件はすべて東日本大震災復興
特別会計（既知の制約）。
