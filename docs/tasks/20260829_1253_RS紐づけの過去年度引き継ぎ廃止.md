# RS紐づけの過去年度引き継ぎ廃止

## 背景

MOF予算書↔RS事業の紐づけ（目単位: `mof-rs-kou-moku-linkage-{年度}.json`、事項単位: `mof-rs-linkage-{年度}.json`）は、対象年度自体のファイルが未生成の場合、直近の過去年度の紐づけを識別子突合で「参考値」として引き継いで表示していた。データ構造が新しくなったのに合わせ、この過去年度への引き継ぎを廃止する（ユーザー指示）。

なお RS_YEAR = MOF予算年度 + 1（例: MOF2024→RS2025）という**年度対応**自体は今回の対象外で、変更なし。

## 変更内容

- `app/lib/api/mof-rs-kou-moku-linkage-loader.ts`: `resolveLinks()` から過去年度フォールバック（識別子突合による引き継ぎ生成ロジック）を削除。対象年度自体にファイルが無ければ `{ available: false, links: [] }` を返すのみ。`LinkageResolution` から `isCarriedOver`/`sourceBudgetYear` を削除し `available` に統合。
- `app/lib/api/mof-kou-loader.ts`: `sectionDetail()` の事項単位RS紐づけ（`jikouRsLinkYear`）も同様に過去年度探索を削除。対象年度自体に無ければ空配列。`MOFKouSectionDetail.jikouRsLinkYear` フィールドを削除。
- `app/api/mof-kou-moku/linkage/route.ts` / `app/api/mof-kou/route.ts`: `sourceBudgetYear` 前提だった `rsYear` 解決を、リクエスト年度自体を使う形に簡略化。
- `types/mof-rs-kou-moku-linkage.ts` / `types/mof-kou.ts`: `isCarriedOver`/`sourceBudgetYear`/`jikouRsLinkYear` を型から削除。
- `app/mof-kou-moku/page.tsx` / `client/components/mof-kou-moku/KouMokuTable.tsx`: 引き継ぎ元年度を表示していたアンバーのバッジ・注記UIを削除。

## 変更しないもの

`carriedOverFrom`（`MofRsKouMokuLinkageRecord` の内部フィールド）は**別概念**なので維持。RSは決算（決算ベース執行実績）を目単位で持たないため、決算種別の目のRS紐づけは同一年度内の予算種別（当初・補正等）行から引き継ぐ仕組みで、年度をまたぐものではない。

## 確認

- `npx tsc --noEmit` / `npm run lint`: エラーなし（既存warningのみ）
- `GET /api/mof-kou-moku/linkage?year=2024`（自前データあり）: `available: true`, 24,223件で変化なし
- `GET /api/mof-kou-moku/linkage?year=2025`（自前データなし）: 変更前は2024年度から引き継ぎ表示していたが、`available: false`, 0件に変化（意図通り）
- `GET /api/mof-kou?year=2025` の `metadata.linkage`: `{ available: false, rsYear: null }` に変化
- `/mof-kou-moku` を2026年度で表示し、RS列がすべて「—」（紐づけなし）になることを確認
