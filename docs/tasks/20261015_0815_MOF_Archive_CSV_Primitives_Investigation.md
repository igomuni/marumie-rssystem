# MOF の archive から 項・事項・目 の CSV を作る — 検討

状態: 調査と提案（未着手。実装・取得はしていない）。結論: **項と目は、archive の公式 CSV から機械的に作れる。事項だけは CSV に無く、Web 帳票の XML が要る。FY2024 は CSV・XML・目次 HTML がすべて archive にそろっているので、FY2024 を最初の対象にする**（ユーザーの指摘どおり。FY2025 は XML が archive に無い）。

目的: 概算要求との突合で「項・事項の構造をどう作るか」が問題になったため、normalized の jsonl に頼らず、archive の原本から、人間が確認できる素朴な CSV（項・事項・目）を作る。

## 提案: 素朴な CSV を3つ（原本の形のまま、列名は原本の見出し、意味づけや推測はしない）

1. **`mof-kou.csv`**（項）: 所管、組織、項コード、項名。（`b.csv` の列から、そのまま一意にしたもの。行数は項の数。）
2. **`mof-moku.csv`**（目）: `b.csv` の全行を、列名もそのままにした CSV（元の行番号を足す）。
3. **`mof-jikou.csv`**（事項）: 所管、組織、項コード、項名、事項名、主要経費別分類コード、金額の列、原典の位置（XML のファイルと頁・行の id）。XML のセルの `id`（頁・行・列）を読むだけで表を再構成できる（ガイド）。

人間が確認しやすい形として、項ごとに「事項の一覧」と「目の一覧」を並べて見られる表示も考えられる。ただし、事項と目を対応づけない。

## 検証（対応づけを使わない、構造だけの整合）
- 項: CSV の項と、XML の項が、件数・コード・名称で一致すること（FY2024 は、V2 の jikou との比較では一致を確認済み。今回は XML から直接やり直す）。
- 金額: 項ごとに、目の要求額の合計と、事項の金額の合計が等しいか（どちらも項の内訳なので、等しいはず。未確認。「うち」書きなどで崩れる可能性があり、崩れ方自体を記述する）。総額も、目の合計が 112,571,688,422 千円であること。
- 行の数と重複キー（`b.csv` の目の行は、キーが重複する行が3つある〔FY2025〕）を台帳にする。

## 決めてほしいこと
1. 範囲: まず FY2024 の一般会計だけでよいか（特別会計は `12001` の CSV と XML があるが、組織の列がなく、列の位置が違う）。
2. 事項の XML の読み取り: 既存の凍結済みの parser（`lib/mof-budget-xml-items.ts`、FY2024 の一般会計だけに対応）の規則を使うか、素朴な primitive として新しく書くか。どちらも jsonl は経由しない。
3. 事項の CSV に、説明欄・主要経費別分類コードを含めるか。
4. FY2025 の扱い: XML の取得（ネットワーク）を許可するか。成立後と提出時のどちらを使うか。

## 次の一歩（案）
契約（定義）→ 項・目の CSV（CSV から機械的に。すぐ作れる）→ 件数の台帳 → 事項の CSV（XML）→ 構造の整合チェック。各段で、入力の hash を固定し、2回実行して同一であることを確かめる。
