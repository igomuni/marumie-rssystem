# 再委託UI 追加改善 対応案

再委託UI刷新 Phase 1–4 完了後の追加改善要望（2026-07-24）への対応案。
「一気にやる必要はない」との方針のため、**小さな独立PRに分割**して優先度・依存を整理する。
既存の設計方針は [20260720_1011_再委託UI刷新_設計方針.md](20260720_1011_再委託UI刷新_設計方針.md)、
今後の課題は [20260722_0818](20260722_0818_間接経費のサンキー非表示問題とブロック連結可視化.md)。

## 実装状況（2026-07-24・PR #281 マージ済み）

第1弾として **S2 / F3 / S3** ＋ 実装中に追加合意した変更を実施済み。当初案からの差分:

- **S2 は実質消化**（当初「流れを予算・執行の右へ」だったが、下記で予算・執行タブ自体を廃止し、
  フローを入口＝先頭タブにしたため、S2 の当初目的は吸収された）。
- **フロー図 hoverツールチップをメイン様式に統一（F3）** 済み。
- **「流れ」→「フロー」改称＋金額表示＋合流時の上流複数行（S3）** 済み。
  - 向きは **上流→下流**（起点 → 対象）で確定（当初案の `対象 ← 起点` 例は不採用）。
  - 並びは金額順、ただし **直接→再委託→別財源** の群順で直接を上位に。
  - フロー各行は **他タブと同じ2行構成**（上段=起点、下段=→対象＋流入額右寄せ）。
  - 合流数はフィルタ後の表示行数から導出（レビュー対応済み）。
- **初期タブをフローに**・**予算・執行タブを一旦廃止**。
  廃止した予算・執行の表示は **S1 で「メイン画面と同型のパネル表示」として再統合**する
  （データ配管＝API の `budgetSummary`/`budgetBreakdown` と型フィールドは残置済み。下記 S1・F1 で消費）。

**残り**: F1（予算・執行ノード列）、S1（ヘッダ/概要/品質スコア一致＋予算表示の再統合）、F2（ズーム/ラベル一致）。

## 要望一覧と現状・対応方針

### サイドパネル

#### S1. ヘッダー・事業概要・品質スコアをメイン画面と一致させる ＋ 予算・執行表示の再統合（未着手）

> **更新（PR #281 後）**: 廃止した「予算・執行」タブの表示は、本項でメイン画面と同型のパネル表示として
> 取り込む（タブに戻すのではなく、メインの事業概要/予算・執行の並びに合わせる想定）。
> データは API の `graph.budgetSummary`/`budgetBreakdown` を利用（取得済み・追加fetch不要）。

- **現状**: 再委託パネルのヘッダは 事業名／予算／執行／タグ／主要経費＋RSリンク。
  メイン画面（/sankey-svg）は 予算額／支出額（1円単位併記）＋**事業概要アコーディオン**＋**品質スコアブロック**を持つが、
  再委託パネルには**事業概要・品質スコアが無い**。
- **データ**（PR #281 後に再確認して訂正）:
  - `projectDetail`（`/api/project-details`）取得済み → `overview` はfetch追加なしで使える。
  - **品質スコアも実は取得済み**: 再委託ページは `/data/project-quality-scores-{year}.json` を既に fetch している
    （[page.tsx:1321](../../app/subcontracts/[projectId]/page.tsx#L1321)）が、現状は **org chain（bureau/division…）の抽出のみ**に使い、
    スコア本体を捨てている。**同ファイルの item に `totalScore`・`axisIdentify/Purpose/Budget/Effective/Structure`・
    `effectiveReason`・`aiSource` 等が全て含まれる**ため、S1a は**追加fetch不要**で、既存fetchの item から
    スコア欄を読んで表示するだけでよい（当初案の「/api/quality-scores/{pid} 追加fetch」は不要）。
  - 共有部品 `ScoreDetailDialog` は既存（詳細ダイアログ用）。
- **対応方針**:
  1. メイン画面の「品質スコアブロック」を `client/components/quality/` に**共有コンポーネント抽出**し、両ページで使う
     （メインは現状 page.tsx 内インライン。抽出すれば一致が保たれる ＝ 設計方針の共有プリミティブ路線）。
  2. 「事業概要」アコーディオンも同様に共有化 or 再委託側に同型実装（overview は取得済み）。
  3. ヘッダの数値表記（予算額／支出額・1円単位サブ表記）をメインの `StatRow` 相当に揃える。
- **規模**: 中。品質スコアの抽出＋fetch追加が主。**S1a=品質スコア**、**S1b=事業概要**、**S1c=ヘッダ数値表記** に分割可。
- **メモ**: 品質スコアブロック抽出はメイン画面にも影響する（インライン→コンポーネント差し替え）。回帰に注意。

#### S2. リストタブの「流れ」を「予算・執行」の右へ移動 ✅（吸収済み）

> **更新**: 予算・執行タブを廃止し、フローを入口＝先頭タブにしたため当初目的は消化。
> 現タブ順は `フロー / ブロック / 支出先 / 間接経費`（既定=flow、URL: fl/bl/rc/ic、fl は省略）。

#### S3. 「流れ」に金額表示 ＋ 合流時は上流側を複数行に ✅（実施済み・向きは上流→下流で確定）

- **現状**: `FlowListRow` は 起点タグ＋合流バッジ＋`起点ブロック → 対象ブロック` 名のみで**金額を出していない**。
- **データ**: `BlockEdge` に辺ごとの金額フィールドは無い。フローの金額は実質**対象ブロックの `totalAmount`**
  （そのブロックへ流入する額）で代表するのが妥当。合流（`targetIncomingBlockCount >= 2`）は
  1つの対象に複数の起点が流入する。
- **実施結果**（当初案から向きを修正して確定）:
  1. 対象ブロックの金額（`targetBlock.totalAmount`＝流入額）を各行の右端に右寄せ表示。
  2. **対象ブロックでグルーピング**（合流＝同一対象への複数流入を集約）。
  3. 向きは **上流→下流**。2行構成で 上段=起点（上流。合流時は複数行）、
     下段=`→ 対象ブロック` ＋ 流入額。当初案の `対象 ← 起点` は不採用。
  4. 合流数は**フィルタ後の表示行数**（`incoming.length`）から導出（構造的な `targetIncomingBlockCount` は使わない）。
- **メモ**: 辺ごとの金額はデータに無く、対象総額しか出せない。tooltip で「（合計）」と明示。
  対象へ異なる origin の辺が混在する稀ケース（2025で20件）ではフィルタ時に金額が過大に見え得るが、
  対象ブロックの真の総額であり、算出可能な唯一の値として継続表示。

### フロー図

#### F1. 事業ノードの左に「予算・執行」ノード列を追加

- **現状**: リボンフロー図の最左は事業（root）ノード。予算・執行の列は無い。
  （当初モック画面②では「一般会計 → 事業」を描いていたが本実装には未反映。）
- **データ**: `graph.budgetSummary`（totalBudget/executedAmount）・`budgetBreakdown` は API 取得済み（Phase 3で追加）。
- **対応方針**: リボンレイアウトに最左列「予算・執行」を追加し、緑ノード（予算総額／執行）から事業ノードへ1本のリボン。
  メイン画面の `総計→省庁→事業→支出先` と方向感を揃える（再委託図は `予算・執行→事業→ブロック→再委託ブロック`）。
- **規模**: 中。`subcontract-ribbon-layout` に列を1つ足し、ノード・リボン描画とズーム範囲（fit計算）に反映。
- **メモ**: 会計区分（一般/特別）で分けるか総額1本かは要判断。まず総額1本で足場を作るのが安全。

#### F2. ズームのインタラクション・ラベル構成をメイン画面に合わせる

- **現状**: 再委託図は独自のズーム/パン（`transform`/`baseZoom`/`scrollMode`、wheelハンドラ）。
  メインは `ZOOM_MIN/MAX_*`、ズーム連動フォント拡大（`ZOOM_FONT_MAX_RATIO`）、ミニマップ（`MinimapOverlay`）を持つ。
  ラベル構成（切り詰め規則・金額tspan・列見出し）も細部が異なる。
- **対応方針**: 段階的に寄せる。
  - **F2a**: ズーム上下限・ホイール挙動・スクロールモードの定数/作法をメインと統一（`ZOOM_*` 相当を共有定数化）。
  - **F2b**: ズーム連動フォント拡大をメインの `zoomFontRatio` 相当に合わせる。
  - **F2c**: ラベル構成（列見出し・名前切り詰め・金額tspan）をメインの流儀に合わせる。
  - **F2d（任意）**: ミニマップ導入。
- **規模**: 中〜大。ズーム機構は両者で作り込みがあり、完全一致は工数大。共有化できる定数/ユーティリティは
  `app/lib` に切り出す価値あり。**F2a→F2b→F2c** の順で小さく。

#### F3. hover ポップアップのレイアウト・スタイルをメイン画面に合わせる ✅（実施済み）

- **実施結果**: 色帯ヘッダ＋淡色ボディ → メイン様式のフラット白背景（#e0e0e0 ボーダー・控えめな影）。
  意味色は小さな共有 TagChip（事業/直接/再委託/別財源、移替・参考=グレー）、本文は中立グレー・金額太字。
  `flowOriginToTagKind` を共有 origin-kind に追加。**共有コンポーネント化まではせず**、メイン側の様式に合わせる形で実装
  （将来、ツールチップ表示部の共有化は F2 の共有化と併せて検討可）。

## データ・技術メモ（実装時の要点）

- 品質スコア: **追加fetch不要**。既存の `/data/project-quality-scores-{year}.json` fetch（現状 org chain 用）の
  item にスコア本体（totalScore/各軸/effectiveReason 等）が含まれる。org 抽出と同じ item からスコアも読む。
- 事業概要: `projectDetail.overview` は取得済み。fetch追加不要。
- 流れの金額: 辺ごとの額はデータに無い → 対象ブロック `totalAmount` を「流入額」として表示（意味を明記）。
- 予算・執行列: `graph.budgetSummary` を使用。会計区分分割は将来拡張、初手は総額1本。
- ズーム/ツールチップ共有化: `ZOOM_*` 定数・`zoomFontRatio`・ツールチップ表示部を `app/lib`／`client/components` へ抽出すると、
  以後メイン・再委託の乖離が再発しにくい（Phase 1 で semantic-colors / TagChip を共有化したのと同じ方針）。
