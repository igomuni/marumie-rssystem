# 列幅等のlocalStorage永続化と、コンボの外側クリックで再表示される不具合の原因判明・修正

## コンボが「マウスダウンで消えるがマウスアップで再表示される」原因判明

`FilterSidebar.tsx`の5つのコンボが`<label className="block space-y-1"><span>ラベル文字</span><MultiSelectCombo/></label>`という構造で、`<label>`要素は子孫の labelable 要素（`<button>`を含む）へクリックを転送するブラウザの標準機能を持つ。ラベル文字（例:「会計区分」の`<span>`）をクリックすると:

1. `mousedown`がラベルの`<span>`から`document`まで バブルし、`MultiSelectCombo`の外側クリック検出リスナが「spanはコンボの外側」と判定してコンボを閉じる（`onOpenChange(false)`）
2. Reactがこの状態更新を反映してから、ブラウザが`<label>`のクリック転送により、内部の`<button>`へ**合成クリックイベント**を発火させる
3. ボタンの`onClick`は現在の`open`（既にfalseに更新済み）を見て`!open`でトグル → **true に戻り再度開く**

これが「マウスダウンで一時的に消えるが、マウスアップ（実質的にはラベル転送によるクリック）で再表示される」の正体だった。5つのコンボラベルを`<label>`から`<div>`に変更し、ネイティブのラベル転送を止めることで解消。これにより「コンボボックスのクリックだけで展開する」という要望も同時に満たされる。

## 列幅等のlocalStorage永続化

年度切替時、`data`が一時的に`null`になる間`selectedRow`が消えて`KouSidePanel`自体がアンマウントされる（既知の挙動）。前回はタブ・グリッド列幅の状態をpage.tsx側のReact stateへ持ち上げて対処したが、それでもパネル自体は一瞬消える。ユーザーの提案どおり、より頑健な対処として以下をlocalStorageに永続化する`usePersistedState`フック（`client/hooks/usePersistedState.ts`、既存の`useTopNSettings`と同じ「マウント時に読み込み・更新のたびに書き込み」方式）を新設し、以下をブラウザに保存するようにした:

- `mof-kou:widths`（一覧の列幅）
- `mof-kou:sidebarWidth`（フィルタパネル幅）
- `mof-kou:panelWidth`（詳細パネル幅）
- `mof-kou:panelTab`（詳細パネルのアクティブタブ）
- `mof-kou:panelGridStates`（詳細パネル各タブのソート・列幅）

フィルタ条件・選択行はこの永続化の対象外（セッション内のReact stateのまま。ページ再読み込みをまたいで古い選択行が残ると紛らわしいため）。

## 検証

- `npx tsc --noEmit` / `npm run lint`: クリーン
- Playwrightで: ラベル文字クリックでコンボが開かないこと、コンボボタンのクリックのみで開閉すること、外側クリックで3回連続して確実に閉じることを確認
- 列幅をリサイズ→ページ全体をリロード→リサイズ後の幅が復元されることを確認
