# mof-kou-loader.ts の正準データ移行

`docs/tasks/20260828_1920_MOF予算データの階層JSON統合を実装.md` で「まだ新しい統合ファイルを読んでいない」としていたローダー移行を実施した。

## 変更内容

`app/lib/api/mof-kou-loader.ts` を全面書き換え。従来は `mof-jikou-{年度}.json` / `mof-kou-moku-{年度}.json` / `mof-section-pages-{年度}.json` を実行時に3方向結合していたが、事前結合済みの `mof-budget-{年度}.json` を直接読むだけに簡素化した。RS紐づけ（`mof-rs-kou-moku-linkage`）は更新サイクルがMOFデータと独立しているため、引き続き実行時オーバーレイのままにしている。

`sectionDetail()` が返す `MOFJikouItem` / `MOFKouMokuItem` は `mof-budget-{年度}.json` の軽量な `MOFJikouLeaf` / `MOFKouMokuLeaf`（親の `MOFSection` フィールドを持たない）から `hydrateJikou()` / `hydrateKouMoku()` で再構築し、既存のAPI出力形状を完全に維持している。

## 見つけたバグ

`hydrateKouMoku()` が `section.specialAccount` をそのまま使っていたため、事項・目の両方を持つ項では「先に登場したソース」の生値（事項側は`〜特別会計`接尾辞あり、目側は接尾辞なし）を引きずり、目の `key`/`specialAccount` が本来の目側の形式と食い違っていた。これは `mof-rs-kou-moku-linkage-{年度}.json` の `kouMokuKey` と一致しなくなり、RS紐づけバッジのルックアップが特別会計を持つ項全般で機能しなくなる回帰だった。`normSpecialAccount()` を `hydrateKouMoku()` 内で適用して修正（目側の値は元々接尾辞が無いため冪等）。curlで `kouMokuItems[0].key === rsLinks[0].kouMokuKey` が `true` になることを確認。

## 副次修正: MOFJikouLeaf に決算4項目が欠落

`types/mof-budget.ts` の `MOFJikouLeaf` に `currentAmount`/`spent`/`carriedOver`/`unused` が無く、`generate-mof-budget-data.ts` もこれらを転記していなかった（設計当初の見落とし）。追加し、全10年度分を再生成・再圧縮した。

## 検証

- `npx tsc --noEmit`: クリーン
- `npm run lint`: 既存の警告のみ（新規なし）
- `/api/mof-kou?year=2024` を移行前後でフィールド単位比較 → 3,321/3,321項が完全一致（金額・件数・出典ページ含む全フィールド）
- `sectionDetail()` を `基礎年金給付費` で確認 → 目のkey/specialAccountがRS紐づけの`kouMokuKey`と一致
- Playwrightで `/mof-kou` を操作し年度推移・事項・目・RSの4タブをスクリーンショット確認 → コンソールエラー無し、RS件数バッジが正しく表示
