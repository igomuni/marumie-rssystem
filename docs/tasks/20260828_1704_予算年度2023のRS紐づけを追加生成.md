# 予算年度2023のRS紐づけを追加生成

`基礎年金給付費`の令和5年度（2023・28.37兆円）にRS紐づけが表示されない、という指摘から発覚。
`data/year_2024`（RS事業年度2024＝予算年度2023の実データ）は存在するのに、目単位・事項単位いずれの
RS紐づけスクリプトも予算年度2024（RS_2025）分しか生成しておらず、予算年度2023分が未生成だった。

## 対応

```bash
npx tsx scripts/generate-mof-rs-kou-moku-linkage.ts 2024   # → mof-rs-kou-moku-linkage-2023.json
npx tsx scripts/generate-mof-rs-linkage.ts 2024             # → mof-rs-linkage-2023.json
```

`npm run generate-mof-rs-kou-moku-linkage`は`package.json`側で年度引数が`2025`固定のため、
追加の年度引数は無視される。別年度を生成するときは`npx tsx scripts/...`で直接呼ぶこと。

## カバレッジが2024年度より大幅に低い点に注意

| | 予算年度2024（RS_2025） | 予算年度2023（RS_2024） |
|---|---:|---:|
| 目単位・行カバレッジ | 92.2% | 22.5% |
| 目単位・金額カバレッジ | 97.5% | 47.7% |
| 事項単位・金額カバレッジ | 54.6%※ | 3.1% |

※事項単位は一般会計・当初予算のみが対象範囲のため単純比較不可（参考値）。

原因を実データで確認: RS の `2-2` CSVは1シートに複数年度分（例: RS_2024のシートは予算年度
2021〜2024を収録）の実績を持つが、**所管・組織・項・目などの分類情報が正確に埋まっているのは
シートごとに一部の年度のみ**で、それ以外の年度は金額だけが記録され分類欄が空欄になっている
（実測: RS_2024シート内で予算年度2024の行は91.2%が分類欄あり、予算年度2021〜2023の行は
16〜23%程度しかない）。RS_2025シートでは予算年度2024・2025の両方が90%超で分類欄ありだったため、
たまたま前回（予算年度2024の生成）は高カバレッジだった。

この性質上、**過去年度に遡って直接RS紐づけを生成しても、遡るほどカバレッジは大きく落ちる**
（RS側のデータそのものの制約であり、突合ロジックの問題ではない）。年度をまたぐ識別子引き継ぎ
（`resolveLinks`のフォールバック）は、直接データが無い年度にのみ発動する設計のため、この
予算年度2023のように直接データが（低カバレッジながら）存在する年度はそちらが優先される。

## 確認

- `/mof-kou`の年度推移で`基礎年金給付費`の令和5年度（当初予算・決算）にRS=1が表示されることを確認
- `/api/mof-kou?year=2023`のmetadata.linkageが`{available:true, isCarriedOver:false, sourceBudgetYear:2023}`
