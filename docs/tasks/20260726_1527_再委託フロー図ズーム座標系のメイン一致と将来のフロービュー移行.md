# 再委託フロー図ズーム座標系のメイン一致と将来のフロービュー移行（設計整理）

## 背景・目的

`/subcontracts/[projectId]` のフロー図（ribbon）を `/sankey-svg`（メイン）のズーム挙動に一致させる作業の中で、
両者の**座標系アーキテクチャが根本的に異なる**ことが判明した。単なるフォント調整（F2b・実装済み）では不足で、
座標系そのものの作り替えが必要になる。

加えて、将来的には **メイン画面 `/sankey-svg` を「再委託フロービュー」へ切り替え／移行する構想** がある。
そのため本ドキュメントでは、

1. 現状の座標系の差分整理
2. 再委託フロー図をメイン挙動に一致させる改修設計
3. 将来のメイン→再委託フロービュー移行を見据えた共有化方針

をまとめ、実装着手前の合意形成の土台とする。

## 用語

```text
メイン       = /sankey-svg（全事業を集約した総計→省庁→事業→支出先のサンキー）
再委託フロー = /subcontracts/[projectId] の「フロー図」タブ（予算→事業→支出先→再委託先…のribbon）
zoom         = ユーザーが操作する拡大率（transform.scale / 内部の zoom 状態）
baseZoom     = フィット時の zoom（100%表示の基準倍率）
```

## 1. 現状の座標系比較

### メイン `/sankey-svg`（横縦分離）

```tsx
<g transform={`translate(${pan.x},${pan.y}) scale(${zoom})`}>
  <g transform={`translate(${MARGIN.left},${MARGIN.top})`}>
```

一様 `scale(zoom)` の群に見えるが、**横座標だけ zoom で割り戻している**ため実質は横縦分離：

| 軸 | 仕組み | zoom時の挙動 |
|----|--------|-------------|
| 横（列位置・ノード幅・ラベル間隔） | `getNodeScreenX0`（`horizontalScale`＝zoom非依存）で画面固定位置を算出 → `screenToInnerX(sx)=sx/zoom` で群に渡す | **画面上の横位置は不変**。ノード幅も `NODE_W/zoom` で画面一定 |
| 縦（ノード高さ・y座標） | レイアウト座標のまま群の `scale(zoom)` で拡大 | **高さ・縦間隔が zoom連動で変化**（ラベル非重複の余白が生まれる） |
| フォント | `colFontPx/zoom * getZoomLabelScale(zoom,baseZoom)` | 画面一定＋baseZoom超で最大 `ZOOM_FONT_MAX_RATIO(2.0)` 倍 |
| ズームのアンカー | `getZoomAnchoredPanY`（pan.y のみ調整） | 横は不変なので pan.x は触らない |

関連実装: `getNodeScreenX0`/`getNodeInnerX0`/`screenToInnerX`/`screenWToInner`/`horizontalScale`
（すべて `app/sankey-svg/page.tsx` にインライン。`computeLayout` も同ファイル内）。

### 再委託フロー（一様スケール）

```tsx
<g transform={`translate(${transform.x},${transform.y}) scale(${transform.scale})`}>
```

- レイアウト（`app/lib/subcontract-ribbon-layout.ts`）が x/y を絶対座標で確定し、ページは**完全一様スケール**で描画。
- `resetViewport`：`fitZoom = min(cW/w, cH/h)*0.9` の一様フィット（baseZoom=fitZoom）。
- `applyZoom`：**両軸**アンカーズーム（pan.x/pan.y 両方調整）。
- フォント：F2b で `scaleFont(px)*getZoomLabelScale/transform.scale` に変更済み（画面一定＋最大2倍）。

## 2. ギャップ（ユーザー指摘の3点）

1. **zoomで変わるのはノード高さとフォント** … 再委託は横も一緒に拡大してしまう
2. **縦間隔がラベル非重複のため変化** … 再委託は縦が zoom基準で伸びない（ラベルは一定なのに余白が増えない）
3. **横の列位置は画面上固定** … 再委託は zoom で列が横に広がる／縮む

→ 差分の核心は**横方向を zoom不変にし、縦方向のみ zoom拡大する**こと。F2b（フォント一定化）は土台として活用できる。

### 2-1. 横方向の追加制約（確定・ユーザー指示 2026-07-26）

- **横は「メイン画面の横幅に4列が収まる」固定ピッチに合わせる**（＝ fit-all で全列を詰め込まない）。
  4列 = `予算・執行 / 事業 / 支出先(depth1) / 再委託先(depth2)`。
- **再委託階層が深く5列以上になる場合は、無理に収めず横方向へオーバーフロー**させてよい（パンで閲覧）。
- これにより横スケールは**コンテンツ列数にも zoom にも依存しない固定値**となり、設計が単純化する
  （§3-1 は fit-all をやめ、固定ピッチ方式に確定）。

## 3. 改修設計（再委託フローをメイン挙動に一致）

方針：メインの `getNodeScreenX0`/`screenToInnerX` 相当を再委託ページに移植し、横縦を分離する。
レイアウト（`subcontract-ribbon-layout.ts`）が返す座標は現状維持し、**描画時の座標変換だけを変える**（layoutは横=画面px相当・縦=画面px相当のまま流用）。

### 3-1. 座標変換ヘルパー

```ts
// horizontalScale: 「可視幅に4列が収まる」固定ピッチ（zoom非依存・列数非依存）。
// 1列 = レイアウト上の RIBBON_COL_W + RIBBON_COL_GAP。可視幅(cW)を4列で割ったものを
// 1列あたりの画面ピッチとし、レイアウト1列ぶんがそれに一致する倍率を求める。
const VISIBLE_COLS = 4;                                   // 予算/事業/支出先/再委託先
const layoutColPitch = RIBBON_COL_W + RIBBON_COL_GAP;     // レイアウト単位の1列ピッチ
const horizontalScale = (cW / VISIBLE_COLS) / layoutColPitch;
// 群は scale(zoom) されるので、横は zoom で割り戻して画面固定にする
const ix = (x: number) => x * horizontalScale / transform.scale;  // inner x
const iw = (w: number) => w * horizontalScale / transform.scale;  // inner width
// 縦はレイアウト座標のまま（群の scale(zoom) が拡大＝縦間隔もzoom連動）
```

5列以上（`再委託先2` 以降）は `ix()` により画面右へ延伸し、可視幅を超えた分はパンで閲覧する
（横スケールは固定なので圧縮されない）。

### 3-2. 適用箇所（フロー図の全 x/幅）

- バー：`x`,`width` → `ix/iw`
- 予算内訳ノード：`x`,`width` → `ix/iw`
- 事業ノード：`mergedProjectPath(x0,…,barW,…)` の x0/barW → `ix/iw`（yはそのまま）
- 各フロー（順方向/backEdge/budgetFlows）：`x1`,`x2` → `ix`（y1/y2はそのまま）
- 別財源レーンのラベル・区切り線 x → `ix`
- ラベル clipPath（`ribbonColX`）→ `ix`
- 列見出しオーバーレイ（F1・HTML絶対配置）：`transform.x + xCenter*horizontalScale`（縦は `transform.y + topY*transform.scale`）

### 3-3. pan/zoom/fit の分離

- `applyZoom`：**pan.y のみアンカー調整**、pan.x は据え置き（横不変）。
- `resetViewport`：横＝固定`horizontalScale`（4列ピッチ）で `pan.x` は可視領域左端に左寄せ（`予算・執行` 列が左端）、
  縦＝高さフィットで baseZoom を設定・`pan.y` で縦中央。**横フィットは行わない**（4列固定・超過分はパン）。
- ホイール／スライダ／数値入力：縦方向 zoom のみを操作する意味に統一。

### 3-4. 検証

- PID 7（浅い・階層3）／PID 4119（18予算・多支出先）で、
  - zoomイン：ノードが縦に伸び、列の横位置が動かない、フォントは最大2倍で頭打ち、ラベルが重ならない
  - zoomアウト：縦が縮む、横位置固定
  - フィット：baseZoomによらずフォント一定
- 列見出し（F1）が横位置固定・縦スクロールでSticky追従を維持

### 3-5. リスク

- 中〜大の作り替え。フロー図描画のほぼ全 x/幅＋pan/zoom/fit＋F1オーバーレイに波及。
- 横フィットと縦フィットの独立化で、既存の「サイドパネル分の可視領域補正」ロジックとの整合に注意。
- ブロック図（`view=block`・別経路）は本改修の対象外に留める（別途）。

## 4. 将来構想：メイン→再委託フロービュー移行

### 4-1. 現状のデータスコープ差

| | メイン | 再委託フロー |
|--|--------|-------------|
| 対象 | 全事業を集約（総計→省庁→事業→支出先） | 単一事業（予算→事業→支出先→再委託先…可変深度） |
| レイアウト | `computeLayout`（page内インライン、列固定） | `computeSubcontractRibbonLayout`（可変深度） |
| ノード | total/ministry/project-budget/project-spending/recipient | budgetItem/root(事業)/block(可変depth) |

「メインを再委託フロービューへ切り替え」= メイン画面に**単一事業の再委託フロー表示モード**を持たせる、
あるいは全体ビューから事業ドリルダウンで再委託フローへ遷移する、のいずれか（要確認）。

### 4-2. 移行を楽にするための共有化候補

本改修を「再委託ページ限定のインライン実装」で終わらせず、移行時にメインへ持ち込める形にするなら、以下を
`app/lib` / `client/components` へ抽出する価値がある（既に font-scale / semantic-colors / TagChip は共有済み）：

1. **座標変換ユーティリティ**：`horizontalScale`／`screenToInnerX`／`ix/iw`／`getZoomLabelScale`／ZOOM定数
   → `app/lib/flow-view-transform.ts`（仮）。メイン・再委託の座標系乖離の再発防止。
2. **フロービュー描画コンポーネント**：ribbon描画（バー・フロー・ラベル・列見出し・pan/zoom）を
   `client/components/flow/FlowCanvas`（仮）として切り出し、layout（データ）を props で受ける。
   メインは `computeLayout` 出力、再委託は `computeSubcontractRibbonLayout` 出力を共通の中間表現へ写像して渡す。
3. **共通中間表現（IR）**：`{ columns, nodes(x,y,w,h,kind,label,amount), flows(x1..y2), colHeaders }` のような
   描画非依存の型。両layoutをこのIRに変換すれば、FlowCanvas は片方の実装に依存しない。

### 4-3. 段階提案

| 段階 | 内容 | 対象 | 備考 |
|------|------|------|------|
| P0（本改修） | 再委託フローの座標系をメイン挙動へ（横固定・縦zoom・フォント一定） | 再委託ページ | まずは**インライン**で正しく動かす。共有化は最小限 |
| P1 | 座標変換ユーティリティを `app/lib` に抽出、メイン・再委託双方が使用 | 両画面 | 乖離再発防止。メイン側は挙動不変を保証しつつ置換 |
| P2 | フロービュー描画を共通コンポーネント化（IR経由） | 両画面 | 移行の本体。メインに再委託フロー表示モードを載せる素地 |
| P3 | メイン画面に再委託フロービュー切替を実装 | メイン | データ配管（単一事業取得）とUI切替 |

**推奨**：P0 はまずインラインで確実に挙動一致させる（過度な共有化を先行させない）。P1以降は移行の意思決定後に、
本ドキュメントの共有化候補を土台として着手する。
