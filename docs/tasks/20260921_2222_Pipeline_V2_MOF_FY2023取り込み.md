# Pipeline V2 — MOF FY2023（令和5年度）取り込み

## 経緯

`feat/validator-v2-hardening`のmerge後、MOF FY2023データを`download-mof-archive.ts`で取得済み（`data/download/mof.go.jp/archive/2023/`、20件、CSV zip 8件・決算参照等PDF 12件）。今回はこれをPipeline V2の全層（normalize→derive→derive-integrated→publish→validate）に取り込んだ。

## 各層の対応状況

`normalize-mof.ts`・`derive-mof.ts`はもともと`[year...]`をCLI引数で受け付ける設計で、コード変更なしに`2023`を渡すだけで動作した。

`derive-integrated.ts`・`validate-v2.ts`・`publish-v2.ts`の3ファイルは`FISCAL_YEARS`/`fiscalYears`がCLI引数を受け付けず`[2024, 2025]`にハードコードされていたため、`[2023, 2024, 2025]`に変更した（ロジック自体の変更なし）。

## 実行結果

```bash
npx tsx scripts/pipeline-v2/normalize-mof.ts 2023   # budget-items.jsonl: 19797行
npx tsx scripts/pipeline-v2/derive-mof.ts 2023       # sections.jsonl: 1314件、決算検算 mismatch=0
npx tsx scripts/pipeline-v2/derive-integrated.ts     # review-2024×fy2023, review-2025×fy2023を新規生成
npm run pipeline:v2:publish
npm run pipeline:v2:validate                          # error=0（FY2024/2025の既存sanity値は不変）
```

新規生成された組み合わせ:

```text
review-2024×fy2023: linkGroups=1505 linkedProjects=1036 linkedRs=3051 unlinkedRs=10515
review-2025×fy2023: linkGroups=1468 linkedProjects=995  linkedRs=2958 unlinkedRs=9981
fy2023: Publish(MOF) — sections=1314 detail records checked=19797 findings=0 event groups checked=14707 findings=0
```

## 既存データへの影響

`public/data/v2/rs/**/core/*.json.gz`のうち511ファイルが更新されたが、差分を確認したところ変更点は`mofLinks`フィールドのみ（fy2023分のリンクが追加されたことによる想定どおりの変更）。FY2024/FY2025のMOF/RS/links件数・sanity値はvalidate結果上すべて不変。

`npx tsc --noEmit`・`npm test -- --run`（619 tests）・`npm run lint`（既存warningのみ）はいずれもクリーン。

## 未対応・留意点

- review-2026×fy2023の組み合わせは生成されない（review-2026のRS正規化データにfiscalYear=2023の行が無い、またはRS側review-2026データ自体が部分的なため）。
- FY2022以前への遡及は未検証。`download-mof-archive.ts`のURL変換（`reiwa{year-2018}`）は機械的だが、年度によって様式・帳票構成が変わる可能性があり、個別確認が必要。
