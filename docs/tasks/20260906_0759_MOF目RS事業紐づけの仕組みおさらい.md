# MOF目↔RS事業紐づけの仕組みおさらい（実データ例つき）

`scripts/generate-mof-rs-kou-moku-linkage.ts` の実装内容を、実データの生値つきで整理する。

## 入力

- **RS側**: `data/year_{RS年度}/2-2_予算・執行_予算種別・歳出予算項目.csv`（1行＝1予算事業×1歳出予算科目）
- **MOF側**: `public/data/mof-kou-moku-{予算年度}.json`（科目別内訳CSVから生成済みの「目」データ）

RS年度は予算年度の翌年（RS_2025のシートが予算年度2024を記録）。

## 突合キー（完全一致・名前ベース、コードは使わない）

NFKC正規化＋空白除去した文字列を結合するだけの**完全一致**。あいまいマッチ・部分一致は一切していない。

- **一般会計**: `予算種別｜所管｜組織・勘定｜項｜目`（RS） ↔ `予算種別｜所管｜組織｜項名｜目名`（MOF）
- **特別会計**: `予算種別｜所管｜会計｜勘定｜項｜目`（RS） ↔ `予算種別｜所管｜特別会計名｜勘定｜項名｜目名`（MOF）
  - RSの「組織・勘定」列は特別会計だと「勘定」と重複するので使わず、「会計」「勘定」を個別に使う

完全一致で通る理由は、RSの2-2 CSVがMOFの科目別内訳と**同じ語彙**（同じ帳票由来）で所管・組織・項・目の名称を持っているため。目コード・項コードは突合キーに使っていない。

## 予算種別の対応

- `当初予算` ↔ `当初予算`
- `第N次補正予算`（RS） ↔ `補正予算（第N号）`（MOF）
- `前年度から繰越し` `予備費等N` は対象外 — RS側にこの行の所管/組織/項/目が記録されておらず（空欄）、原理的に突合不可能

## 決算への引き継ぎ（直接突合ではなく推定）

RSは決算段階の目別内訳を持たないため、決算の目は直接一致させられない。代わりに**予算種別を除いた識別子**（会計区分・所管・組織/特会・勘定・項コード・目分類コード・目名）で、当初/補正予算側で既に成立しているリンクの金額をそのまま決算目に転記する（`carriedOverFrom`で判別可）。ここだけコードを使っており、かつ金額は実測ではなく推定（詳細は③参照）。

## 実測カバレッジ（2024年度）

- 一般会計・当初予算: 行の92.7%・金額の97.9%が一致
- 特別会計・当初予算: 行の86.6%・金額の98.9%
- 一致しない残差は主に組織名・目名の表記差やRS側独自科目（未精査）

## 出力

`public/data/mof-rs-kou-moku-linkage-{予算年度}.json` の `links[]`。`app/lib/api/mof-kou-loader.ts`がこれを読み、`/mof-kou`の「RS事業」列・件数の元データにしている。

## 補足: `sectionCode`（項コード）の由来と「コード番号について」との関係

### 由来

`sectionCode`（例: `"024"`）は、一般会計歳出CSV `DL{YYYY}11001b.csv` の**「項コード」列をそのままコピーしたもの**（`scripts/generate-mof-kou-moku-data.ts` の `rowFields()`: `sectionCode: row['項コード'] ?? ''`）。3桁・**組織内の連番**で、パイプラインが計算した値ではなく元CSVの生データそのもの（詳細: [docs/mof-budget-data-guide.md](../mof-budget-data-guide.md) §2-2）。

### 予算書「(参考) コード番号について」（p.1135等）との関係

予算書に載っているこの参考ページは、次の**7種類の分類コード表**を定義している（`docs/mof-budget-data-guide.md` §4-1〜4-7）:

- 所管コード（§4-1）
- 主要経費別分類コード（§4-2）
- 目的別分類コード（§4-3）
- 財政法公債金対象非対象別分類コード（§4-4）
- 経済性質別分類コード（§4-5）
- 使途別分類コード（§4-6）
- 目別分類コード（§4-7）

**`項コード`（sectionCode）はこの一覧に含まれていない。** 上記7種は「コードの値そのものに意味がある」分類（例: 目別分類コード`16`=補助金の類）で、予算書側にコード↔名称の対応表が存在する。一方、項コードは単に「その組織の中で何番目の項か」を示す通し番号で、対応する定義表が予算書側に存在しない（項の実体を指すのは`項名`そのもので、項コードは表内の位置を示す付随情報に過ぎない）。この性質の違いが、目コード等より項コードの方が年度をまたいで不安定になりやすい一因（項が増減すると以降の連番が総ずれする。`docs/mof-budget-data-guide.md` §3-1-2に詳細）。

MOFKouMokuItemの`majorExpenseName`・`objectiveName`・`fiscalLawName`・`economicNatureName`・`purposeName`は、CSVのコード列（`majorExpenseCode`等）を`scripts/mof-classification-tables.ts`・`scripts/mof-major-expense.ts`の対応表で名称に変換したもの＝この「コード番号について」ページの内容そのもの。`sectionName`だけは対応表を介さず、CSVの「項名」列をそのままコピーしている。

### CSVにあるもの／パイプラインが付加するものの整理

| MOFKouMokuItemのフィールド | 由来 |
|---|---|
| `ministry` `organization` `specialAccount` `subAccount` `agency` | CSV列（所管・組織・特別会計・勘定・政府関係機関）そのまま |
| `sectionCode` | CSV列「項コード」そのまま（組織内連番、対応表なし） |
| `sectionName` | CSV列「項名」そのまま |
| `majorExpenseCode` `objectiveCode` `fiscalLawCode` `economicNatureCode` `subItemCode` `purposeCode` | CSV列（各分類コード）そのまま |
| `subItemName` | CSV列「目名」そのまま |
| `majorExpenseName` `objectiveName` `fiscalLawName` `economicNatureName` `purposeName` | 上記コード列をパイプラインが対応表（`mof-classification-tables.ts`等）で名称に変換したもの。CSVには無い |
| `amount` `previousAmount` `difference` | CSV列（金額）そのまま。ただし予算は千円単位のCSVを円単位に変換済み |
| `currentAmount` `spent` `carriedOver` `unused` | 決算CSVのみに存在する列（歳出予算現額・支出済歳出額・翌年度繰越額・不用額）をそのままコピー。予算（当初・補正）データでは常に`null` |
| `id` | **パイプラインが付加**。`${accountType}-${budgetType}-${CSV行の配列インデックス}`。原簿の番号ではない（前述の注釈参照） |
| `key` | **パイプラインが計算**する複合キー（会計区分・予算種別・所管・組織・特会・勘定・機関・項名・目名。年度横断突合や本ドキュメントの突合キーに使う） |
| `documentId` `sourceUrl` | **パイプラインが構成**。帳票のドキュメントID・XML/HTMLの取得元URL |
| `page` | Web帳票（HTML/XML）側の出典ページ番号を突合して付加。突合できない場合は`null` |

## CSV・XML原本の生値（①②の裏付け）

### ①の元CSV（`data/download/mof_2024/DL202411001.zip` 内の歳出表、UTF-8）

### 発見: 同一事業内でも古い年度は所管/項/目が丸ごと空欄

上の表を年度別に集計すると:

| 予算年度 | 所管等が構造化されている行 | 空欄の行 |
|---|---|---|
| 2025 | 12 | 1 |
| 2024 | 12 | 1 |
| 2023 | 0 | 11 |
| 2022 | 0 | 7 |
| 2021 | 0 | 8 |

**同じ「医療保険給付費国庫負担金等」という1事業の中でも、2024・2025年度は所管/組織・勘定/項/目がほぼ全行で構造化されている一方、2021〜2023年度は全行が空欄で、目の内訳が`歳出予算項目の補足情報`という自由記述テキストにしか残っていない。** これはRSのレビューシート自体が、直近1〜2年度分だけ歳出予算項目を構造化列で記録し、それより前の年度は自由記述のみという運用になっていることを示す。以前の調査で「2023年度のRS↔MOF紐づけ率が2024年度より大幅に低い」と分かっていたが、その一因はMOF側・突合ロジック側ではなく、**RS側が過去年度分の構造化データをそもそも持っていない**ことにある可能性が高い（本事業の実例では2023年度以前は100%空欄）。全事業に一般化できるかは未検証。
