# 概算要求 明細表 CSV — 3 行の表頭ページを読む修正の契約

状態: 実装・実行の前に commit する。**修正の範囲と回帰条件を先に固定する。** 結果（行数）を見て規則を変えない。

## 原因（記述）
明細表の builder（`scripts/pipeline-v2/lib/budget-request-detail-table.ts`）の `headerBoundary` は、表頭を「`事項`・`前年度`・`備考` を同じ行に持つ 1 行目」と「`番号`・`予算額`・`比較` を持つ 2 行目」の 2 行として探す。一部のページ（FY2025 で 12 ページ、FY2024 で 11 ページ。各組織・文書の最初の明細表ページ）は、表頭が次の 3 行になっており、`PAGE_WITHOUT_HEADER_BOUNDARY` として**ページの全行が表から落ちている**。
- 1 行目: `要求` … `前 年 度 ７ 年 度` … `対 前 年 度`
- 2 行目: `番号` … `事 項` … `備 考`
- 3 行目: `予 算 額 概算要求額 比較増△減`
12 ページ・11 ページのすべてが、この 3 行の形（`要求`・`前年度`、`番号`・`事項`・`備考`、`予算額`・`概算要求額`・`比較` の各語の行の並び）であることを確認済み。落ちたページには、`CONTEXT`（`23 財務省所管` など）、組織・項・事項・目の行が含まれる。

## 修正
`headerBoundary` に**フォールバック**を足す。既存の 2 行の探索が `null` を返したときだけ使う（既存のページの結果は変わらない）。
- 3 行の形: 行 f が `前年度` を含み `事項` を含まない、行 f+1 が `番号`・`事項`・`備考` を含む、行 f+2 が `予算額`・`概算要求額`・`比較` を含む。
- `boundary` ＝ 行 f の `前` の位置（`q`）、`remarksStart` ＝ 行 f+1 の `備` の位置、`windows` ＝ 行 f+2 の各語の位置から既存と同じ式、`headerEnd` ＝ f+2。`q < 備` の位置を満たさなければ `null`。
- それ以外のパース（列の窓、行の分類、金額）は変えない。

## 回帰条件（すべて満たさなければ STOP）
1. 既存のテスト（`budget-request-detail-table.test.ts` ほか）が無変更で通る。
2. FY2024・FY2025 の明細表 CSV を再生成し、**修正前に行があったページ**の行は、`row_index` を除いて同一（同じ `source_file`・`source_page`・`source_line_start` の行の他の列が一致）。`row_index` は source 内の通し番号で、落ちていたページの行が加わると後続が変わる。
3. 修正前に `PAGE_WITHOUT_HEADER_BOUNDARY` だったページは、修正後に境界が見つかる（FY2025 12／FY2024 11 ページ）。それ以外のページの境界の有無は変わらない。
4. 行数は報告のみ（期待値を置かない）。算術診断（`arithmetic-diagnostics.csv`）の件数も報告する。

## 手順
実装 → 単体テスト（3 行の表頭の合成ページ）→ FY2024・FY2025 の明細表 CSV を再生成（`data/work/` 上書き）→ 回帰条件の確認 → 結果の記録 → MOF との突合を再実行（別の PR で）。
