# MOFデータの階層と識別子の実測（2017〜2026の10年度）

「どの列が事項のIDなのか」「年度をまたいで同じ事項を追えるのか」を実測で確定させた記録。
きっかけは主要経費別分類コードを事項のIDと取り違えたこと。**MOFは事項にIDを振っていない。**

## 1. 階層 — 事項は最小単位ではない

同じ「項」の下に、切り口の違う内訳が2系統ぶら下がる。入れ子ではなく並列。

```text
所管 ─ 組織 ─ 項 ┬─ 事項   （事項別内訳。Web帳票のXMLのみ）
                 └─ 目     （科目別内訳。ZIP同梱CSV）
```

令和8年度・一般会計の実測:

| 単位 | 件数 | 出典 |
|---|---:|---|
| 項 | 824 | 両方に共通 |
| 事項 | 1,303 | 事項別内訳 |
| 項×目 | **6,790** | `DL202611001b.csv` |

**最小構成要素は目**で、事項の5倍細かい。1項あたり事項1.6件・目8.2件。

ただし**事項と目の対応表は公表されていない**。事項別内訳に目の欄は無く、科目別内訳に事項の欄も無い。
目は「職員基本給」「庁費」のような支出の**性質**、事項は「アイヌ政策の推進に必要な経費」のような
**目的**による括りで、切り口が違うため1対1に対応しない。

事項を採用しているのは、**MOF側で唯一「事業らしい」名前と説明文を持つ粒度**だから。
令和8年度当初の1,712事項すべてに `説明` がある。目は名前が定型で用途が読めない。

## 2. 主要経費別分類コードは分類であってIDではない

令和8年度・当初予算（1,712事項）:

| 指標 | 値 |
|---|---:|
| コードの種類数 | 35 |
| 1コードあたり平均事項数 | 48.9 |
| 最多コードが抱える事項数 | **696**（`95 その他の事項経費`） |

1コードが数百の事項を束ねる。`docs/mof-budget-data-guide.md` 4-2節のコード表どおりの
静的な分類であって、事項を識別する値ではない。目的別・経済性質別・使途別も同じ性質。

## 3. 同一年度内 — 項コードは予算種別をまたいで一貫する

当初・暫定・補正・決算で項コードが振り直されることはない。

| 検査 | H30 | R2 | R8 |
|---|---:|---:|---:|
| 組織×項名 → 項コードが複数 | 0 | 0 | 0 |
| 同一キーの事項が種別間で項名不一致 | 0 | 0 | 0 |
| 組織×項コード → 項名が複数 | 6 | 4 | 3 |

最後の行はゼロではないが、原因は項コードの揺れではない。

- **特会の所管名が年度内で変わる**: 復興特会の所管は共管省庁を全部並べた文字列。
  令和8年度は防災庁の新設で当初と暫定の所管名が違う文字列になった（項コードは同じ）
- **復興特会は勘定を持たず項コードが会計内で重複**: `項01` が「復興債費」と「復興庁共通費」の両方
- **項名の改称**: H30 `項257` が「航路標識災害復旧事業費」→「船舶交通安全基盤災害復旧事業費」

## 4. 年度をまたぐと項コードは動く

**項コードは組織内の連番**なので、項が増減すると以降が総ずれする。

当初予算・10年度・全会計での実測:

| 検査 | 件数 |
|---|---:|
| 組織×項名 の組合せ総数 | 1,496 |
| **項名は同じなのに項コードが変わった** | **96件（6.4%）** |
| 同じ項コードが別の項名に再利用された | 164件 |

農林水産省の例。個別にバラつくのではなくブロック単位で一斉に動く。

```text
水産基盤整備費                        2017-2020:143 → 2021-2025:141 → 2026:122
水産基盤整備事業工事諸費              2017-2020:146 → 2021-2025:144 → 2026:124
国立研究開発法人水産研究・教育機構運営費  2017-2020:134 → 2021-2025:133 → 2026:112
保険料国庫負担金等食料安定供給特別会計へ繰入  2017-2020:140 → 2021-2025:138 → 2026:118
```

**年度横断のキーとして項コードを信頼してはいけない。**

## 5. 現行の同一性判定ロジック

`app/lib/api/mof-jikou-loader.ts` の `identityKey()`。**8要素の連結文字列の完全一致**だけで、
正規化も曖昧一致もしない。

```ts
[accountType, ministry, organization, specialAccount, subAccount, agency, sectionCode, name].join('|')
```

生成物の `key` は予算種別を含む9要素。`identityFromKey()` が2番目（予算種別）だけを落とす。
種別を落とすのは**当初と決算を同じ事項として辿るため**。

突合は `filter` であって `find` ではない。同一年度の当初・暫定・補正・決算がまとめて `items` に入る。

**識別子 × 年度 × 予算種別 の重複は10年度・全種別で0件**（4年度時点の前提が10年度でも成立）。

## 6. 追跡が切れる原因は2つある

コード上のコメントは事項名の改称にしか触れていないが、実測すると**項コードの移動も効いている**。

当初予算・10年度:

| 識別子 | 事項の系列数 | 10年そろう系列 | 平均で追える年数 |
|---|---:|---:|---:|
| 項コードあり（現行） | 2,620 | 1,065 | **6.39年** |
| 項コードなし | 2,391 | 1,116 | **6.78年** |

項コードを外すと10年そろう系列が51本増え、平均0.39年ぶん長く追える。
系列数が減るのは、分裂していた同一事項が統合されるため。

### 改称による切断

同じ組織×項コードで「ある年度に終わる系列」と「翌年度に始まる系列」が同時にある境界を数えた。

| 種類 | 件数 |
|---|---:|
| 境界の総数 | 208 |
| 1対1（改称の可能性が高い） | **156** |
| 1対多（分割） | 13 |
| 多対1（統合） | 20 |
| 多対多（再編） | 19 |

1対1の例:

```text
2025→2026  「共生社会政策の企画立案等に必要な経費」 → 「共生・共助政策の企画立案等に必要な経費」
2025→2026  「生物多様性の保全等の推進に必要な経費」 → 「生物多様性の保全に必要な経費」
2017→2018  「航路標識整備事業に必要な経費」 → 「船舶交通安全基盤整備事業に必要な経費」
```

1対多の例（1事項が3つに分割）:

```text
2017→2018  「子どもの体力の向上に必要な経費」 → 「スポーツを通じた社会課題解決の推進…」
                                              → 「スポーツ参画人口の拡大…」
                                              → 「公正・公平なスポーツの推進…」
```

**これは候補であって確定ではない。**同じ項コードで別の事項が独立に廃止・新設された場合も混ざる。
上限として156件と読むのが妥当。

多対多の例（2事項が2事項に組み替わり、対応が一意に決まらない）:

```text
子ども・子育て支援の財源の年金特別会計…へ繰入れ ＋ 特例給付等の財源の年金特別会計…へ繰入れ
  → 児童手当等の財源の子ども・子育て支援特別会計…へ繰入れ
  ＋ 妊婦のための支援給付事業等の財源の…へ繰入れ

あへんの供給確保等に必要な経費 ＋ 麻薬・覚せい剤等対策に必要な経費
  → 麻薬・覚醒剤等対策に必要な経費 ＋ 麻薬・覚醒剤等対策の推進に必要な経費
```

後者は「覚せい剤」→「覚醒剤」の表記変更も同時に起きており、名寄せをさらに難しくしている。

## 7. 項コードを外せば済む話ではない

外すと追跡は伸びるが、**事項名は項をまたいで重複する**ため金額が合算されてしまう。

```text
「河川整備事業に必要な経費」   R8当初 = 項353 / 項083 / 項086
「地域連携道路事業に必要な経費」 R8当初 = 項359 / 項086
```

公共事業系で顕著。通常事業と防災・安全交付金などが別の項に立つため。
決算でも1事項が複数の項に分かれる（R2のCOVID交付金は `項281` 1,118億 ＋ `項664` 3,382億）。

改善するなら「項コードを外す代わりに、同名で複数項に分かれる事項は合算せず併記する」設計が要る。
現状は未対応で、`/mof-jikou` の履歴は項コード込みのまま。

## 実務上のまとめ

```text
主要経費コード … 分類。IDではない（1コードに最大696事項）
目            … 最小単位だが事項との対応表が無い
項コード      … 同一年度内は信頼できる／年度をまたぐと動く（6.4%）
事項名        … 単独では一意にならない。項コードとセットで初めてキー
所管名        … 特会の共管グループ名は年度内でも変わりうる
事項のID      … 存在しない。合成キーを作るしかない
```

## 8. 結論 — 名寄せはしない

**52件（25%）が1対1でない**ため、「前年度の事項」を1つ持つ単一参照では足りず N 対 N の関連が要る。
そして**元データにその関連が無い**以上、作るには推定に頼るしかない。

推定で関連を作ると元データに無い関係を生成することになる。予算データで根拠のない接続を
作るのは正確性を損なうため、**現状の切断をそのまま見せる方針を維持する**。
現行の実装は「元データの限界がそのまま表れている」状態であり、嘘をついていない。

根本解決は元データ側（MOF が前年度事項への N 対 N 参照を持つ）でしか成立しない。
この判断は `docs/mof-budget-data-guide.md` 3-1-2節に記録した。
