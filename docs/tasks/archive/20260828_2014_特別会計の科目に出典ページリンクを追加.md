# 特別会計の科目（目）に出典ページリンクを追加

これまで科目別内訳の行単位出典URL（`page`/`sourceUrl`）は一般会計のみ対応していた（`buildGeneralPageMap`、`科目別内訳`帳票を走査）。特別会計の目は帳票単位のトップURLしか持たなかった。特別会計にも同様の行単位リンクを追加した。

## 実装

`scripts/generate-mof-kou-moku-data.ts` に `buildSpecialPageMap()` を追加。特別会計の目は「科目別内訳」ではなく「歳入歳出予定額科目別表」という別帳票（勘定ごとに1XMLファイル）に載っている。列構成も一般会計と異なる:

- 項の行: col1=項コード（数字のみ、プレースホルダ付きの場合あり）, col2=項名
- 目の行: col1=分類コード（ハイフン区切りの合成コード, 例 `02081-509-21`）, col5=目名, col6=金額

行判定は「col1のcolSub番号」ではなく「テキストにハイフンを含むか」で行う。年度によりXML生成側のcolSub割り当てが変わる（2024年度はcol1が項=colSub2/目=colSub3、2017年度は項=colSub2/目=colSub4）ため、colSub依存だと年度間で一貫しない。

項に目が1件も続かない場合（例: 予備費）、CSV側の目名は一般会計と同じ「(項名)」プレースホルダになる規約を確認し、同様に登録した。

補正予算は「歳入歳出予算補正予定額科目別表」という別帳票で列構成（colSubの割り当て）も異なるため、v1では対象外（`layout === 'standard'`のみ走査、当初・暫定予算が対象）。

## 検証結果（2024年度）

特別会計の目 2,832件（決算含む全予算種別）中 929件で行単位URLを特定。当初予算のみで見ると 1,225件中 928件（75.8%）が一致し、**残り297件は全て東日本大震災復興特別会計**（`parseTable()`が`rowSub`を無視して`(page,row)`単位でセルをまとめるため複数の項が1行に混在する既知の制約。`docs/tasks/20260828_1908_項自体の出典ページを追加.md`と同じ限界）。それ以外の会計は当初予算で不一致0件。

10年度全てで再生成し、東日本大震災復興特別会計以外の未一致が無いことを確認（2017年度406件不一致→全て東日本大震災復興、以下同様のパターン）。

下流の `mof-budget-{年度}.json`（`generate-mof-budget-data.ts`）も再生成・再圧縮し、`/mof-kou-moku`・`/mof-kou` の両ページで反映を確認（`基礎年金給付費`の目が `帳票・ページ: 202612001 p.264 出典XML` を表示）。

## 未対応

- 補正予算の特別会計（別帳票、列構成の再調査が必要）
- 東日本大震災復興特別会計（既知の制約、対応見送り）
